## 1. 这个系统负责什么

**设备系统是盲盒的入口工具**：**没有设备，既不能开盒也不能装模块**。它是核心循环的第一步，不是可选修正层。原"作用于转化端"的职能已取消（`06` 已解耦、D9 已固定为 30%）。（**术语**：本文件以"**设备**"为准，"**设备**（装置）"同指 `Device` / 本系统；**沿用文件内既有用词，不为改名而全量改写**。）

装置是**开启盲盒与给盲盒添加模块的前置条件**（`engine` 出口，核心 §3 / §4.4）：物品先**制造**出装置（**装置侧唯一的动作是制造**，㊷），**持有至少一台设备**是 `redeem`（开盒 / 兑现）与 `socket`（镶嵌 / 装模块）的**链首校验**（§5.7）。**逻辑执行者不变**——开盒仍归 `GachaService.redeem()`（01）、池子数据仍只由 `PoolService`（01）写，**设备只是前置条件**（§2）。

| 职责 | 内容 |
|---|---|
| 定义装置 | `DeviceDef`：成本 + 品质 + 条件 + 互斥 + 标签 + 解锁标记。**效果类型 / 目标 / 系数（效果族）已作废**，替代形状未裁决（§11 04-L） |
| **硬门槛（★ v0.16）** | **没有设备，既不能开盒也不能装模块**——`redeem` / `socket` 的**链首先校验"已有一台设备"**；无设备 ⇒ **响亮拒绝 `no_device`、不消耗任何一次寿命、状态逐项不变**（§5.7）。**判定归本系统，落点归 01**（§8） |
| **开局发放（★ v0.16）** | **新游戏初始化时发放一台基础装置**（**基础款一件，品质待 ㉙ 裁定**——**精度①：不得先给一个数**；形态沿用 §4 既有定义，见 §1.1）——**否则开局死锁**（开盒需设备 → 设备由物品制造 → 物品来自开盒）。**定义归本系统（`04`）；"写入持有事实 + 落盘 / 读回"归 `10`（初始化路径 + 存档层）**（§1.1） |
| 承载镶嵌 | 由本系统**发起**模块的镶嵌 / 拆卸调用（`PoolService.socket()` / `unsocket()`）——**池子数据的唯一写入方仍是 `PoolService`**，本系统只是**工具路径**（§3 / §5.6 / §8）；**v0.16 起它还多一层身份：镶嵌的硬门槛**（§5.7 / §1） |
| 品质梯度 | 作为内容释放载体之一（R11 / D13），高阶装置由里程碑任务释放 |
| 归因条目 | **每台已持有的装置**应有可读的归因 / 展示条目（P2）；**装置自身在 ρ 里的贡献度量随效果族作废而待定**（§11 04-L）。**装置侧的形态只有"持有"** |

**服务循环的哪一步：** "使用物品"（核心 §1.1）——装置是"同一份物品，用掉还是留下当工具"里的**留下**；**v0.16 起它同时是"开盒"这一步的前置条件**（没有设备 ⇒ 循环的第一步就走不动）。

### 1.1 开局状态：必须已有一台基础装置（★ v0.16）

- **开局发放**：**新游戏初始化时，玩家必须已经持有一台基础装置**——**基础款一件，品质待 ㉙ 裁定**（**精度①：不得先给一个数**——开局那台是什么品质、有没有成本，取决于未决的 ㉙）。**形态沿用本文件既有的装置定义**（§4 的 `DeviceDef` / `DeviceCost` / `DeviceCondition`，**不新增任何字段、不新增机制**）；`[补充]` **它是一件普通的内容配置装置（`.tres`）**，本文只写死"**开局必须已有一件这样的装置**"——**它的 `display_name` / `cost` / `condition` / `tags` 的具体取值由内容配置给出，本条不发明任何数值**（R11：新增装置必须能纯配置产出，§5.5）。
- **开局那台的 `id` 常量（★ ㉜：`04` 只定义"内容 + id"）**：`STARTING_DEVICE_ID = &"dev_basic_q1"`（定义在 `src/device/device_constants.gd`；新游戏初始化路径读它，**不在调用处硬编码字面量**）。**本条只写 id 与"基础款一件"这个事实，不给品质值**——**基础款一件，品质待 ㉙ 裁定**。★ **澄清（复核项）**：id 里的 `q1` **只是命名，不构成品质裁决**。
- **为什么必须是"开局就有"**：设备是**硬门槛**（§5.7）⇒ 没有设备就**既不能开盒也不能装模块**；而设备由物品制造、物品来自开盒 ⇒ **不发这一台就是开局死锁**（§1 / `01-gacha.md` §5.10）。
- **归属（唯一口径，★ ㉜ 裁定；**归属一律写成"层"，不写代码类型名**）**：**`10`（新游戏初始化路径 + 存档层）负责写入"持有一台基础装置"这个事实，并负责落盘与读回**（`devices` 入档、**缺键 ⇒ 补发开局那台**、**键存在但空数组 ⇒ 报错拒绝载入**）；**`04` 只定义 `DeviceDef` 与"基础款"的内容配置**（含开局那台的 `id` 常量），**不发放、不写档、不持任何玩家状态**；**`01` 只做 `has_device()` 前置校验**（无设备 ⇒ `no_device`）；**`03` 完全不涉及**。（**★ `Q20` 已关闭；归属见 ㉜**——**见 `10-progression.md` §4 / §7.4 第 10 条**；本条**不再并列任何"说法"、也不留任何"待裁"字样**。）
- **这一台够用，且是"可回滚的默认"**：**设备是通用耐用工具**——**不绑定盒子、不限制服务次数、不消耗、不损耗**（核心 §15 **D21 已裁决**）⇒ **开局那台永远够用、死锁被消除**；回滚路径 = 判定入口改为带 `box_id` 的形式（§11 **04-M** / **04-N**）。
- **教学含义（只登记，节奏归核心 §11）**：**开局就有一台** ⇒ 装置**在教学第一步就必须被展示**（否则玩家根本开不了盒），**不再是"30 min 才引入的可选配件"**。

## 2. 不负责什么（边界）

| 不属于本系统 | 归属 |
|---|---|
| 任务需求向量（`TaskDef`）的结构与匹配 | 见 `03-task.md` |
| ρ / M̄ / D̄ / B / σ 的**计算口径**与归因汇总 | 见 `07-economy-rho.md` |
| **池子数据**（某个盒子的池子状态、镶嵌位、排除 / 提升 / 损耗）——本系统只**发起**镶嵌调用 | 见 `01-gacha.md`（`PoolService` 是**唯一写入方**；没有"该套系的池子"这个对象） |
| 物品的类别 / 品质定义、**持有量（派生值）与物品实例列表** | 见 `02-item.md`（`ItemService` 是实例列表的**唯一写入方**） |
| 六面板渲染、展开入口、实时联动 | 见 `08-ui-panels.md` |
| 里程碑解锁的发放逻辑 | 见 `10-progression.md`（本文只消费 `unlock_flag`） |

**硬边界：** 本系统**不写池子数据**——`PoolService.socket()`（01）是池子数据的**唯一写入方**，本系统只是**触发 / 承载镶嵌动作的工具路径**（§3 术语纪律 / §8 铁律 7）。装置**永不**触碰概率与抽取，也**不读**池子（原"只读池子、仅用于 `cross_end` 判定"随 `cross_end` 作废，见 §5.4 / 核心 §16.10）。

**★ v0.16 追加：设备不写任何池子数据、不参与抽样——它只作为前置条件**（§5.7）。`roll(evaluation, seed)` 的签名与入参、`PoolState` 的写入权、`EvalService` 的分工**一字不动**：**设备不进 `PoolState`、不进 `EvalResult`、不参与抽样**，也不改变任何概率。**无设备时两侧入口被拒绝，是"校验"，不是"设备参与了逻辑"。**

## 3. 核心概念与术语

术语一律使用 `README.md` §5 的中文名 + 代码名，不自造同义词。

| 中文名 | 代码名 | 本文用法 |
|---|---|---|
| 装置 | `Device` | **开盒与装模块的前置条件 / 入口工具**（**v0.16 硬门槛：没有设备，既不能开盒也不能装模块**，§1 / §5.7）。一件可**制造**的**装模块工具**（**不再有"作用端"**） |
| 镶嵌 | `socket` | 把模块写进**某个盒子**的第 `slot` 位——**动作由本系统发起，数据写入归 `PoolService`**（§5.6 / §8） |
| **替换** | `replace` | **替换 = 拆卸 + 重新镶嵌（§5.6），消耗该盒寿命 1 次**——**本文件唯一的权威定义**（**模块侧**，§5.6） |
| 引擎 | `engine` | 物品出口之一：**制造**为装置 / 模块 |
| 物品 | `Item` | 装置素材来源（消耗规则见 §5.5） |
| **物品实例** | `ItemInstance` | **制造**时被**销毁**的那个物品个体（见 §5.3）；**返还实例的落点在模块侧 `unsocket`**；实例列表归 02 |
| **实例 id** | `instance_id` | **UUIDv4，全局唯一**；**制造**消耗按它指定实例（**模块侧返还产出的实例 `instance_id` 是全新的**，权威在 02） |
| **收藏编号** | `serial` | **判据（带作用域）：分配编号的只有开盒（`gacha`）；恢复编号的是迁移（一次性、且必须与 `serial_counters` 对齐）。除这两者外，任何来源的实例 `serial == 0`。**（举例：转化 / 返还产出；**举例不是权威，判据才是**）；**它是实例字段，不是 `grant` 的参数**，由 02 内部置位（§5.3 / `02-item.md`） |
| **物品品质** | `quality` | 1–5 序数，见 `02-item.md`；`DeviceDef.cost[].quality` 用的是它 |
| **套系品质** | `series_quality` | 核心 §4.1.1 的套系分级，决定镶嵌位数（`01`）与常规物品数；由里程碑解锁 |
| **池子** / 池子状态 | `Pool` / `PoolState` | **某一个盒子**的池子当前状态（= 该盒 `Box.item_pool` + `Box.modules` 的派生结果，**不入档**）；本系统**不读、不写、不缓存** |
| 闭环收益率 | `rho` / ρ | 装置**自身不再直接进入 ρ**（效果族作废）；其影响只经"镶嵌的模块"间接体现，口径见 `07` |

**术语纪律 —— "品质"有两个含义，本文必须分辨：** **物品品质** = `quality`（1–5 序数，见 `02-item.md`）；**套系品质** = `series_quality`（核心 §4.1.1）。本文出现装置的**"品质梯度"**（§1 / §5.5 / D13 / R11）时，指的是**后者所在的这套品质体系**——"按品质梯度释放内容"的节奏，**不是**物品等级：装置自身的档位是 `DeviceDef.quality`（4 档枚举），`DeviceDef.cost[].quality` 才是物品品质。

**术语纪律 —— 镶嵌动作归设备系统触发、数据写入归 `PoolService`：** 本系统是**镶嵌 / 拆卸模块动作的发起方**（工具路径），`PoolService.socket()` / `unsocket()`（01 §4.5）是**池子数据的唯一写入方**。因此本系统**不构造池子读写路径**、**不缓存池子状态**、**不求值概率 / 占比**；发起调用时必须显式给出 `box_id`（动作作用在**某一个盒子**上），但本系统**不持有**任何池子快照。

**已作废名词（一句话）：** `convert_end`（作用端）／ `apply_end` ／ `CrossEndCondition` / `cross_end` ／ `DeviceEffect` ／ `get_modifiers()` ／ `get_loss_reduction_pp()` ——**转化端机制的名词整族作废**（核心 §16.10）。

**位次体系只有一套（★ v0.16）：** **设备侧没有任何位子结构**（装置**不绑定盒子、不限制次数**，§11 04-M）⇒ 本文不涉及"两套位次"的对照。**盒子的镶嵌位** `socket_slot` = **该盒的** `Box.item_pool.socket_count`（该盒获得时从 `SeriesDef.socket_count` **冻结进这个盒子**、**同一池（盒）内恒定**，见 `01-gacha.md`）；**装置不能被镶嵌进池子**这条纪律不变（README §3 铁律 4 / 核心 §16.5 C4）。

**新增字段说明：** 本文出现 `[补充]` 标记的字段均为核心文档已命名能力在 GDScript 层的落地形状，**不引入新机制**；**装置的效果族（作用端 / 目标 / 强度）已作废**，其替代形状未裁决（§11 04-L），本轮不发明。

### 5.6 镶嵌动作与寿命预算（★ v0.15 本轮唯一新增的实质规则）

- **动作的发起方是本系统，数据的写入方是 `PoolService`**：镶嵌由本系统发起 `PoolService.socket(state, box_id, module_id, slot)`（01 §4.5）；**`PoolService` 是池子数据的唯一写入方**，本系统只是**工具路径**（§3 术语纪律 / §8）。
- **每次成功镶嵌消耗该盒一次使用**：`Box.uses_remaining -= 1`（核心 §4.1 的**总寿命预算** `k`，按该盒所属套系品质在发放时初始化：**品质 1→10、2→15、3→20、4→25**，存活范围 **10–25**）。★ **别把预算与位数混成一个数**：**镶嵌位数仍是 `item_pool.socket_count` = 2/3/4/5**（随套系品质）——**预算远大于位数**（用户口径："盲盒的使用次数**远远超过**镶嵌的次数"）⇒ **装满镶嵌位烧不光预算**。
- **`unsocket` 不退还次数（现行规则，核心 §15 D20② 已裁决）**：**拆卸零成本**——不扣寿命，但**已消耗掉的那一次寿命不返还**（`uses_remaining` 逐项不变）；物品侧照旧**返还 50% 材料**。★ **"退还"（寿命次数）与"返还"（物品材料）是两件事，不得混写**。理由 = **配置是沉没成本**，与"**模块是消耗品、拆卸只返还 50% 材料、模块本体不回收**"**同一设计意图**（核心 §3.3 / §4.5 / §16.5）。★ **替换是镶嵌的重复发生**：**`m` 是历史累计**（原装 + 替换）⇒ **反复替换可把剩余可开次数压到 0（"未开即毁"仍可达）**。
- **替换也是镶嵌 ⇒ "换掉谁"不再可以随意试错**：同一个盒子内**位数恒定、不能扩容** ⇒ **不存在"再装一个"这个选项，只有"换掉谁"**；而 **替换 = 拆卸 + 重新镶嵌** ⇒（拆卸不退那一次）**每替换一个位子额外 −1 `uses_remaining`**——**每次替换都要从该盒的寿命预算里再扣 1 次**，该位子历史累计花掉 **2 次**（原装 1 + 新装 1；再换一次即 3 次）。**★ 分账（裁定⑩/⑬，唯一权威写法；只写不变式与上界，不写范围口径）**：**镶嵌（含替换）与兑现共用同一份预算 `k`**：**不变式** —— **`镶嵌总次数（含替换） + 兑现次数 + uses_remaining == k`**；**装满位子后剩下的 `d = k − 位数`（8 / 12 / 16 / 20，**仅"不替换"前提下**）由"替换"与"开盒"分账**——**每替换一次就少开一次盒**——**"换掉谁"的价格是一次开盒机会**。由此：**装满后再替换的上界 = `k − 位数`**（8 / 12 / 16 / 20）；**只反复替换同一个位子的上界 = `k − 1`**（9 / 14 / 19 / 24）——**这是推论、不是规则：它的前提是"其余位子一个都不开"**（**㊹：可以留，但必须带上这个前提，且不得进任何断言**）。**禁**把 **8 / 12 / 16 / 20 抄成"每盒可替换次数"常量**（**它们只是"装满位子"前提下的推论**）；**"只装 1 个再反复替换"属退化玩法——不单独写规则、不得写成断言**。**禁写任何"范围口径"**（旧的"每盒能换多少次"这类区间说法已作废：替换次数由**不变式**与分账决定，不是固定次数）。因此 **`m` = 该盒历史累计的镶嵌次数（含替换），只在"从不替换"时才受位数封顶**（位数封的是**同时占用**的位子数）。
- **归零即摧毁**：`uses_remaining` 扣到 **0** ⇒ **该盒连同它的 `item_pool` 与 `modules` 立即被摧毁**（核心 §4.1 / §4.6；摧毁动作的执行方不在本系统，§2 边界）。
- **归零与摧毁：三段式口径（唯一权威写法）**：①**作废的只是那条具体路径**——**"装满镶嵌位 ⇒ 预算归零"已不成立**（位数 **2–5** < 预算 **10–25** ⇒ **装满位子最多只扣 2–5 点**，**`d` 仍剩 `k − 位数` = 8 / 12 / 16 / 20（满配时）**）；②**"归零判定只看计数器"仍成立**——**与"是否兑现过"无关**；③**"从未兑现就被摧毁"整体仍然可达**——**替换不占新位子、但计入 `m`**（**全程只需 1 个空位**）⇒ **反复换模块可把 `m` 推到 `k`** ⇒ **`d = 0`**（**合法路径**，代价 = **该盒一次都没开过就没了**；**这正是"换掉谁"的真实代价**，与 §5.6 裁定⑩ 同源）。★ 机制：**替换使 `m` 不再受位数封顶**（位数只封"同时占用"的位子数），**每替换一个位子额外 −1** ⇒ **反复替换可以把 `d = k − m` 一路压到 0**（**分账**：**装满位子后剩下的 `d = k − 位数` = 8 / 12 / 16 / 20 由"替换"与"开盒"分账 ⇒ 每替换一次就少开一次盒**）；**这是设计上的真实决策风险，不是缺陷**。**不得**把它实现成"寿命不足，所以禁止镶嵌 / 替换"的**前置拦截**：预算是**配额**，不是**准入条件**（核心 §4.1.1）。

- **原子且绝不消耗寿命（写死）**：被拒绝的那次调用**逐项不变**——**`uses_remaining` 连一次都不扣**、`item_pool` / `modules` 逐项不变、**实例列表逐项不变**、**存档断点上不留任何中间态**（与"校验失败不扣次数"同一条纪律）。
- **禁止的写法**：**不得**"先扣一次寿命再校验设备"、**不得**"扣了再补回来"、**不得**把无设备的调用静默当成已消耗。
- **这不是"拦截"**：门槛是**前置条件**（**没有工具就没法动手**），不是对玩家决策的防御性拒绝——**它与 §5.6 里被明文禁止的"寿命不足 ⇒ 禁止镶嵌"完全是两件事**：后者是**发明规则**，前者是**规则本身**。
- **★ 门槛的范围：不得加宽（v0.16 裁定⑪）**：**"必须先有设备"只摆在「开盒」与「装模块」两个动作上**——**造设备（`DeviceCost` 制造路径，即物品转化）不受门槛约束** ⇒ **手里有材料就能自己造一台装置**。（写死这一句的理由：否则实现者很容易把门槛加宽成"**没有装置就什么都干不了**"。）
- **★ 装置不能离开玩家（㉗ 把 D21② 扩写为"装置会不会离开玩家"）⇒ 设备集合只增不减（规则侧事实）**：**不消耗、不损耗**，且**不可主动销毁、不可丢弃、不可卖出**（**任何"离开玩家"的路径都会复现开局死锁**，§1.1）⇒ **"已有一台设备"一旦成立就不再回退**，因此**"持有 0 台设备"在规则上不可达**（只可能来自**损坏档或手改档**）；**"开局那台是否为不可摧毁保底"不需单独子问——没有装置能离开玩家**。⇒ **规则侧只需判定"是否有 ≥ 1 台"（§5.7 首条）**；**存档侧怎么处置（键缺失 ⇒ 补发开局那台；键存在但空数组 ⇒ 报错拒绝载入）归 `10-progression.md`**——**本文不写存档布局**（§1.1 亦不发放、不落盘）。

## 7. 流程 / 状态机

**本文件有效的流程是模块侧（镶嵌 / 拆卸 / 替换）与设备硬门槛（§5.7）**：

**镶嵌 / 拆卸模块（模块侧动作，由本系统发起；§5.6）：**

```
前置：**已有一台设备**（硬门槛，§5.7）——无设备 ⇒ 本次调用被拒绝（`no_device`），**不进入下述任何一步**
镶嵌：PoolService.socket(state, box_id, module_id, slot) 成功
      → Box.uses_remaining -= 1
      → 归零（== 0）⇒ 该盒连同 item_pool / modules 立即被摧毁
             ⚠️ 归零由"镶嵌（**含替换**）+ 兑现累计到 0"触发：**装满位子烧不光预算**（10–25 ≫ 2/3/4/5），
                但**反复替换可以**（每替换一个位子额外 −1，§5.6）；**不得**实现成"寿命不足 ⇒ 禁止镶嵌 / 替换"的前置拦截
拆卸：PoolService.unsocket(state, box_id, slot)
      → **不退还**镶嵌时消耗的那一次（核心 §15 D20② 已裁决）：uses_remaining 逐项不变，只返还 50% 材料
替换：拆卸（不退还）+ 重新镶嵌 ⇒ **该位子净扣 1 次寿命**（该位子历史累计 2 次）
```

**开盒（`GachaService.redeem()`）走同一条前置**：**无设备 ⇒ `no_device`、不消耗那一次寿命**，盒子连同它的池子与 `modules` **原样留着**（落点归 01，本文只提供判定；`01-gacha.md` §5.10）——**即使盒子 `uses_remaining == 1`，被拒绝的兑现也不得把它摧毁**。

**池子数据的变化由 `PoolService` 负责**：模块镶嵌 / 拆卸改变**某一个盒子**的池子占比（**不影响同套系的其他盒子**），池子派生量的重算走 01 / 07 的既有链路（README §2.2）。本系统**不订阅池子事件、不缓存池子状态、不持有池子快照**（§3 术语纪律）。
