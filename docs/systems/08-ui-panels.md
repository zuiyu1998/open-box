# 08 · 界面与信息呈现系统

- 上游：`../core-design.md` **v0.6** ／ `README.md`（系统索引、所有权边界、术语表）
- 依赖系统：**07 数值与期望（`EvalService`）**、05 模块与池子（`PoolService`）、01 盲盒与概率、02 物资、03 任务、09 演出（入口）、10 收集与进度（入口）
- 被依赖：无。本系统是**叶子**：只消费 `EvalService` 的结果并渲染，不产出任何被计算的数值

> **单一数据源声明（本系统第一条铁律）**
> **盲盒默认层 / 循环面板 / 池子面板 / 归因面板 / 架上面板 / 任务面板，加上试算（沙盒）与兑现对照，全部从 `EvalService` 单一数据源取数。**
> 任何面板自行计算、各自缓存概率副本、或自带一套数字口径，一律视为缺陷（核心文档 §9 铁律 3/4；README §3.3）。
> **本系统不拥有任何数值公式。** 它只决定"哪些数字、在哪里、以什么格式、在什么时机出现"。

## 1. 这个系统负责什么

| # | 职责 | 出处 |
|---|---|---|

| 4 | **R12 对策**：展开入口必须显眼，默认层必须给"共有 N 款"总量提示 | 核心 §6.5 / §12 R12 |
| 5 | **试算 / 沙盒**的交互规格：镶嵌前实时预览，含编辑前后分布对比 | 核心 §8.2 / P6 |

## 3. 核心概念与术语

沿用 README §5 术语表（中文名 + 代码名），本系统只新增呈现层标识符。

| 中文名 | 代码名 | 在本系统的含义 |
|---|---|---|
| 封面层 / 默认层 | `headline` | 盲盒封面：最好物品 + 其概率 + 期望（核心 §6.1） |
| 展开层 | `expanded_layer` | 全款分布、标记、损耗、镶嵌位、σ、直方图（核心 §6.3）`[补充]` |
| 池子 | `Pool` | 某套系当前的概率分布状态 |
| 池子状态 | `PoolState` | 基础权重 + 模块编辑结果（只读消费，见 `05-module-pool.md`） |
| 款 / 物品 | `Item` | 池中单个可产出物；默认层取材是其中价值最高者 |
| 套系 | `Series` | 一个独立概率池：`regular_count` 常规 + 1 隐藏（品质 1/2 = 8 常规，品质 3/4 = 12，核心 §4.1.1） |
| 排除 / 提升 / 损耗 | `ban` / `boost` / `loss` | 展开层要展示的**标记**；规则见 `05-module-pool.md` |
| 隐藏款 | `hidden` | 展开层中以"免疫编辑"视觉语言标注 |
| 镶嵌位 | `socket_slot` | **格数由套系品质决定**（= `SeriesDef.socket_count`，v0.6 起不再固定为 3）；同一套系内恒定，展开层与池子面板**按该值动态渲染格子，不得写死** |
| 期望 | `ev` | 默认层的第二个数字（`best_item_prob` 之后） |
| 闭环收益率 | `rho` | 归因面板与循环面板的主体 |
| 保底 | `pity` | 展开层的可查项（P1） |
| 试算 / 沙盒 | `sandbox` | 镶嵌前的实时预览态（核心 §8.2）`[补充]` |
| 空洞 | `void` | 排除损耗产生的**零价值结果**；在分布中占一个显式位置，**但它不是一款**（不计入 N） |
| 套系品质 | `series_quality` | 决定该套系的常规款数、镶嵌位数、装置槽位数与物资品质区间（README §5，核心 §4.1.1）。**08 只直读渲染品质标识与位子说明，不参与任何计算** |
| 物资 / 物品品质 | `quality` / `star` | 物资（与物品）的 1–5 等级，与 `series_quality` **不是同一维度**（见下） |

`[补充]` `expanded_layer` / `sandbox` 的代码名：术语表只给了 `headline`，而核心 §6.3 / §8.2 要求展开层与试算必须落地为独立状态，故补两个标识符。

**术语纪律（v0.6 新增）：本系统里"品质"有两个含义，线框图与文案中两者都会出现，必须可分辨。**

| 含义 | 代码名 | 书写规范 | 例 |
|---|---|---|---|
| **套系品质** | `series_quality` | 数字 **+ 档位名**，恒带 ` · ` 间隔符 | `品质 3 · 稀有` |
| **物资 / 物品品质** | `quality` / `star` | 只写数字或星级符号，**不得带档位名** | `品质 3` ／ `★★★` |

理由：默认层、展开层与线框图里"品质 3"与"品质 3 · 稀有"会同时出现（一个是盒子的档次，一个是东西的好坏），不加区分则玩家与实现者都会误读。**"套系品质必带档位名"是一条机械可检的书写规则**：任何出现 `series_quality` 的文案若缺少档位名，一律视为缺陷。`[补充]`

## 4. 数据结构（GDScript Resource 字段定义）

```gdscript
# res://scenes/panels/panel_def.gd
class_name PanelDef
extends Resource

enum PanelId { HEADLINE, LOOP, POOL, ATTRIBUTION, SHELF, TASK }

@export var panel_id: PanelId = PanelId.HEADLINE
@export var title_cn: String = ""
@export var unlock_step: int = 0                  # 教学曲线步骤（核心 §11）
@export var eval_fields: PackedStringArray = []   # 允许读取的 EvalResult 字段白名单
@export var is_expandable: bool = false           # 仅 HEADLINE / POOL 为 true
```

`[补充]` `PanelDef` 与 `eval_fields`：核心 §8.1 只规定面板内容，未规定配置形态。"字段白名单"是落地所需，同时是**单一数据源**的机械保证——面板读不到自己不该算的字段。

```gdscript
# res://scenes/panels/panel_view_state.gd
class_name PanelViewState
extends Resource

@export var expanded: bool = false              # 展开层状态（核心 §6.3）
@export var sandbox_active: bool = false         # 沙盒预览中（核心 §8.2 / P6）
@export var before_snapshot: RefCounted          # 编辑前的 EvalResult 只读快照
@export var after_snapshot: RefCounted           # 编辑后的 EvalResult（来自 EvalService）
@export var highlighted_item_id: StringName = &""
@export var pulse_shown: bool = false            # 展开入口首见脉冲，一次性（R12 对策）
```

`[补充]` `EvalResult` 类型由 07 定义（见 `07-economy-rho.md`）；`before_snapshot` 是**呈现层缓存**，只服务"编辑前后对比"，不参与任何求解，也不得被任何面板当作数据源。

## 5. 规则与公式

**本系统不定义任何游戏数值公式。** 以下是渲染规则（R）与一条纯排版公式。

| # | 规则 | 依据 |
|---|---|---|
| **R-1** | **默认层三行制**：`best_item`（含星级与图）、`best_item_prob`、`ev`。**不得追加第四项数值** | 核心 §6.1 |
| **R-2** | **总量提示常驻**：默认层固定显示"共有 N 款"，N = 池中款总数 = **`regular_count` + 1 隐藏**（品质 1/2 → 9 款，品质 3/4 → 13 款，随套系变化）。**被排除的款仍计入 N**——玩家要知道总量，而不是可见量 | 核心 §6.5 / §4.1.1 |
| **R-3** | **展开入口显眼**：位于默认层内部、常驻可见、点击区 ≥ 48×48 dp；首次出现时脉冲提示一次 | 核心 §6.5 / R12 |
| **R-4** | **实时联动**：`PoolService` 变更信号到达后，默认层在同一帧末重取 `EvalService.compute()`；**禁止任何 UI 侧的概率增减** | 核心 §6.4 |
| **R-5** | **同一数字必须同一 formatter**：默认层与展开层对同一字段使用同一格式化函数，否则"同源"在玩家眼里会变成"两个数" | 核心 §6.4 的信任前提 |
| **R-6** | **直方图共享纵轴**：编辑前后两组柱共用同一 `max(pᵢ, void_prob)`（`void` 计入共享域，否则"空洞变大"看不出来），否则形状对比失真 | 核心 §13.1 / `07-economy-rho.md` §5.4 |
| **R-7** | **款序对齐**：编辑前后两组柱按**同一款序**排列，被排除款保留空位（不塌缩），玩家才能看出"哪一根消失了" | 核心 §13.1 |
| **R-8** | **隐藏款视觉语言**：`hidden` 恒用"锁定"样式，`ban` / `boost` 交互控件对其禁用 | 核心 §5.4（执行在 05，UI 只禁用并给文案） |
| **R-9** | **不隐藏**：已解锁的信息项永不隐藏、永不移到更深的层级 | P1（核心 §7） |
| **R-10** | **`void` 柱必须画出且与款柱可区分**：`void` 恒占一个**独立槽位**，位于款区之外（隐藏款之后），使用"空洞/缺口"样式（无填充或斜纹底 + 虚线边框）。**不得混在常规款里，也不得与隐藏款共用样式** | `07-economy-rho.md` §5.4 / `05-module-pool.md` §5.4 |
| **R-11** | **损耗必须可见且可解释**：展开层显示 `void_prob` 当前值与逐款来源；沙盒显示编辑后 `void_prob` 的变化。「要不要继续排除」的判断依据必须一眼可取，不能只给一个数字 | `07-economy-rho.md` §9（P2 / P6）/ `05-module-pool.md` §5.3 |
| **R-12** | **默认层不显示 `void_prob` 数值**（R-1 的三项契约不破）；但 `void_prob` ≥ 警示阈值时，默认层出现一条**不含数字**的提示条「池子已有损耗 · 展开查看空洞」，点击即展开 | 核心 §6.1 / §6.4 / §6.5 `[补充]` |
| **R-13** | **品质与位子数必须可查（P1）**：展开层与架上面板恒显示「套系品质标识 + 当前镶嵌位 `x / socket_count`」，并附一行来源说明——**位子数由套系品质决定、同一套系内不可扩容、更高品质的套系给更多位子**（并指向解锁来源，见 `10-progression.md`）。数字一律直读 `SeriesDef`，**08 不得自行推导位子数** | 核心 §4.1.1 / §11（3 h+）/ P1 `[补充]` |

`[补充]` **R-12 的警示阈值**：核心文档 §6.1 只规定默认层"只有三样东西"，未规定损耗在默认层的可见性。为使"排除积累出的空洞"不在头部完全消失（§6.4 的精神：编辑必须在默认层留下痕迹），补一条阈值触发的提示条——它不新增数字，只增强展开入口（R-3 / R12）。

`[补充]` **R-13 的呈现位置与文案**：核心 §4.1.1 规定"位子由品质决定"，P1 只要求"可查"，未规定查在哪里。落到展开层的**镶嵌位状态行**与架上面板的**位次占用行**各加一行来源说明即可（一行字 + 一处深链），不新增页面层级、不新增默认层数字项。理由：v0.6 把品质变成玩家可主动追求的轴（核心 §11 的 3 h+ 教学点），若界面只显示"3 格"而不说"为什么是 3 格、哪里能拿到更多"，这条轴在 UI 上等于不存在。

排版公式（**仅布局，不含玩法语义**）：

```
柱高 hᵢ = clamp(pᵢ / max_j(p_j, void_prob), 0, 1)   # pᵢ 取自 EvalResult.distribution，void_prob 取自 EvalResult.void_prob（07 §4）
柱数   = regular_count + 2 个独立槽位               # 常规款数 + 1 隐藏 + 1 空洞 void
       # regular_count 取自 SeriesDef（核心 §4.1.1），不得写死：
       #   品质 1 / 2 → 8 + 2 = 10 槽位　｜　品质 3 / 4 → 12 + 2 = 14 槽位
编辑前后两组柱使用同一个 max_j(p_j, void_prob)
```

## 6. 参数表（推荐值 + 调参旋钮）

| 参数 | 推荐值 | 说明 |
|---|---|---|
| 默认层数值项数 | **2**（`best_item_prob`、`ev`） | 硬约束，非旋钮：R-1 的三行 = 1 个物品行 + 2 个数字；品质标识与总量提示均不计入数字项（核心 §6.1 / §9.2 裁决） |
| 默认层总量提示 | 常驻"共有 N 款" | 硬约束（核心 §6.5 / R12） |
| 默认层刷新预算 | ≤ 1 帧（上限 100 ms）🔧 | R-4 的量化；超预算即视为"编辑没反应" |
| 展开按钮最小点击区 | 48 × 48 dp 🔧 | R-3 |
| 展开入口首见脉冲 | 1 次 🔧 | 一次性，不重复打扰 |
| 概率小数位 | 1 位（`1.4%`） | 与实体盲盒包装的语言一致 |
| `ev` 小数位 | 2 位（`3.24`） | 默认层第三行 |
| `rho` 有效数字 | 3 位（`2.41`） | 归因面板与循环面板 |
| 直方图柱数 | **`regular_count + 2` 槽位**（常规款数 + 1 隐藏 + 1 空洞 `void`）：品质 1/2 = **10**，品质 3/4 = **14** 🔧 | 随套系品质变化，**不得写死**（v0.6）；含被排除款的空位（R-7）；`void` 独立槽位（R-10） |
| 镶嵌位格数 | **`socket_count`**（品质 1/2/3/4 = 2 / 3 / 4 / 5） | 同套系恒定、跨套系随品质增长；展开层与池子面板**按此数动态渲染格子**（R-13），格数与占用标记必须整块重绘（T14） |
| 默认层品质标识 | 仅 `series_quality` ≥ 3 时显示「品质 3 · 稀有」文字铭牌 🔧 | **零数字项**；档位名必带（§3 术语纪律）；是否默认显示见 §9.2 裁决与 U11 |
| 直方图纵轴 | 编辑前后共享，共享域含 `void_prob` 🔧 | R-6 |
| `void` 柱视觉 | 无填充 / 斜纹底 + 虚线边框 + 独立分隔线 | 与常规款、隐藏款三方互不混淆（R-10） |
| `void` 增量可见阈值 | ≥ 2 个百分点（共享 max 域内）🔧 | T12 的肉眼可见判定门槛 |
| 默认层 `void` 警示阈值 | 10%（低于此值不提示）🔧 | 默认层仍为三项数字（R-12）；只加提示条，不加数字 |
| 沙盒快照对 | 1 组（编辑前 / 编辑后）🔧 | 只支持"当前 vs 一次候选"，须含 `void_prob` 对 |
| 面板切换动画 | 120 ms 🔧 | 不得掩盖数字变化 |
| 架上 / 循环 / 任务面板解锁 | 见 §9.5 教学映射 🔧 | 与核心 §11 对齐 |

## 7. 流程 / 状态机

### 7.1 展开层状态机

```
collapsed ──(点击展开入口)──▶ expanded
expanded  ──(点击折叠 / ESC)──▶ collapsed
expanded  ──(选中候补模块)──▶ sandbox_preview
sandbox_preview ──(改目标款 / 改强度)──▶ sandbox_preview      # 每次改动重取 EvalService
sandbox_preview ──(取消)──▶ expanded                          # 状态零变更
sandbox_preview ──(确认镶嵌)──▶ replace_confirm
replace_confirm ──(确认)──▶ collapsed                          # 池子已改，默认层立即更新
replace_confirm ──(返回)──▶ sandbox_preview
```

**关键约束：** `sandbox_preview` 全程**只读**。默认层在预览中显示的是"镶嵌后"的数字（`after_snapshot`），但 `PoolState` 只有走 `PoolService.socket()` 才发生变更（核心 §9 铁律 5）。

### 7.2 沙盒流程（P6）

1. UI 取候选状态（只读，不入库）。
2. 用候选状态调用 `EvalService.compute(candidate)` 得到 `after_snapshot`。
3. 直方图并排显示编辑前 / 编辑后（共享纵轴含 `void`，款序对齐）。
4. **显式展示编辑后 `void_prob` 的变化**（如「空洞 4.90% → 7.35%」），与前后两条分布同屏对比——这是玩家判断"要不要继续排除"的唯一依据（`07-economy-rho.md` §9）。
5. 默认层数字并排显示"现在 → 镶嵌后"，**包括它变差的情况**。
6. 显示 `void_prob` 的逐款来源、被换下模块及其损失——**损耗的算法见 `05-module-pool.md`，UI 只渲染字段**。
7. 确认后写入 → 变更信号 → 默认层重取（R-4）。

### 7.3 导航与信息层级

```
L0  盲盒封面（默认层）—— 1 屏，**两个数字** + `best_item` 行 + "共有 N 款" + 展开入口（+ 品质标识，见 §9.2 裁决）
      │
      ├──▶ L1a 展开层（同屏内联展开）—— 全款分布 / 标记 / 损耗 / 镶嵌位 / σ / 直方图
      └──▶ L1b 底部导航：循环 · 池子 · 归因 · 架上 · 任务
L1  池子 ⇄ 归因  双向深链（编辑现场 ↔ 编辑依据）
    架上 ──▶ 兑现（见 `09-presentation.md`）／ 图鉴与套系进度（见 `10-progression.md`）
    任务 ──▶ 缺口物资 ──▶ 转化 / 装配
L2  沙盒预览与替换确认（模态覆盖，不新增页面层级）
```

**层级原则：** 深度按需下沉，但**入口在浅层**（R-3 / R-9）。层级越深的信息，入口必须越显眼。

**只有三件事**：最好的物品、它的当前实际概率、数学期望。加上 R12 要求的总量提示与展开入口——**其余一律下沉到展开层**。本图主体按**品质 2 · 精良**绘制（款数 9）；品质标识是**占位示例**，与品质 2 不同时出现——它只出现于品质 ≥ 3 的套系，且**不占数字项**（三件事的数值契约不变）。

> **裁决（§6.1 的 `void` 呈现）：默认层不显示 `void_prob` 数值。**
> 默认层仍是"头奖概率 + 数学期望"两项数字（R-1）。理由：默认层的全部价值就是 5 秒可懂（核心 §6.2），任何第三个数字都在花掉它。
> **但不允许损耗在默认层完全不可见。** 当 `void_prob` ≥ 警示阈值（推荐 10% 🔧）时，默认层出现一条**不含数字**的提示条「池子已有损耗 · 展开查看空洞」，点击即展开（R-12）。理由：核心 §6.4 要求编辑在头部留下痕迹——排除"最好的物品"会当场拉低 `ev`，同理，排除积累出的空洞也必须在头部留下痕迹，否则 P1 想防的"系统在背后动手脚"的感觉会重新出现（R12 同源）。

> **裁决（品质标识在默认层）：可以显示，但必须是"零数字项"的文字铭牌，且只对较高品质套系显示。**
> 核心 §6.1 规定默认层只有"最好物品 + 其概率 + EV"三项，**v0.6 没有改变这一点**，因此这条裁决必须在不新增数字的前提下成立：
> - **允许**在套系名后追加纯文字铭牌「品质 3 · 稀有」（档位名必带，§3 术语纪律）；
> - **禁止**因它追加任何统计数字（概率、EV、位子数、款数等一律不许随标识新增）；
> - 铭牌里的"3"是**档位名的一部分**（等级标签），不是数值项——默认层仍是两个数字（`best_item_prob`、`ev`）；
> - **仅 `series_quality` ≥ 3 时出现**：品质 1/2 是默认档，标识只制造噪音（核心 §6.2 的"5 秒能懂"）。
>
> 理由：核心 §4.1.1 把品质做成了一条**玩家可主动追求的轴**（核心 §11 的 3 h+ 教学点），而默认层是唯一常驻画面（R-9）。铭牌是这条轴在头部留下的最小痕迹，成本为零数字项；反过来，**只要它带上数字，就会花掉"5 秒能懂"**（核心 §6.2 / T10）。
> 这条与核心 §6.1 的三项契约的正式对齐仍记为待定项 **U11**。

### 9.5 信息密度与教学曲线（核心 §11）

| 教学阶段 | UI 上出现的东西 | 玩家此刻不需要理解 |
|---|---|---|
| 0–5 min | 默认层三行 + "共有 N 款"（N = `regular_count` + 1，本例 9）+ 任务面板 | **概率、分布、σ、损耗、品质标识** |
| 5–15 min | 循环面板（`rho` / `m_bar` / `d_bar` / `b`） | 分布 |
| 15–30 min | 转化入口（见 `06-conversion.md`） | 池子编辑 |
| 30 min–1 h | 架上面板完整版（位次占用） | 损耗 |
| 1–2 h | 模块·排除 → 池子面板 + 展开层分布与标记（**`void` 柱同时出现**，但只标"空洞"，不解释 40%） | **损耗的算术概念** |
| 2–3 h | 提升 + `loss` 行与 40% 口径 + **`void` 来源分解** + 镶嵌位占用行（格数 = `socket_count`） | σ、直方图 |
| 3 h+ | **套系品质与更大的施工台**（品质标识 + R-13 的位子来源说明）、σ、直方图前后对比、多套系对比 | — |

**硬要求：**
- **前 15 分钟不需要理解概率**——这段时间里唯一出现的概率数字就是"最好款的当前概率"。
- §5.2 的 **C5（编辑全程可查）**优先于节奏：**一旦玩家做过第一次镶嵌，分布与标记就必须始终可展开查看**，不得因教学阶段而锁。
- **`void` 柱从"展开层分布首次出现"起就画出**，不随教学阶段延后。理由：`Σ probs + void_prob + 隐藏款 = 100%` 必须随时可核对（P1 / R-9），若在 1–2 h 阶段把 `void` 藏起来，玩家加总概率会发现缺口，反而怀疑系统藏了东西。教学差异只体现在**解释文案的深度**（2–3 h 才讲 40%），不体现在"画不画"。
- 未解锁项**不出现**；已解锁项**永不隐藏**（R-9）。
- 展开层默认收起——**但入口必须显眼**（R-3）。默认层是门面，不是牢笼。

### 9.6 直方图规格（本作最重要的单个 UI）

1. **必须同时呈现编辑前后的分布形状**，并排或叠加，不允许只画一条（核心 §13.1）。
2. 共享纵轴（R-6，共享域含 `void_prob`）、款序对齐、被排除款保留空位（R-7）——**"哪一根被削掉了"必须在 0.5 秒内看出来**。
3. 纵轴即概率，柱数 **`regular_count + 2` 槽位**（常规款数 + 1 隐藏 + 1 空洞 `void`）：品质 1/2 = 10，品质 3/4 = 14，**随当前套系品质取值，不得写死**。
4. **`void` 柱必须画出，且与常规款、隐藏款三方样式互不混淆**（R-10）：独立槽位（位于款区之外）、无填充或斜纹底 + 虚线边框 + 独立分隔线。**理由：损耗必须可见**，否则玩家无法理解 40% 意味着什么，也无法据此判断"要不要继续排除"（`07-economy-rho.md` §5.4 / §9，`05-module-pool.md` §5.3）。
5. **沙盒预览中，`void_prob` 的变化必须与编辑前后两条分布同屏呈现**（`07-economy-rho.md` §9 的硬要求）；直方图**实时重绘**，与默认层数字同帧更新（P6 的"没有实时预览的池子编辑是不可用的"）。
6. 不做动画过渡掩盖形状变化：形状变化本身就是要看的东西。

| **T1 同源验证（默认层 ⇄ 展开层数字一致性）** | 用返回**哨兵值**的假 `EvalService` 驱动全部六面板，断言：默认层的 `best_item_prob` 与展开层分布表中 `best_item` 那一行的"当前"列**字符串完全相等**，且两处均等于哨兵值 | 六面板无第二个数据源 |

| **T3 编辑后默认层立即更新（验收）** | `PoolService.socket()` 后 ≤ 1 帧（上限 100 ms）默认层两数字变化；**排除"最好的物品"时 `ev` 必须下降**，且下降量与该次编辑在归因面板产生的 `池子损耗` 项一致（核心 §6.4 推论） | 头部自我记录代价 |
| **T4 R12 对策** | 断言默认层在任意池子状态下都渲染"共有 N 款"，且 N 恒等于款表长度（`regular_count` + 1：品质 2 → 9，品质 3 → 13），**被排除款不减少 N**；展开入口控件存在且点击区 ≥ 48 × 48 dp | 玩家不会怀疑系统藏概率 |
| **T5 沙盒只读** | 完整走完预览 → 改目标款 → 改强度 → 取消；断言 `PoolState` 哈希不变、默认层数字回到编辑前 | P6 预览不落地 |
| **T6 直方图正确性** | 断言编辑前后两组柱的 `max` 相同且共享域含 `void_prob`（R-6）；断言被排除款的柱位存在且为空（R-7）；断言柱数 = **`regular_count + 2`**（品质 1/2 → 10，品质 3/4 → 14），**柱数取自当前套系而非常量**（v0.6）；断言 `void` 柱与款柱使用**不同的样式资源**、且位于款区之外（R-10） | 形状对比不失真 |
| **T7 formatter 一致性** | 同一字段在默认层与展开层渲染出的字符串相等（R-5） | 不产生"两个数"的观感 |
| **T8 红线守护（README §3.5）** | C1/C2/C3/C4/**C6** 的回归测试归属 01/05/07；**08 侧守护方式**：断言 UI 层不存在概率副本——UI 显示的每个概率都能追溯到某次 `EvalService.compute()` 的返回值 | 显示即真相 |
| **T9 性能** | 款数 × 6 面板整屏刷新 ≤ 1 帧（品质 2 = 9 款 10 槽位；品质 3 = 13 款 14 槽位，都须达标）；沙盒从选中到预览 ≤ 100 ms | 实时感的量化门槛 |
| **T10 5 秒可懂性** | 新玩家在无人引导下 5 秒内指出"这个盒子最好能开出什么、平均能拿到多少" | 核心 §13 问题 2 |
| **T11 切片失败信号（必须观测）** | ① **测试者从不展开详情层，也从不觉得缺什么** → 深度被默认层埋没：**先改入口（R12），不得砍深度**（核心 §13.4）；② 测试者问"平均能拿多少"却找不到答案 → 默认层失败；③ 测试者在 10 分钟内把池子编到接近必出 → C4 未生效，检查代码 | 核心 §13.4 |
| **T12 `void` 增量肉眼可见（验收）** | 排除一款后，该次编辑产生的 `void` 增量在直方图上必须**肉眼可见**：编辑前后 `void` 柱高差 ≥ 可见阈值（推荐 2 个百分点，R-6 共享域内）🔧；且该增量柱与款柱样式可区分。**08 只断言"可见性"，不重算增量**——增量真值（`== 0.4 × 该款释放质量`）由 `07-economy-rho.md` §10.1 T3 守护 | 损耗可见才可被理解（05 §5.4 / 07 §5.4） |
| **T13 `void` 呈现失败信号** | 若测试者**不理解"为什么池子里多出一块空白"** → `void` 呈现失败：检查 ① `void` 柱是否被混进常规款、② 展开层是否给出 `void_prob` 当前值与逐款来源、③ 是否有一行"空洞 = 排除损耗"的文案。**处置：提高样式区分度与文案，不得通过删掉 `void` 柱来解决**（删掉即为损耗重新不可见） | 07 §10.3「测试者能理解 `void` 的含义」 |
| **T14 品质切换重绘（v0.6 验收）** | 在同一会话内把当前套系从品质 2 切到品质 3，再切回：① 断言镶嵌位**格数 = 新套系的 `socket_count`**（3 ↔ 4），格子与占用标记一并重绘；② 断言直方图**柱数 = 新套系的 `regular_count + 2`**（10 ↔ 14），款序按新套系重建；③ 断言上一个套系的形状**零残留**——不残留旧格数、旧空位、旧 `void` 柱、旧 `ban` / `boost` 标记；④ 断言默认层两个数字按新套系重取，且品质标识按 §3 书写规范渲染 | 位子数与柱数是**每套系常量**；写死、缓存或增量重绘即缺陷（R-13 / 核心 §4.1.1 / P7） |

**切片期必采指标：** 展开层打开率、人均展开次数、首次镶嵌到首次展开的时长、"共有 N 款"的点击率、**`void` 来源行的查看率**。展开率过低即触发 T11 ①。
