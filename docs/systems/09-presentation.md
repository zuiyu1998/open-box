> **本文档的最高铁律**
> 演出层**订阅结果事件**，**不参与任何随机数生成或结算**。
> 演出层内不得出现 `randi` / `RandomNumberGenerator` / `GachaService.roll` / `PoolService.*` 的调用。
> **先结算结果，再播放演出**：`Result` 在演出开始前已由 01 生成，演出只播放已知结果。

> **v0.13 同步（去除隐藏款）——演出层的音画分级由三档减为两档。**
> 上游删除了隐藏款（核心 §5.4 / §16.8）：每个套系**全部是常规物品**、**全部物品共分 100%**，红线 **C3 作废**（**行号保留、不重编号**）。对本系统的改动：
> ① **分级预告只有两档**：**常规 / 稀有**（`void` 取最低档，§5.8）；`Tier.HIDDEN` 枚举、隐藏档的时长键与分级语言、强制完整播放设置**全部删除**——**剩余档位保持原有名字与相对顺序**（本层内部约定，**不牵动跨文档编号**）。
> ② **隐藏档的停顿延长（`hold_extend_hidden_s`）删除**：`HOLD` 对所有档位恒为 `hold_s`（1.5s）；段时长合计变为 **常规 4.5s / 稀有 5.0s / `void` 3.1s**——**15s 硬上限、4.5–7s 区间、可跳过规则、批量兑现规则一律不变**（§5.1 / §5.2）。
> ③ **P4 说明改写**（§5.3）：原先"隐藏档预告等价于指认该物品"的论证**随隐藏档一并删除**——演出播放的是**已结算**结果，P4 约束的是**结算前**的不可预知性。
> ④ **不变**：`void` 的全部分级与补偿规格（§5.8）、溢出告知（§5.9）、订阅已结算结果的最高铁律、演出层不参与结算；**红线清单随 C3 作废只回归 C1 / C2 / C4 / C6**（§10 T11）。

> **v0.11 同步（去除保底系统）——演出的补偿清单少了一项，这是本次改动最需要正视的代价。**
> 上游**删除了保底**（核心 §4.1 / §5.4 / §5.6 / §16.6）：**一次抽取的概率就是公布的分布，不存在任何"必出"覆盖**。对本系统的四处改动：
> ① **§5.8 V5（`void` 的补偿呈现）删掉"保底计数推进"这一项**——核心 §5.6 已重写：`void` 现在**不推进任何计数器**，**它的补偿只剩演出层**（**两项**：池子损耗来源提示 + 盒已消耗确认）。§5.8 的全部分级规格（V1–V8）与相关测试断言已按此改写（**凡依赖"保底推进"的断言，一律改成断言"该元素不再存在"**）。
> ② **§5.5「重复物品的体面」四项 → 三项**：删掉"保底计数 `pity` 变化"（见 §5.5 / §10 T7）。
> ③ **"必出"的语言一律消失**：演出层**不得出现任何"必出 / 下一次一定出 / 系统会兜底 / 再开几次就该出了"式暗示**——保底已删除，任何"必然发生"的表述都在破坏 P1 的严格性（核心 §16.6；§5.8 V8 已加这条禁令）。
> ④ **§10 的演出层断言清理**：T2 / T4 / T9 / T14 / T15 / T16 中凡涉及 `pity` / 保底计数处已删除或改为"**不得出现**"式断言（§10）。
> **不变**：§5.8 `void` 的时长与分级规格（V1–V4、V6、V7 的归因展开）、**4.5–7s、15s 硬上限、可跳过规则、批量兑现规则**、§5.9 的溢出告知规格；演出层的最高铁律（订阅已结算结果、不参与结算、不重抽）同样不变。

> **v0.10 同步（池子随盒子走）——演出只反映"被兑现那个盒子"的池子，本层只改三处口径。**
> 上游把池子从"套系的共享状态"改判为"**每个盒子的属性**"（核心 §4.1.2 / §16.5），并澄清 **`Box` 下面是两个并列字段**：**`item_pool`（物品池，生成数据的凭证）+ `modules`（模块列表）**——**模块不是折进池子里的**，它与池子**并列**，**唯一作用方式就是更改 `item_pool` 的状态**。**池子的当前状态是这两份数据的函数**（`PoolService`（05）唯一求值/写入，`EvalService`（07）唯一求值成概率 / EV / ρ），因此**同一套系的两个盒子可以有完全不同的池子**。对本系统的三处改动：
> ① **`result_ready(result, pool_snapshot)` 里的 `pool_snapshot` 现在指"被兑现那个盒子"的池子**当前状态**快照**（**不再是"套系池子"**，也**不是**一个被模块"改写过"的池子**字段**，而是 **`f(item_pool, modules)`** 的**求值结果**的**冻结副本**——核心 §4.1.2 已固定字段名 `Box.item_pool` / `Box.modules`）——`PresentationJob.pool_snapshot` 的字段注释与所有权声明已按此改写（§3 / §4 / §7 / §8）；
> ② **§5.4「让池子编辑可感知」的规则一字未改，但数据来源改为该盒的池子**：**同一场演出只反映这一个盒子的编辑结果**——它**不是**"全局编辑状态"的展示，也不是该套系其他盒子的展示（§5.4）；
> ③ **`void` 的补偿呈现（§5.8 V5）读的同样是该盒的池子快照**——"你排除的 3 个物品贡献了这一格"只可能来自**这一个盒子**。
> **本层不读 `Box.modules`、不自己应用模块、不计算池子状态**——它只消费 01 交付的那一份快照（最高铁律：演出层不参与结算，不得调用 `PoolService.*`）。
> **§5.8 `void` 规格、4.5–7s 时长、15s 硬上限、可跳过规则、批量兑现规则一律不变**；演出层的最高铁律（订阅已结算结果、不参与结算、不重抽）同样不变——**本层仍然只读池子快照，不写池子**。

> **v0.9 同步（仓库容量与邮件）**：①`INTAKE` 段要处理**产出溢出**——02 的 `grant()` 可能把实例**直接放进邮件**（`location == &"mail"`），演出**必须告知玩家**，否则会产生"东西凭空消失"的感觉（新增 **§5.9**，回执里读 `location`，**本层不做任何溢出判定**）；②**§5.8 的 `void` 路径一字未改**（`void` 不产生实例、无编号可展示，**两项补偿仍成立**——**v0.11 起"保底推进"那一项已删除**）；③**段时长（4.5 / 5.0 / 6.7 / 3.1；v0.13：隐藏档删除后为 4.5 / 5.0 / 3.1）、15s 硬上限、可跳过规则、批量兑现规则一律不变**——溢出告知**不新增时段**，它渲染在既有的 `INTAKE` → `RHO_IMPACT` 画面内（§5.9）；④**适用范围按核心 v0.9 裁决 17 收窄**：**被动产出（开盒）放不下 → 进邮件**——本文档只处理这一条；**主动操作（转化 / 拆卸返还）放不下 → 拒绝整个操作**，它**不产生实例、也不产生任何演出**（§5.9 N8）。

> **v0.8 同步（物品实例化）**：①`INTAKE` 段触发的是 **02 创建实例**（`ItemService.grant`），演出层**取回 `instance_id` 与 `serial`** 用于展示，**不创建实例、不分配编号**；②§5.5 的"体面"改为展示**新实例的收藏编号**（"这是你的第 187 个星尘"）而非"数量 +N"；③**时长、可跳过规则、`void` 规格、15s 硬上限、批量兑现规则一律未改**——`void` 不产生实例，故 §5.8 的补偿呈现（损耗来源 + 盒已消耗）**一字不动**。（**v0.11 已作废本条里原来并列的第三项"保底推进"**——保底在 v0.11 被整体删除，见文首 v0.11 说明。）

## 1. 这个系统负责什么

1. **四段式时间轴**的完整规格与播放：摇盒 → 破封 → 分级预告 → 揭晓入库（核心 §9）。
2. **总时长控制**：推荐 4.5–7s，**硬上限 15s**（核心 §9）。
3. **可跳过规则**：常规结果可跳过，稀有结果强制完整播放（核心 §9 / R7）。
4. **分级预告的音画分级**：常规 / 稀有**两档**（v0.13：隐藏档已删除）的颜色、频段、光效语言；`void` 取**最低档**（§5.8）。
5. **让池子编辑在演出中可感知**（核心 §5 的新增要求）：被**排除**的物品不出现；被**提升**的物品有可感知的视觉倾向。**v0.10：读的是"被兑现那个盒子"的池子**——**同一场演出只反映这一个盒子的编辑**，不代表"全局编辑状态"，也不代表该套系其他盒子（§5.4）。
6. **重复物品的"体面"呈现**（P5）：重复必须仍被读作一次进展——v0.8 起用**新实例的收藏编号** `serial` 表达（"这是你的第 187 个星尘"，见 §5.5）。
7. **兑现后立刻显示本次产出对 ρ 的影响**（核心 §13.1 兑现链条）。
8. **批量兑现**：一次队列内连续兑现多个 `Box`。
9. **空洞 `void` 结果的呈现**（见 §5.8）：`void` 是排除损耗的显式零价值结果（`README.md` §6.1 / `07-economy-rho.md` §5.4），演出必须能播它，且**不得给它稀有档的分级语言**。
10. **`INTAKE` 的入库广播 = 02 创建实例（v0.8）**：本层在 `INTAKE` 触发 `ItemService.grant`，并**取回 `instance_id` / `serial` / `location`** 供演出展示；**实例的创建、`serial` 的分配与幂等全部归 02**（核心 §4.2.1 / §14.2 铁律 8）。
11. **产出溢出的告知（v0.9）**：`grant()` 的回执可能表明该实例**已直接进入邮件**（`location == &"mail"`，核心 §4.7）。此时演出**必须告知玩家**"本件已存入邮件"，否则玩家会以为东西凭空消失（**§5.9**）。**本层不做溢出判定**——判定在 02 的 `grant()` 内部；本层只渲染回执。

## 3. 核心概念与术语

沿用 `README.md` §5 术语表：盲盒 `Box`（**v0.10：每个盒子带着稳定身份 `box_id`，并挂着自己的 `item_pool` + `modules`**）／套系 `Series`／物品 `Item`／**物品实例 `ItemInstance`**（`instance_id` / `item_id` / `acquired_at` / `source` / `serial`，核心 §4.2.1）／**重复即新实例**（v0.8：`count` 是派生值，不再是存储字段）／池子 `Pool`／池子状态 `PoolState`（**v0.10：由该盒 `item_pool` + `modules` 求值而来的"当前状态"——派生值、不入档**；演出只消费**被兑现那个盒子**的那一份，§5.4）／排除 `ban`／提升 `boost`／闭环收益率 `rho`。**v0.11：保底 `pity` 已从沿用的术语表项中删除**——该概念与计数器整体不存在（核心 §4.1 / §16.6）。**v0.13：隐藏物品 `hidden` 已从沿用的术语表项中删除**——池中**全部是常规物品**（核心 §5.4）。
另沿用 `07-economy-rho.md` §3 的 **空洞 `void`**：排除损耗产生的**零价值结果**（`v = 0`），满足**物品概率之和 + `void_prob` 恒为 100%**（`README.md` §6.1；v0.13：不再有隐藏款的 0.02）。
另沿用核心 §4.7 的**位置 `location`**（v0.9）：实例要么在**仓库 `warehouse`**（计入 `count()`，可用于交付 / 装配 / 镶嵌 / 转化），要么在**邮件 `mail`**（**不计入可用持有**，**不可**用于上述四种操作）。演出层只消费 `grant()` 回执里的 `location`，**既不判定、也不改写**（§5.9）。**注意区分（核心 v0.9 裁决 17）**：`location == mail` 只由**被动产出（开盒）**的溢出造成；**主动操作（转化 / 拆卸返还）放不下时整个操作被拒绝**，根本不产生实例——因此本层**没有**它们的溢出告知分支（§5.9 N8）。

本系统新增的**演出层局部**概念（不进入全局术语表）：

| 中文名 | 代码名 | 说明 |
|---|---|---|

| 段落 | `phase` | 四段式中的一段：`SHAKE` / `SEAL_BREAK` / `TEASE` / `REVEAL` |
| 停顿 | `HOLD` | 分级预告之后"什么都不出现"的留白段，是**设计出来的** |
| 兑现作业 | `PresentationJob` | 单个 `Box` 的一次演出实例，只读持有结果 |
| 兑现批次 | `BatchJob` | 一次连续兑现多个 `Box` 的队列 |
| 位置回执 | `intake_location` | v0.9：`INTAKE` 时 02 的 `grant()` 回执中的 `location`（`warehouse` / `mail`）；本层据此决定是否显示溢出告知（§5.9）`[补充]` |
| 溢出告知 | `mail_notice` | v0.9：回执为 `mail` 时，在 `INTAKE` → `RHO_IMPACT` 画面内给出的**一次性**提示「本件已存入邮件」（§5.9）`[补充]` |
| 被兑现盒子的池子快照 | `pool_snapshot`（`PresentationJob` 字段） | v0.10：**被兑现那个盒子自己的**池子当前状态冻结快照——**来源是 `f(item_pool, modules)`**，即「该盒 `item_pool` + `modules`」的**求值结果**（**不是**"一个被模块改写过的池子字段"，字段名由核心 §4.1.2 固定）。**一场演出只用这一份**——不合并其它盒子、不回退到套系基础池（§5.4 / §10 T18） |

**术语纪律**：不得把 `tier` 写成"品质"；**"品质"有两个含义，引用时必须写全**——**物品品质 `quality`**（物品的等级维度，1–5 序数，取自 `ItemDef.quality`，归 `02-item.md`）与**套系品质 `series_quality`**（套系分级，决定常规物品数 `regular_count` / 镶嵌位数 / 装置槽位数，归核心 §4.1.1），二者不得混用；不得把 `HOLD` 与暂停/加载混为一谈；`void` 是**零价值结果**，不是"失败""抽空""报错"——文案与音效中不得出现否定性表述（P5，见 §5.8）。**v0.8 追加**：`serial` 是**收藏编号**（该玩家开出的第 N 个此物品），`serial == 0` 表示**非开盒来源**（转化 / 返还 / 解锁发放，核心 §4.2.3），**不得渲染成"第 0 个"**；`serial` 不得与"数量"混为一谈——数量是派生值 `count`，编号是个体的身份。

## 5. 规则与公式

### 5.1 时间轴表格（段 / 时长 / 内容 / 玩家可操作性）

| 段 `phase` | 时长 | 内容 | 玩家可操作性 |
|---|---|---|---|
| **摇盒 `SHAKE`** | **1.0–1.8s** | 盒子晃动；**被提升物品**有可感知的份量倾向（更重、晃动更沉）、摇盒音效不同；**被排除物品不出现在任何候选暗示中**（**v0.10：两者都读"该盒"的池子快照**——同一场演出只反映这一个盒子的编辑，§5.4） | **可操作**：点击/按住改变晃动节奏与音效密度——**制造掌控错觉**。输入不改变任何结果（P4），只改变播放表现；输入窗口 `shake_input_window_s` |
| **破封 `SEAL_BREAK`** | **0.4–0.6s** | 封条破裂、光缝、短促冲击音；不出现任何物品的形象 | 不可操作（太短，输入被忽略） |
| **分级预告 `TEASE`** | **0.3s** | **先只说稀有度，不说是哪一个物品**：档位色、档位图标形状、档位音高 | 不可操作 |
| **停顿 `HOLD`** | **1.5s** | **任何东西都不出现**：没有物品、没有名字、没有数量、没有概率；只有暗示——档位色的呼吸、低频/中频余韵 | 不可操作。**这段留白是设计出来的，不得为节奏紧凑而删除或压缩** |
| **揭晓入库 `REVEAL` → `INTAKE`** | **1.0–1.5s** | 揭晓：该物品形象、名称、`tier` 回归常规色；入库：**02 创建实例**并回填**新实例的收藏编号**（"这是你的第 187 个星尘"）、重复物品的进展信息（§5.5）、套系完成度变化；随后立刻弹出 ρ 影响提示（§5.6） | **可操作**：常规档可继续点击加速收束；`reveal_present_hold_s` 内可读产出 |

**档位推荐的段时长与合计**

| 段 | 常规 | 稀有 | 空洞 `void` |
|---|---|---|---|
| 摇盒 `SHAKE` | 1.2 | 1.5 | 1.0 |
| 破封 `SEAL_BREAK` | 0.5 | 0.5 | 0.5 |
| 分级预告 `TEASE` | 0.3 | 0.3 | 0.3 |
| 停顿 `HOLD` | 1.5 | 1.5 | **0.3** |
| 揭晓入库 `REVEAL` | 1.0 | 1.2 | 1.0 |
| **合计** | **4.5** | **5.0** | **3.1** |

`[补充]` 上表澄清核心 §9「4.5–7s」的口径：四段之和的下界由**常规档**给出（4.5s 整），当前最高档是**稀有档**（5.0s：更长的摇盒 + 更长的揭晓）；**7s 是允许上界**，两档都远低于它。理由：用户要求的总时长区间必须与逐段时长自洽（v0.13 沿革：隐藏档删除前，上界曾由它的停顿延长给出 **6.7s**）。

`[补充]` **`void` 是时长区间的显式例外**（合计约 3.1s，低于 4.5s）：留白服务于"期待好东西"，对一个零价值结果保留 1.5s 停顿等于戏弄玩家（§5.8）。理由：4.5–7s 的下界是为**有产出的结果**设定的，`void` 不在其语义覆盖内。

```
total_play_s(tier) = shake_s[tier] + seal_break_s[tier] + tease_s
                   + hold_s + reveal_s[tier]        # v0.13：HOLD 不再有隐藏档延长
total_play_s(void) = shake_s[NORMAL] + seal_break_s[NORMAL] + tease_s + hold_void_s + reveal_s[NORMAL]
play_s(tier)       = min(total_play_s(tier), hard_cap_s)     # hard_cap_s = 15.0
```

**硬上限守护**：`elapsed_s > hard_cap_s` 时**无条件**进入 `FORCE_FINISH`——跳至 `REVEAL` 尾帧 + `INTAKE`（入库广播**必须送达**），不得静默丢弃。任何 tick 抖动、断点、资源加载失败都不得让 `play_s` 越过 15s。

### 5.2 可跳过规则

| 档位 `tier` | 可跳过 | 规则 |
|---|---|---|
| 常规 `NORMAL` | ✅ | `SHAKE` 段起任意时刻可跳过：直接进入 `REVEAL`（`skip_fade_s` 收束）。**跳过不改变结果** |
| 稀有 `RARE` | ❌ | **强制完整播放**（核心 §9；R7：每个数量级/每档稀有度都要有新的可感知内容）。跳过输入被忽略并给出弱提示 |
| **空洞 `void`** | ✅ | **可跳过**（归最低档，见 §5.8）。强制完整播放一个空结果会显著加剧挫败 |

`void` 归入最低档，因此自动继承常规档的可跳过资格——**不得**把它放进 `force_complete_tiers`（见 §5.8）。

批量兑现中的可跳过规则：常规档播**压缩版**（跳过摇盒与破封，只播预告+停顿+揭晓）；稀有档**强制完整播放并暂停队列**，播放结束后继续队列。

### 5.3 分级预告的音画分级规格

| 档位 | 颜色 | 频段 | 图标形状 | 附加 |
|---|---|---|---|---|
| **常规** | 中性色（灰白、无彩） | 低频 | 圆角方 | — |
| **稀有** | 暖色（琥珀 → 橙） | 中频 | 菱形 | 音高高于常规一档 |
| **空洞 `void`** | 去饱和冷灰（**弱化形态**，饱和度低于常规） | 低频残余（音量低于常规，**不上扬**） | 圆角方（**与常规同形**，尺寸更小） | **无**上扬音高、无稀有档语言 |

`[补充]` **`void` 必须复用常规档的分级语言**：它归**最低档**（§5.8）。**绝不能**给 `void` 任何稀有档的分级语言（暖色 / 中频 / 上扬音高），否则玩家会误以为开到了好东西——这是比"什么都不播"更糟的误导。

**双重编码**：档位同时用**颜色 + 图标形状 + 频段**三种通道表达，任一通道单独可辨；因此色觉差异玩家在无设置菜单的情况下也能读出档位（核心 §13.2 不做设置菜单，故不依赖可访问性选项）。

**停顿期间的信息封锁（`[补充]`）**：核心 P4 否决"透视/预知"，故 `HOLD` 段内必须屏蔽一切可提前暴露结果的通道——开箱日志、图鉴/套系进度刷新、默认层与展开层的实时联动（**v0.11：原"保底计数刷新"已从该清单删除**——保底不存在）。理由：这些通道若在揭晓前刷新，等价于把已结算结果漏给玩家。入库广播与图鉴刷新统一发生在 `INTAKE`。

`[补充]` **P4 说明（v0.13 改写）**：分级预告只暴露**档位**（该物品的 `quality` 是否 ≥ `tier_quality_threshold`），**不指认具体物品**；演出播放的是**已结算**结果，而 P4 约束的是**结算前**的不可预知性。（v0.13 沿革：原先另有一段"**隐藏档预告等价于指认那一款隐藏物品**"的论证——隐藏款删除后该情形**不存在**，论证随之一并删除；核心 §5.4。）

### 5.4 让池子编辑可感知（核心 §5）

| 编辑操作 | 演出中的可感知表现 | 边界 |
|---|---|---|
| 排除 `ban` | 该物品**不出现**在摇盒段的任何候选暗示、也不出现在预告/揭晓的候选中 | 结果侧本就不会产出（`01-gacha.md`）；本系统另做**展示侧**过滤：从**该盒的** `pool_snapshot` 读取被排除物品并剔除 |
| 提升 `boost` | 该物品"份量"更重：晃动更沉、摇盒音效不同（更低的撞击音 + 更长的尾音）；摇盒暗示中其形象的出现权重更高（**纯表现层权重**，与概率无关） | **严禁**让表现层权重影响结果；表现层的候选暗示不是概率的可视化 |

理由（核心 §5）：如果池子编辑在演出中不可感知，玩家会觉得自己的施工没有落地。**演出的职责是让玩家看到自己的池子在起作用。**

**v0.10：本节的数据来源是"被兑现那个盒子"的池子（规则一字未改，只换数据来源）。**
池子随盒子走之后（核心 §4.1.2），**同一场演出只反映这一个盒子的编辑结果**——它**不是**"全局编辑状态"的展示，也**不是**该套系其它盒子的展示：

- 盒子 A 排除了物品 X、盒子 B 没有排除 → **A 的演出里 X 不出现**，而 **B 的演出里 X 照常可能出现**（§10 T18）；
- 一场演出的 `SHAKE` / 预告 / 揭晓过滤**只用一份快照**（该盒的 `pool_snapshot`）：**不得**把多个盒子的池子并起来算，也**不得**回退去读套系的基础池；
- 快照由 01 在结算时冻结、随 `result_ready` 一起交付（归属 05），**本层只读、不写池子、不重抽**（最高铁律）；**它的来源是该盒的 `item_pool` + `modules`（由 05 折算成池子状态）**——本层**既不读 `modules`、也不自己应用模块**：演出看到的是"**这一个盒子**的池子现在长什么样"，而不是"我改了哪些模块"。

### 5.5 重复物品的"体面"规格（P5）

常规物品重复时**不得羞辱玩家**（禁止"再来一次""重复"等否定性文案与贬低性音效）。重复必须显示下列**变化量**，让它在视觉上仍是一次进展：

| 必须显示 | 数据来源 |
|---|---|
| **新实例的收藏编号 `serial`**（"这是你的第 187 个星尘"）——v0.8 取代原"该物品数量 `+N`" | 02：`ItemService.grant` 在 `INTAKE` 的回执（核心 §4.2.1） |
| **套系完成度变化**（该套系集齐进度） | 见 `10-progression.md` |
| "它还能去哪儿"提示：该物品可作装置/模块素材（P5：重复物品是原料） | 见 `04-device.md` / `05-module-pool.md` |

> **v0.11：本表由四项减为三项**——原第 2 行「**保底计数 `pity` 变化**」**整行删除**（保底与计数器已整体删除，核心 §4.1 / §16.6）。**这是删保底在演出层最直接的代价**：重复物品的"进展感"现在只剩**编号 + 套系完成度 + 去处提示**三条；**不得**用"离必出还差 N 次"之类的伪进展把它补回来（§5.8 V8 / §9 禁止项）。

`[补充]` **为什么用编号替换"数量 +N"**：v0.8 里 `count` 已是**派生值**，把它抬到演出层等于让演出消费一个统计量，且"数量 +N"对玩家只意味着"又多了个没用的"；`serial` 则是**这次开盒独有、不可复现**的——它同时表达"又得到一个"与"这是第几个"，正是 P5 要的**收藏叙事**。**边界**：`serial == 0` 的实例（转化 / 返还 / 解锁发放）**不经过开盒演出**，故本节**三项**只针对开盒产出的实例；**演出层不得为任何结果编造编号**（`void` 见 §5.8 V5）。

`[补充]` 说明：指令中提到的"碎片""升阶"在核心设计书 v0.5 中不存在，本系统**不实现**（不得发明新机制），已列入 §11 待定项。

### 5.6 兑现后立刻显示对 ρ 的影响

`REVEAL` → `INTAKE` 之后**立刻**（同一画面内，不得需要玩家手动切换面板）显示：

1. 本次产出的 **Δρ / ΔM̄**（必须取自 `EvalService`，见 `07-economy-rho.md`；**演出层不得另算**，跨系统铁律 3）；
2. **"这批原料能完成几个任务"**（需求向量 vs 持有物品向量的匹配数，口径见 `03-task.md`）；
3. 归因摘要的一句式表述（P2：每一次 ρ 的上升都必须可归因）。
4. **本盒结果为 `void` 时**：ρ 影响提示必须**展开归因中的损耗项**（`AttributionEntry{source_kind = LOSS}`，"池子损耗"）并标注"本次结果即由该项产生"，**不得**只显示一个没有来源的负数（详见 §5.8）。

`[补充]` 批量兑现时（§5.7）上述各项按**批次聚合**后再展示一次，避免逐盒刷屏；单盒模式则逐盒展示。理由：核心未规定批量形态下的展示粒度。

### 5.7 批量兑现（必要功能）

`[补充]` 批量兑现：核心 §4.6 只写了"盲盒可囤积"，未写批量。但 ρ 成型后玩家会**连续验证**自己的池子（核心 §13.3 的囤积行为判据），逐盒强制播完四段式在时间上不可接受。故补一个**排队播放器**：不新增任何结算或概率机制，只复用单盒管线，且完全遵守 §5.2 的可跳过规则。

规则：
1. 队列元素为 `Box`；**每个 `Box` 独立走一次 01 的结算**，逐盒结算、逐盒入库，**不是**一次批量结算。
2. 顺序 = 队列顺序，不重不漏；`N` 个 `Box` 恰好 `N` 次 `roll()`。
3. 档位为**稀有**的盒**暂停队列**并强制完整播放；播放完毕后继续。
4. 批次结束后显示一次批次汇总（产出清单 + 聚合 Δρ + 可完成任务数）。

### 5.8 空洞 `void` 的演出规格

**背景**：`void` 是 C2 的 40% 损耗的落地形式——蒸发的概率不消失，而是成为一个**显式的零价值结果**（`README.md` §6.1、`07-economy-rho.md` §5.4、`05-module-pool.md` §5.4）。玩家能开出 `void`，因此**演出必须能播它**。

`[补充]` 本小节全部为落地细节：上游只裁决了 `void` 的数值语义，未规定它怎么播。理由：不给规格就会出现"空结果临时拼一个动画"的散装实现。

| # | 规格 | 裁决 |
|---|---|---|
| V1 | **`tier` 判定** | `void` 归**最低档**（复用常规档的时长键与分级语言，`is_void = true` 走弱化分支）。**严禁**给稀有档分级语言——那是误导 |
| V2 | **`HOLD` 停顿** | **缩短至 `hold_void_s`（0.3s）**，不是跳过整段。理由：留白的目的是放大**期待好东西**的悬念，对一个零价值结果做 1.5s 留白是对玩家的戏弄 |
| V3 | **揭晓表现** | 呈现为**"这一格是空的"**：盒子内是空的格位（注意：是空**格位**，不是"抽空了/失败了"）。档位色回落为去饱和冷灰，无音高上扬、无稀有档语言（§5.3） |
| V4 | **文案与音效禁令（P5）** | 禁止"很遗憾""什么都没有""抽空了""白开""failed"等否定性文案与贬低性音效；禁止失望音效、禁止灰屏、禁止"重试"式按钮 |
| V5 | **补偿呈现（必须立刻、同一画面内）——v0.11：由三项减为两项** | 立刻显示这次兑现**换到了什么**：①**池子状态提示**（本盒产出的空位来自玩家自己的排除，例如"损耗：你排除的 3 个物品贡献了这一格"，措辞数据来自**被兑现那个盒子的**池子当前状态快照（= 该盒 `item_pool` + `modules` 的求值结果）——v0.10：每盒一份，"你排除的 3 个物品"只可能指这**一个**盒子，见 `05-module-pool.md`）；②该 `Box` 已消耗的确认。**不显示**升阶/碎片（核心 v0.5 无此机制，见 §11 P09-1）。**⛔ v0.11 删除项：原①「保底计数 `pity` 推进」整项删除**——核心 §5.6 已重写：`void` **不推进任何计数器**（保底已删除），**它的补偿只剩演出层**，而演出层只剩上述**两项**。**不得**用"离必出还差 N 次""再开几次就该出了"之类的话术把它补回来（V8 / §9 禁止项 / 核心 §16.6）。**v0.8 确认**：`void` **不产生实例**，因此**没有 `serial` 可展示**——上述**两项**全部不依赖任何实例字段，**在实例化之后仍成立**；`void` 的 `serial` 保持 0，本层不得为其编造编号 |
| V6 | **可跳过** | ✅ 可跳过（归最低档，§5.2） |
| V7 | **ρ 影响归因** | ρ 影响提示（§5.6）**必须**展开 `EvalService` 归因中的 `LOSS` 项（"池子损耗"）并标注本次结果由该项产生；**不得**让玩家看到一个无法解释的数值下降（P2）。`void_prob` 只从 `EvalService` 读取，**演出层不计算**任何数值 |
| V8 | **不得反向暗示，也不得暗示"必出"（v0.11 加后半句）** | 演出**不得**做成"再来一次就会好"的话术（核心 P4：可优化的是分布，不是结果）；`void` 的正解是**去池子面板看损耗、决定是否拆卸模块**，提示应把玩家导回 `05-module-pool.md` 的编辑台。**v0.11 追加**：**保底已删除**，因此**不得出现任何"必出 / 距下次必出还差 N 次 / 系统会兜底 / 再开几次就该出了"式暗示**——一次抽取的概率**就是**公布的分布，任何"必然发生"的表述都在破坏 P1 的严格性（核心 §16.6）。**这条同时是对"删掉 V5 保底项"的补偿纪律**：缺了"离必出还差多少"的进展感，**不许**用别的伪进展补回来 |

**为什么 `void` 极其重要**：它是玩家亲手施工的**可见后果**——"我把池子凿出了一个洞"（`05-module-pool.md` §5.4）。因此 `void` 的演出不是"处理坏结果"，而是**让损耗可感知**，与 §5.4（让池子编辑可感知）同源。

### 5.9 产出溢出的告知（v0.9）

**背景**：核心 §4.7 定下"任何产出放不下就进邮件"。于是**"揭晓入库"这一步现在有两种落位**：实例进仓库，或进邮件。若演出对两者不作区分，玩家会看到一个物品被揭晓、然后**在仓库里找不到它**——这正是 P5 要防的"我什么都没得到"的观感（尽管规则上什么都没丢）。

`[补充]` 本小节全部为落地细节：上游只裁决了"溢出进邮件"与"演出必须告知"，未规定呈现形态。理由同 §5.8——不给规格就会出现"临时拼一句文案"的散装实现。

| # | 规格 | 裁决 |
|---|---|---|
| N1 | **触发条件** | `INTAKE` 的回执实例 `location == &"mail"`（本层把它抄进 `intake_location`）。**判定只读回执**——本层**不得**读取容量 / `size` / 占用，也不得自行推测"这次应该放不下"（核心 §4.7：判定在 02 的 `grant()` 内部，且**全库只有这一个判定点**） |
| N2 | **位置与时机** | 在 `INTAKE` 的入库信息里追加一行，并在 `RHO_IMPACT` 画面内**保持可见**。**不新增时段、不改动任何段时长与合计**（§5.1 / §6 的时长表一字不动） |
| N3 | **文案** | 「**本件已存入邮件** · 仓库空间不足」——中性、陈述事实。**禁用**"丢失 / 被回收 / 消失 / 溢出失败"等否定性词（与 §5.8 V4 同一禁令）。**必须**同时给出"到哪里找"：指向架上面板 → 邮件抽屉（`08-ui-panels.md` §9.7） |
| N4 | **不得表现为"什么都没得到"** | 揭晓**照常完整播放**：形象、名称、档位色、以及 §5.5 的收藏编号四项**全部保留**。溢出是**位置**的差别，**不是产出的差别**——物品确实到手了，只是先落在邮件里（P5） |
| N5 | **与 `void` 严格区分** | `void` 是**没有实例**（§5.8）；溢出是**有实例、只是位置在邮件**。两者**不得共用文案、不得共用样式**：溢出走常规档的完整揭晓 + 一行位置说明；`void` 走 §5.8 V1/V3 的弱化分支 |
| N6 | **批量兑现** | 逐盒照常（每盒各自判定）；**批次汇总**追加一行「其中 N 件存入邮件」，N = 批次内 `mail` 回执的计数。**口径只数回执，不推算**；`void` 盒不计入 N |
| N7 | **中断 / 补送** | 中断补送的 `INTAKE` 若回执为 `mail`，告知**仍须送达一次**（与 §7 的"入库广播必达"同级）；重复补送不得重复计数（幂等归 02，本层只取回执） |
| N8 | **适用范围：只管被动产出（核心 v0.9 裁决 17）** | §5.9 **只覆盖被动的开盒产出**（放不下 → 进邮件）。**主动操作**（转化 / 拆卸返还）空间不足时**拒绝整个操作**——**不产生实例、不产生演出**；因此本层**没有**它们的溢出分支，也**不得**为它们实现一个。**理由**：若主动操作的产出一律进邮件，**转化会反噬**——销毁源腾出了空间、产出却进邮件，等于**净损失可用持有** |

**为什么这条区分正落在这里（裁决 17 的目的）**：R14 的整套对策要解决的是"**攒了一堆盒子却不敢开**"。这个恐惧只来自**被动产出**——玩家对开盒结果没有任何控制权，所以必须保证"开了就一定有收获"。主动操作反之：那是玩家**自己按下的按钮**，它可以被拒绝，因为玩家能改主意（先丢弃 / 先交付腾空间）。**§10 的 T16 正是这条规则的目的所在**：只要开盒（被动）依然"永不空手"，R14 就守住了。

**为什么这条如此重要**：R14 的整套对策建立在"玩家相信东西不会丢"上（核心 §12 R14 对策①）。**演出不告知，玩家就只能靠翻邮件才发现自己的东西**——那正是"开了没处放"的心理摩擦**没有被解决**的样子（核心 §4.7 的"已知风险"）。演出是唯一能把这个事实**当场**说清楚的地方。

## 7. 流程 / 状态机

```
                        result_ready(result, pool_snapshot)   ← 结算已完成（01/07）
                                   # v0.10：pool_snapshot = **被兑现那个盒子**的池子快照（每盒一份，**不是"套系池子"**）
                                   │
   IDLE ───────────────────────▶ SHAKE
                                   │ elapsed ≥ shake_s
                                   ▼
                              SEAL_BREAK
                                   │ elapsed ≥ seal_break_s
                                   ▼
                                 TEASE
                                   │ elapsed ≥ tease_s（只说档位）
                                   ▼
                                 HOLD ── 无任何内容，只有暗示
                                   │ elapsed ≥ hold_s（v0.13：不再有隐藏档延长）
                                   ▼
                                REVEAL
                                   │ elapsed ≥ reveal_s
                                   ▼
                                INTAKE ── 入库广播（02 创建实例并回填 instance_id / serial / location）+ 图鉴/进度刷新（10）
                                   │        └ 回执 location == mail ──▶ 溢出告知（§5.9，同一画面内，不新增时段）
                                   │
                                   ▼
                              RHO_IMPACT ── EvalService 输出，本层只渲染
                                   │
                                   ▼
                                 DONE

  旁路 1（跳过，仅 NORMAL，含 void）:  SHAKE|SEAL_BREAK|TEASE|HOLD ──skip──▶ REVEAL
  旁路 2（硬上限守护）:      任意 phase ──elapsed > hard_cap_s──▶ FORCE_FINISH ──▶ REVEAL(尾帧) ──▶ INTAKE
  旁路 3（中断）:            任意 phase ──abort()──▶ ABORTED ──▶ 强制补送 INTAKE
  旁路 4（void）:            SHAKE|SEAL_BREAK|TEASE ──▶ HOLD(hold_void_s = 0.3s) ──▶ REVEAL
```

| 状态 | 进入条件 | 允许的输入 | 退出 |
|---|---|---|---|
| `IDLE` | 收到 `open_requested`，`Result` 已就绪 | — | 立即进入 `SHAKE` |
| `SHAKE` | — | 点击/按住（仅改变表现）；`skip`（仅 NORMAL） | `elapsed ≥ shake_s` → `SEAL_BREAK` |
| `SEAL_BREAK` | — | `skip`（仅 NORMAL） | `elapsed ≥ seal_break_s` → `TEASE` |
| `TEASE` | — | `skip`（仅 NORMAL） | `elapsed ≥ tease_s` → `HOLD` |
| `HOLD` | — | `skip`（仅 NORMAL，含 `void`）；**不得刷新任何结果相关 UI** | `elapsed ≥ hold_s`（`void` 用 `hold_void_s`）→ `REVEAL` |
| `REVEAL` | — | 点击加速收束（NORMAL） | `elapsed ≥ reveal_s` → `INTAKE` |
| `INTAKE` | — | — | 入库广播送达（02 的 `grant` 返回实例，本层读其 `instance_id` / `serial` / **`location`**）→ `RHO_IMPACT`（`location == mail` 时同画面内进入 §5.9 溢出告知） |
| `RHO_IMPACT` | — | 点击继续 | 展示完成 → `DONE` |
| `DONE` | — | — | 触发 `presentation_finished` |
| `ABORTED` | `abort()` / 场景销毁 | — | **强制补送 INTAKE**（结果不得丢失） |

**批量队列**：`BatchJob` 持有 `Array[Box]`，对每个 `Box` 创建独立 `PresentationJob` 并顺序驱动；`BatchJob` 本身不参与结算，只调度。

**禁止调用**：`GachaService.roll`、`PoolService.socket/unsocket`、任何直接写概率的路径（README §2.2 / 核心 §9 铁律 5）。**本层也不得自行创建实例、自行分配或递增 `serial`、自行维护任何持有量副本**——实例列表的唯一写入方是 02（v0.8）。**v0.9 追加**：**不得自行判定溢出、不得读写 `location`、不得累加 `size` 或读取容量**——"放不下"的判定只存在于 02 的 `grant()` 内部，本层只消费回执（核心 §4.7）。

## 9. UI 需求

1. **演出容器**位于 `res://src/presentation/scenes/gacha/`（路径约定见 `README.md` §4.2），**独立可测**，可在无头模式驱动状态机。
2. **画面元素**：盒子本体（含被提升物品的份量差异）／档位色与档位图标／揭晓物品形象与名称／**新实例的收藏编号（"这是你的第 187 个星尘"，v0.8 取代"数量 +N"）**／重复物品进展条（§5.5）／ρ 影响提示条（§5.6）／**`void` 的空格位表现与补偿清单**（§5.8 V3/V5）。
3. **留白纪律**：`HOLD` 段画面**不得**出现任何物品、名称、数量、概率、进度数字；只允许档位色呼吸与频段余韵（v0.13：原列的"隐藏档边缘微光"已随隐藏档删除）。
4. **不泄露**：演出期间 `08-ui-panels.md` 的默认层/展开层/图鉴**不得**提前更新（§5.3 信息封锁）。
5. **批量兑现 UI**：队列进度（第 i / N 盒）、当前盒的档位、批次汇总页；稀有盒暂停队列时给出明确提示。
6. **跳过按钮**：仅在允许跳过的档位下可见/可点；被忽略的跳过输入给出弱提示而非静默无视。
7. **音画分级**同时使用颜色 + 形状 + 频段三通道（§5.3）。
8. 占位资源即可（核心 §13.2 不做成品美术与音效）。
9. **`void` 的文案白名单**：只允许中性词（"这一格是空的""空格位""池子损耗"）；禁止 §5.8 V4 列出的否定性文案与失望音效——这是 P5 在 UI 层的落点。
10. **溢出告知（v0.9）**：`location == mail` 时，`INTAKE` 入库行与 `RHO_IMPACT` 画面内必须出现「**本件已存入邮件** · 仓库空间不足」+ 一处指向邮件抽屉的深链（§5.9 N3）；样式上**必须与常规入库可区分、与 `void` 弱化分支绝不混淆**（N5）；**不新增时段**（N2）。

**失败信号（对照核心 §13.4）**：测试者抱怨"每次都放一样的动画"（分级语言未生效）；测试者在**稀有档**演出上成功跳过（可跳过规则失效——稀有档必须强制完整播放）；测试者问"这批物品能顶几个任务"却要自己去任务面板查（§5.6 缝合失败）；**测试者在仓库满时开盒后说"东西不见了 / 没拿到"**（v0.9，§5.9 溢出告知未落地——处置：修演出告知，**不得**靠调大容量掩盖）。**v0.10 追加**：测试者在**同套系、池子不同的两个盒子**上看到**一样的候选暗示**（该排除的没消失 / 没排除的却消失了）——说明演出读了"套系池子"或复用了上一盒的快照，**§5.4 的数据来源没有逐盒落地**（处置：修快照传递，**不得**靠"反正同套系差不多"掩盖，§10 T18）。

**`void` 专属失败信号** ★：若测试者说**"白开了"**、且**并非指向重复物品而是指向 `void`**（重复物品的"白开了"见 T13 / §5.5），说明 `void` 的**演出与补偿呈现失败**——即 §5.8 V3/V5 未落地（空被播成了失败）；同时若测试者说"这游戏在骗我，概率没算对"，说明 §5.8 V7 的归因未展开（一个无法解释的数值下降）。两者都必须先修演出，**不得**靠调低 `recover_rate` 掩盖。
