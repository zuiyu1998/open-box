# 09 · 开箱演出系统

- 上游：`../core-design.md` **v0.6**（§9 开箱演出、§1.1、§5、P4、R7）／ `README.md`
- 依赖系统：`01-gacha.md`（`Result` 的唯一来源）／`05-module-pool.md`（`PoolState`，展示过滤依据）／`07-economy-rho.md`（`EvalService`，ρ 影响提示的数据源）／`03-task.md`（"能完成几个任务"的口径）／`08-ui-panels.md`（演出容器、兑换入口、面板挂载点）
- 被依赖：`08-ui-panels.md`（兑现入口调用本系统）／`10-progression.md`（入库后刷新图鉴与套系进度）
- 定位：**循环的第一步**（核心 §1.1「开盲盒：悬念、揭示」）。演出层是**纯消费者**，不产生任何数值。

> **本文档的最高铁律**
> 演出层**订阅结果事件**，**不参与任何随机数生成或结算**。
> 演出层内不得出现 `randi` / `RandomNumberGenerator` / `GachaService.roll` / `PoolService.*` 的调用。
> **先结算结果，再播放演出**：`Result` 在演出开始前已由 01 生成，演出只播放已知结果。

## 1. 这个系统负责什么

1. **四段式时间轴**的完整规格与播放：摇盒 → 破封 → 分级预告 → 揭晓入库（核心 §9）。
2. **总时长控制**：推荐 4.5–7s，**硬上限 15s**（核心 §9）。
3. **可跳过规则**：常规结果可跳过，稀有结果强制完整播放（核心 §9 / R7）。
4. **分级预告的音画分级**：常规 / 稀有 / 隐藏三档的颜色、频段、光效语言。
5. **让池子编辑在演出中可感知**（核心 §5 的新增要求）：被**排除**的款不出现；被**提升**的款有可感知的视觉倾向。
6. **重复款的"体面"呈现**（P5）：重复必须仍被读作一次进展。
7. **兑现后立刻显示本次产出对 ρ 的影响**（核心 §13.1 兑现链条）。
8. **批量兑现**：一次队列内连续兑现多个 `Box`。
9. **空洞 `void` 结果的呈现**（见 §5.8）：`void` 是排除损耗的显式零价值结果（`README.md` §6.1 / `07-economy-rho.md` §5.4），演出必须能播它，且**不得给它稀有档的分级语言**。

## 3. 核心概念与术语

沿用 `README.md` §5 术语表：盲盒 `Box`／套系 `Series`／款 `Item`／池子 `Pool`／池子状态 `PoolState`／物资 `Material`／款重复即**数量增加**／排除 `ban`／提升 `boost`／隐藏款 `hidden`／保底 `pity`／闭环收益率 `rho`。
另沿用 `07-economy-rho.md` §3 的 **空洞 `void`**：排除损耗产生的**零价值结果**（`v = 0`），满足 `Σ probs(常规款) + void_prob + 0.02(隐藏) == 1.0`（`README.md` §6.1）。

本系统新增的**演出层局部**概念（不进入全局术语表）：

| 中文名 | 代码名 | 说明 |
|---|---|---|
| 演出档位 | `tier` | 由已结算的 `Result` 推导出的展示档：常规 / 稀有 / 隐藏（`void` 见 §5.8，取最低档） |
| 段落 | `phase` | 四段式中的一段：`SHAKE` / `SEAL_BREAK` / `TEASE` / `REVEAL` |
| 停顿 | `HOLD` | 分级预告之后"什么都不出现"的留白段，是**设计出来的** |
| 兑现作业 | `PresentationJob` | 单个 `Box` 的一次演出实例，只读持有结果 |
| 兑现批次 | `BatchJob` | 一次连续兑现多个 `Box` 的队列 |

**术语纪律**：不得把 `tier` 写成"品质"；**"品质"有两个含义，引用时必须写全**——**物资品质 `quality`**（物资的等级维度，1–5 序数，归 `02-material.md`）与**套系品质 `series_quality`**（套系分级，决定常规款数 `regular_count` / 镶嵌位数 / 装置槽位数，归核心 §4.1.1），二者不得混用；不得把 `HOLD` 与暂停/加载混为一谈；`void` 是**零价值结果**，不是"失败""抽空""报错"——文案与音效中不得出现否定性表述（P5，见 §5.8）。

## 4. 数据结构（GDScript Resource 字段定义）

> `[补充]` 新增 `PresentationDef` 与 `PresentationJob`：核心 §14.1 的 `data/defs` 未列演出参数 Resource，但跨系统铁律 6（数据驱动）要求演出时长与分级语言可纯配置产出，故补一个 Resource；**不新增任何玩法机制**。

```gdscript
# res://data/defs/presentation_def.gd
class_name PresentationDef
extends Resource

@export var def_id: StringName = &"default"
@export var hard_cap_s: float = 15.0             # 核心 §9 硬上限，任何路径不得绕过

# 段时长：Dictionary 的 key 为 Tier 枚举（0 常规 / 1 稀有 / 2 隐藏）
@export var shake_s: Dictionary = {0: 1.2, 1: 1.5, 2: 1.8}        # 摇盒 1.0–1.8
@export var seal_break_s: Dictionary = {0: 0.5, 1: 0.5, 2: 0.6}   # 破封 0.4–0.6
@export var tease_s: float = 0.3                                  # 分级预告 0.3
@export var hold_s: float = 1.5                                   # 停顿 1.5（基准，所有档位）
@export var hold_extend_hidden_s: float = 1.0                     # 隐藏档停顿延长
@export var hold_void_s: float = 0.3                              # `[补充]` 空洞的停顿，显著短于基准（见 §5.8）
@export var reveal_s: Dictionary = {0: 1.0, 1: 1.2, 2: 1.5}       # 揭晓 + 入库 1.0–1.5

@export var shake_input_window_s: float = 0.6    # 摇盒段内可操作的输入窗口
@export var skip_fade_s: float = 0.25            # 跳过时的收束淡入
@export var force_complete_tiers: Array[int] = [1, 2]   # 强制完整播放的档位：稀有 / 隐藏
@export var batch_interval_s: float = 0.35       # 批量兑现的盒间间隔
@export var tier_star_threshold: int = 4         # `[补充]` 档位判定口径：star ≥ 阈值即稀有
@export var reveal_present_hold_s: float = 0.6   # 揭晓后停留（供玩家读产出）
```

```gdscript

extends RefCounted

enum Tier { NORMAL = 0, RARE = 1, HIDDEN = 2 }

var box_id: StringName

var tier: Tier
var is_void: bool = false     # `[补充]` 由 Result 判定；void 复用 Tier.NORMAL 的时长键，另走弱化表现分支

```

**所有权声明**：`result` 与 `pool_snapshot` 均为**只读引用**。`PresentationJob` 不持有也不修改任何池子状态、保底计数、背包数据。

## 5. 规则与公式

### 5.1 时间轴表格（段 / 时长 / 内容 / 玩家可操作性）

| 段 `phase` | 时长 | 内容 | 玩家可操作性 |
|---|---|---|---|
| **摇盒 `SHAKE`** | **1.0–1.8s** | 盒子晃动；**被提升款**有可感知的份量倾向（更重、晃动更沉）、摇盒音效不同；**被排除款不出现在任何候选暗示中** | **可操作**：点击/按住改变晃动节奏与音效密度——**制造掌控错觉**。输入不改变任何结果（P4），只改变播放表现；输入窗口 `shake_input_window_s` |
| **破封 `SEAL_BREAK`** | **0.4–0.6s** | 封条破裂、光缝、短促冲击音；不出现任何款的形象 | 不可操作（太短，输入被忽略） |
| **分级预告 `TEASE`** | **0.3s** | **先只说稀有度，不说是哪一款**：档位色、档位图标形状、档位音高 | 不可操作 |
| **停顿 `HOLD`** | **1.5s**（隐藏档 +1.0s = 2.5s） | **任何东西都不出现**：没有款、没有名字、没有数量、没有概率；只有暗示——档位色的呼吸、低频/中频/高频余韵、隐藏档的屏幕边缘微光 | 不可操作。**这段留白是设计出来的，不得为节奏紧凑而删除或压缩** |
| **揭晓入库 `REVEAL` → `INTAKE`** | **1.0–1.5s** | 揭晓：该款形象、名称、`tier` 回归常规色；入库：数量 +N、重复款的进展信息（§5.5）、套系完成度变化；随后立刻弹出 ρ 影响提示（§5.6） | **可操作**：常规档可继续点击加速收束；`reveal_present_hold_s` 内可读产出 |

**档位推荐的段时长与合计**

| 段 | 常规 | 稀有 | 隐藏 | 空洞 `void` |
|---|---|---|---|---|
| 摇盒 `SHAKE` | 1.2 | 1.5 | 1.8 | 1.0 |
| 破封 `SEAL_BREAK` | 0.5 | 0.5 | 0.6 | 0.5 |
| 分级预告 `TEASE` | 0.3 | 0.3 | 0.3 | 0.3 |
| 停顿 `HOLD` | 1.5 | 1.5 | 2.5 | **0.3** |
| 揭晓入库 `REVEAL` | 1.0 | 1.2 | 1.5 | 1.0 |
| **合计** | **4.5** | **5.0** | **6.7** | **3.1** |

`[补充]` 上表澄清核心 §9「4.5–7s」的口径：四段之和的下界由**常规档**给出（4.5s 整），上界由**隐藏档**（停顿延长 + 更长的揭晓）给出（6.7s）；7s 是允许上界而非常规播放值。理由：用户要求的总时长区间必须与逐段时长自洽。

`[补充]` **`void` 是时长区间的显式例外**（合计约 3.1s，低于 4.5s）：留白服务于"期待好东西"，对一个零价值结果保留 1.5s 停顿等于戏弄玩家（§5.8）。理由：4.5–7s 的下界是为**有产出的结果**设定的，`void` 不在其语义覆盖内。

```
total_play_s(tier) = shake_s[tier] + seal_break_s[tier] + tease_s
                   + (hold_s + (tier == HIDDEN ? hold_extend_hidden_s : 0)) + reveal_s[tier]
total_play_s(void) = shake_s[NORMAL] + seal_break_s[NORMAL] + tease_s + hold_void_s + reveal_s[NORMAL]
play_s(tier)       = min(total_play_s(tier), hard_cap_s)     # hard_cap_s = 15.0
```

**硬上限守护**：`elapsed_s > hard_cap_s` 时**无条件**进入 `FORCE_FINISH`——跳至 `REVEAL` 尾帧 + `INTAKE`（入库广播**必须送达**），不得静默丢弃。任何 tick 抖动、断点、资源加载失败都不得让 `play_s` 越过 15s。

### 5.2 可跳过规则

| 档位 `tier` | 可跳过 | 规则 |
|---|---|---|
| 常规 `NORMAL` | ✅ | `SHAKE` 段起任意时刻可跳过：直接进入 `REVEAL`（`skip_fade_s` 收束）。**跳过不改变结果** |
| 稀有 `RARE` | ❌ | **强制完整播放**（核心 §9；R7：每个数量级/每档稀有度都要有新的可感知内容）。跳过输入被忽略并给出弱提示 |
| 隐藏 `HIDDEN` | ❌ | 同上，且停顿延长后仍强制完整播放 |
| **空洞 `void`** | ✅ | **可跳过**（归最低档，见 §5.8）。强制完整播放一个空结果会显著加剧挫败 |

`void` 归入最低档，因此自动继承常规档的可跳过资格——**不得**把它放进 `force_complete_tiers`（见 §5.8）。

批量兑现中的可跳过规则：常规档播**压缩版**（跳过摇盒与破封，只播预告+停顿+揭晓）；稀有与隐藏档**强制完整播放并暂停队列**，播放结束后继续队列。

### 5.3 分级预告的音画分级规格

| 档位 | 颜色 | 频段 | 图标形状 | 附加 |
|---|---|---|---|---|
| **常规** | 中性色（灰白、无彩） | 低频 | 圆角方 | — |
| **稀有** | 暖色（琥珀 → 橙） | 中频 | 菱形 | 音高高于常规一档 |
| **隐藏** | **高饱和**（品红/青的对比组合） | 中高频 + **音高上扬** | 尖角星 | **屏幕边缘微光**（边缘发光缓慢呼吸） |
| **空洞 `void`** | 去饱和冷灰（**弱化形态**，饱和度低于常规） | 低频残余（音量低于常规，**不上扬**） | 圆角方（**与常规同形**，尺寸更小） | **无**边缘微光、无上扬音高 |

`[补充]` **`void` 必须复用常规档的分级语言**：它归**最低档**（§5.8）。**绝不能**给 `void` 任何稀有档的分级语言（暖色 / 中频 / 上扬音高 / 边缘微光），否则玩家会误以为开到了好东西——这是比"什么都不播"更糟的误导。

**双重编码**：档位同时用**颜色 + 图标形状 + 频段**三种通道表达，任一通道单独可辨；因此色觉差异玩家在无设置菜单的情况下也能读出档位（核心 §13.2 不做设置菜单，故不依赖可访问性选项）。

**停顿期间的信息封锁（`[补充]`）**：核心 P4 否决"透视/预知"，故 `HOLD` 段内必须屏蔽一切可提前暴露结果的通道——开箱日志、保底计数刷新、图鉴/套系进度刷新、默认层与展开层的实时联动。理由：这些通道若在揭晓前刷新，等价于把已结算结果漏给玩家。入库广播与图鉴刷新统一发生在 `INTAKE`。

`[补充]` 补充澄清：在"`regular_count` 常规 + 1 隐藏"的结构下（`regular_count` 由套系品质决定：品质 1–2 为 8，品质 3–4 为 12，核心 §4.1.1），预告"隐藏档"实际等价于指认该款；本文档判定其**不违反 P4**——P4 约束的是**结算前**的不可预知性，而演出播放的是**已结算**结果，且核心 §5.4 已保证隐藏款不可被编辑。

### 5.4 让池子编辑可感知（核心 §5）

| 编辑操作 | 演出中的可感知表现 | 边界 |
|---|---|---|
| 排除 `ban` | 该款**不出现**在摇盒段的任何候选暗示、也不出现在预告/揭晓的候选中 | 结果侧本就不会产出（`01-gacha.md`）；本系统另做**展示侧**过滤：从 `pool_snapshot` 读取被排除款并剔除 |
| 提升 `boost` | 该款"份量"更重：晃动更沉、摇盒音效不同（更低的撞击音 + 更长的尾音）；摇盒暗示中其形象的出现权重更高（**纯表现层权重**，与概率无关） | **严禁**让表现层权重影响结果；表现层的候选暗示不是概率的可视化 |

理由（核心 §5）：如果池子编辑在演出中不可感知，玩家会觉得自己的施工没有落地。**演出的职责是让玩家看到自己的池子在起作用。**

### 5.5 重复款的"体面"规格（P5）

常规款重复时**不得羞辱玩家**（禁止"再来一次""重复"等否定性文案与贬低性音效）。重复必须显示下列**变化量**，让它在视觉上仍是一次进展：

| 必须显示 | 数据来源 |
|---|---|
| 该物资数量 `+N`（重复即数量增加） | 见 `02-material.md` |
| **保底计数 `pity` 变化** | 见 `01-gacha.md` |
| **套系完成度变化**（该套系集齐进度） | 见 `10-progression.md` |
| "它还能去哪儿"提示：该物资可作装置/模块素材（P5：重复物资是原料） | 见 `04-device.md` / `05-module-pool.md` |

`[补充]` 说明：指令中提到的"碎片""升阶"在核心设计书 v0.5 中不存在，本系统**不实现**（不得发明新机制），已列入 §11 待定项。

### 5.6 兑现后立刻显示对 ρ 的影响

`REVEAL` → `INTAKE` 之后**立刻**（同一画面内，不得需要玩家手动切换面板）显示：

1. 本次产出的 **Δρ / ΔM̄**（必须取自 `EvalService`，见 `07-economy-rho.md`；**演出层不得另算**，跨系统铁律 3）；
2. **"这批原料能完成几个任务"**（需求向量 vs 持有物资向量的匹配数，口径见 `03-task.md`）；
3. 归因摘要的一句式表述（P2：每一次 ρ 的上升都必须可归因）。
4. **本盒结果为 `void` 时**：ρ 影响提示必须**展开归因中的损耗项**（`AttributionEntry{source_kind = LOSS}`，"池子损耗"）并标注"本次结果即由该项产生"，**不得**只显示一个没有来源的负数（详见 §5.8）。

`[补充]` 批量兑现时（§5.7）上述各项按**批次聚合**后再展示一次，避免逐盒刷屏；单盒模式则逐盒展示。理由：核心未规定批量形态下的展示粒度。

### 5.7 批量兑现（必要功能）

`[补充]` 批量兑现：核心 §4.6 只写了"盲盒可囤积"，未写批量。但 ρ 成型后玩家会**连续验证**自己的池子（核心 §13.3 的囤积行为判据），逐盒强制播完四段式在时间上不可接受。故补一个**排队播放器**：不新增任何结算或概率机制，只复用单盒管线，且完全遵守 §5.2 的可跳过规则。

规则：
1. 队列元素为 `Box`；**每个 `Box` 独立走一次 01 的结算**，逐盒结算、逐盒入库，**不是**一次批量结算。
2. 顺序 = 队列顺序，不重不漏；`N` 个 `Box` 恰好 `N` 次 `roll()`。
3. 档位为稀有/隐藏的盒**暂停队列**并强制完整播放；播放完毕后继续。
4. 批次结束后显示一次批次汇总（产出清单 + 聚合 Δρ + 可完成任务数）。

### 5.8 空洞 `void` 的演出规格

**背景**：`void` 是 C2 的 40% 损耗的落地形式——蒸发的概率不消失，而是成为一个**显式的零价值结果**（`README.md` §6.1、`07-economy-rho.md` §5.4、`05-module-pool.md` §5.4）。玩家能开出 `void`，因此**演出必须能播它**。

`[补充]` 本小节全部为落地细节：上游只裁决了 `void` 的数值语义，未规定它怎么播。理由：不给规格就会出现"空结果临时拼一个动画"的散装实现。

| # | 规格 | 裁决 |
|---|---|---|
| V1 | **`tier` 判定** | `void` 归**最低档**（复用常规档的时长键与分级语言，`is_void = true` 走弱化分支）。**严禁**给稀有档分级语言——那是误导 |
| V2 | **`HOLD` 停顿** | **缩短至 `hold_void_s`（0.3s）**，不是跳过整段。理由：留白的目的是放大**期待好东西**的悬念，对一个零价值结果做 1.5s 留白是对玩家的戏弄 |
| V3 | **揭晓表现** | 呈现为**"这一格是空的"**：盒子内是空的格位（注意：是空**格位**，不是"抽空了/失败了"）。档位色回落为去饱和冷灰，无边缘微光、无音高上扬（§5.3） |
| V4 | **文案与音效禁令（P5）** | 禁止"很遗憾""什么都没有""抽空了""白开""failed"等否定性文案与贬低性音效；禁止失望音效、禁止灰屏、禁止"重试"式按钮 |
| V5 | **补偿呈现（必须立刻、同一画面内）** | 立刻显示这次兑现**换到了什么**：①**保底计数 `pity` 推进**（见 `01-gacha.md`）；②**池子状态提示**（本盒产出的空位来自玩家自己的排除，例如"损耗：你排除的 3 款贡献了这一格"，措辞数据来自 `PoolState` 快照，见 `05-module-pool.md`）；③该 `Box` 已消耗的确认。**不显示**升阶/碎片（核心 v0.5 无此机制，见 §11 P09-1） |
| V6 | **可跳过** | ✅ 可跳过（归最低档，§5.2） |
| V7 | **ρ 影响归因** | ρ 影响提示（§5.6）**必须**展开 `EvalService` 归因中的 `LOSS` 项（"池子损耗"）并标注本次结果由该项产生；**不得**让玩家看到一个无法解释的数值下降（P2）。`void_prob` 只从 `EvalService` 读取，**演出层不计算**任何数值 |
| V8 | **不得反向暗示** | 演出**不得**做成"再来一次就会好"的话术（核心 P4：可优化的是分布，不是结果）；`void` 的正解是**去池子面板看损耗、决定是否拆卸模块**，提示应把玩家导回 `05-module-pool.md` 的编辑台 |

**为什么 `void` 极其重要**：它是玩家亲手施工的**可见后果**——"我把池子凿出了一个洞"（`05-module-pool.md` §5.4）。因此 `void` 的演出不是"处理坏结果"，而是**让损耗可感知**，与 §5.4（让池子编辑可感知）同源。

## 7. 流程 / 状态机

```
                        result_ready(Result, PoolState)   ← 结算已完成（01/07）
                                   │
   IDLE ───────────────────────▶ SHAKE
                                   │ elapsed ≥ shake_s
                                   ▼
                              SEAL_BREAK
                                   │ elapsed ≥ seal_break_s
                                   ▼
                                 TEASE
                                   │ elapsed ≥ tease_s（只说档位）
                                   ▼
                                 HOLD ── 无任何内容，只有暗示
                                   │ elapsed ≥ hold_s(+hold_extend)
                                   ▼
                                REVEAL
                                   │ elapsed ≥ reveal_s
                                   ▼
                                INTAKE ── 入库广播 + 图鉴/进度刷新（10）
                                   │
                                   ▼
                              RHO_IMPACT ── EvalService 输出，本层只渲染
                                   │
                                   ▼
                                 DONE

  旁路 1（跳过，仅 NORMAL，含 void）:  SHAKE|SEAL_BREAK|TEASE|HOLD ──skip──▶ REVEAL
  旁路 2（硬上限守护）:      任意 phase ──elapsed > hard_cap_s──▶ FORCE_FINISH ──▶ REVEAL(尾帧) ──▶ INTAKE
  旁路 3（中断）:            任意 phase ──abort()──▶ ABORTED ──▶ 强制补送 INTAKE
  旁路 4（void）:            SHAKE|SEAL_BREAK|TEASE ──▶ HOLD(hold_void_s = 0.3s) ──▶ REVEAL
```

| 状态 | 进入条件 | 允许的输入 | 退出 |
|---|---|---|---|
| `IDLE` | 收到 `open_requested`，`Result` 已就绪 | — | 立即进入 `SHAKE` |
| `SHAKE` | — | 点击/按住（仅改变表现）；`skip`（仅 NORMAL） | `elapsed ≥ shake_s` → `SEAL_BREAK` |
| `SEAL_BREAK` | — | `skip`（仅 NORMAL） | `elapsed ≥ seal_break_s` → `TEASE` |
| `TEASE` | — | `skip`（仅 NORMAL） | `elapsed ≥ tease_s` → `HOLD` |
| `HOLD` | — | `skip`（仅 NORMAL，含 `void`）；**不得刷新任何结果相关 UI** | `elapsed ≥ hold_s`（`void` 用 `hold_void_s`）→ `REVEAL` |
| `REVEAL` | — | 点击加速收束（NORMAL） | `elapsed ≥ reveal_s` → `INTAKE` |
| `INTAKE` | — | — | 入库广播送达 → `RHO_IMPACT` |
| `RHO_IMPACT` | — | 点击继续 | 展示完成 → `DONE` |
| `DONE` | — | — | 触发 `presentation_finished` |
| `ABORTED` | `abort()` / 场景销毁 | — | **强制补送 INTAKE**（结果不得丢失） |

**批量队列**：`BatchJob` 持有 `Array[Box]`，对每个 `Box` 创建独立 `PresentationJob` 并顺序驱动；`BatchJob` 本身不参与结算，只调度。

## 9. UI 需求

1. **演出容器**位于 `res://scenes/gacha/`（核心 §14.1），**独立可测**，可在无头模式驱动状态机。
2. **画面元素**：盒子本体（含被提升款的份量差异）／档位色与档位图标／揭晓款形象与名称／数量 `+N`／重复款进展条（§5.5）／ρ 影响提示条（§5.6）／**`void` 的空格位表现与补偿清单**（§5.8 V3/V5）。
3. **留白纪律**：`HOLD` 段画面**不得**出现任何款、名称、数量、概率、进度数字；只允许档位色呼吸、频段余韵与隐藏档边缘微光。
4. **不泄露**：演出期间 `08-ui-panels.md` 的默认层/展开层/图鉴**不得**提前更新（§5.3 信息封锁）。
5. **批量兑现 UI**：队列进度（第 i / N 盒）、当前盒的档位、批次汇总页；稀有/隐藏盒暂停队列时给出明确提示。
6. **跳过按钮**：仅在允许跳过的档位下可见/可点；被忽略的跳过输入给出弱提示而非静默无视。
7. **音画分级**同时使用颜色 + 形状 + 频段三通道（§5.3）。
8. 占位资源即可（核心 §13.2 不做成品美术与音效）。
9. **`void` 的文案白名单**：只允许中性词（"这一格是空的""空格位""池子损耗"）；禁止 §5.8 V4 列出的否定性文案与失望音效——这是 P5 在 UI 层的落点。

## 10. 测试点与验收标准

| # | 测试 | 断言 |
|---|---|---|
| **T1** | **"15 秒硬上限"守护测试** ★ | 构造 1 帧耗时 30s 的驱动器、逐帧卡顿、`reveal_s` 被改成 999、资源加载阻塞四种注入，全部断言 `elapsed_s ≤ 15.0` 且 `INTAKE` **必达**（入库广播送达一次、恰好一次） |
| **T2** | **跳过路径 vs 完整路径结果一致性** ★ | 同一 `seed` + 同一 `pool_snapshot`：走完整路径与走跳过路径，`Result`、背包、`pity`、图鉴进度**完全一致**；且两条路径的 `roll()` 调用次数均恰好为 1 |
| **T3** | **批量兑现正确性** ★ | `N` 个 `Box` 恰好 `N` 次 `roll()`；入库总量 = 各盒产出之和；顺序 = 队列顺序（不重不漏）；稀有/隐藏盒暂停队列且完整播放；批次汇总的 Δρ = 各盒 Δρ 聚合（与 `EvalService` 一致） |
| **T4** | **演出层不参与结算** ★ | 静态检查：`scenes/gacha/` 内无 `randi` / `RandomNumberGenerator` / `roll(` / `PoolService`；运行时：演出前后 `pool_state` 哈希相同、`pity_counter` 仅由 01 变化 |
| T5 | 被排除款不出现 | 对每款依次 `ban` 后兑现 100 次，摇盒暗示与揭晓候选中该款出现次数为 0 |
| T6 | 被提升款可感知 | A/B 快照与音频清单元数据齐全：份量参数、摇盒音效 id 在被提升前后不同 |
| T7 | 重复款不羞辱 | 重复结果下，§5.5 四项进展信息**全部**存在；文案与音效列表中无否定性表述 |
| T8 | ρ 影响提示口径 | 提示中的 Δρ/ΔM̄ 与 `EvalService` 输出逐位相同；任务匹配数与 `03-task.md` 口径一致 |
| T9 | `HOLD` 段信息封锁 | `HOLD` 期间对日志/图鉴/保底计数/默认层的读取均返回演出前状态 |
| T10 | 中断安全 | `abort()` 后入库广播仍送达且仅一次；`Result` 不丢失、不重复 |
| T11 | **五条红线（C1/C2/C3/C4/C6）不被演出破坏** | 回归断言 C1/C2/C3/C4/C6（README §3.5）在演出前后均成立，**同一套系内** `socket_count` 恒定（跨套系取值不同是合法的，核心 §4.1.1） |
| T12 | 时长合规 | 常规档合计 ∈ [4.5, 7]、稀有/隐藏档合计 ∈ [4.5, 7]（不超过推荐上界 7s）；**`void` 合计 ≈ 3.1s，豁免下界**（§5.1） |
| **T13** | **切片失败信号** ★ | 若测试者在演出结束后**说不出刚才开出了什么**，或**完全没注意到自己排除的款消失了**，或**对重复结果表达"白开了"**，则演出失败——分别对应：留白过长/揭晓过短、§5.4 可感知性不足、§5.5 体面规格未落地 |
| **T14** | **`void` 演出规格** ★ | ①`tier` 判定为**最低档**且 `is_void == true`：断言其分级资源 id **不在**稀有/隐藏档集合内（不得借用暖色/上扬音高/边缘微光）；②`HOLD` 时长 == `hold_void_s`（缩短而非删除，段仍存在）；③揭晓文案与音效**不含** §5.8 V4 禁令词；④补偿清单三项（`pity` 推进、池子损耗来源提示、盒已消耗）**全部**出现；⑤ρ 影响提示**展开** `LOSS` 归因项，且数值与 `EvalService` 逐位相同；⑥`void` 可跳过 |

**失败信号（对照核心 §13.4）**：测试者抱怨"每次都放一样的动画"（分级语言未生效）；测试者跳过隐藏款（可跳过规则失效）；测试者问"这批物资能顶几个任务"却要自己去任务面板查（§5.6 缝合失败）。

**`void` 专属失败信号** ★：若测试者说**"白开了"**、且**并非指向重复款而是指向 `void`**（重复款的"白开了"见 T13 / §5.5），说明 `void` 的**演出与补偿呈现失败**——即 §5.8 V3/V5 未落地（空被播成了失败）；同时若测试者说"这游戏在骗我，概率没算对"，说明 §5.8 V7 的归因未展开（一个无法解释的数值下降）。两者都必须先修演出，**不得**靠调低 `recover_rate` 掩盖。
