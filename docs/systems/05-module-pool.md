# 05 · 模块与池子编辑系统 ★

- 上游：`../core-design.md` v0.6 ／ `README.md`
- 依赖系统：`02-material.md`（模块素材）、`07-economy-rho.md`（求值路径）
- 被依赖：`01-gacha.md`（抽取消费池子状态）、`08-ui-panels.md`（池子面板）、`09-presentation.md`（演出过滤）

> **本系统是全作风险最高的系统。**
> 它同时承担三件事：玩家能动性的主载体、"盲盒期望可被施工"的实现、以及最大的平衡风险（R2）与最大的技术风险（R4）。
> 改动本系统前请通读 §5 与 §10.1。

---

## 1. 这个系统负责什么

1. **`PoolState` 的唯一写入方**——池子状态的任何变更都只能经由 `PoolService`
2. **排除（`ban`）**：令指定款概率归零，不再产出
3. **提升（`boost`）**：提高指定款概率，增量从其他常规款按比例扣除
4. **损耗（`loss`）**：排除释放的概率中 40% 不可回收，落为 `void`（详见 §5.4）
5. **隐藏款免疫的执行**：保证隐藏款概率恒为 2%（规则由 `01-gacha.md` 声明，执行在此）
6. **镶嵌位管理**：数量由**套系品质**决定（品质1–4 → 2/3/4/5），**同一套系内恒定、运行时不可变**（C4 / P7）
7. **模块的装配、替换与拆卸**（拆卸返还 50%）
8. **回收（`recover`）**：挽回部分 `void` 质量——**第二切片，本版仅定义接口**
9. **排除款数上限（C6）**：排除款数 ≤ 常规款数 − 3，**任何池子至少保留 3 款可产出**

---

## 2. 不负责什么（边界）

| 不负责 | 归属 |
|---|---|
| 概率求值（把 `PoolState` 变成具体概率） | `07-economy-rho.md` |
| 抽取判定 `roll()` | `01-gacha.md` |
| 隐藏款概率**数值**的声明（2%） | `01-gacha.md` |
| EV / ρ / `headline` 的计算 | `07-economy-rho.md` |
| 池子面板的渲染 | `08-ui-panels.md` |
| 演出中被排除款的过滤**呈现** | `09-presentation.md` |

> **关键边界**：本系统**只写状态，不算数字**。任何"想知道当前概率是多少"的需求，一律调 `EvalService`。

## 3. 核心概念与术语

| 术语 | 代码名 | 说明 |
|---|---|---|
| 池子状态 | `PoolState` | 基础权重 + 全部编辑结果的**唯一权威表示** |
| 修订号 | `revision` | 每次写入 +1；缓存与失效的唯一依据 |
| 模块 | `Module` | 一条作用在开盒端的编辑规则 |
| 镶嵌 | `socket` | 把模块放入镶嵌位 |
| 镶嵌位 | `socket_slot` | **数量由套系品质决定**（品质1–4 → 2/3/4/5）；**同一套系内恒定、运行时不可变**（C4） |
| 排除 | `ban` | 某款概率归零 |
| 提升 | `boost` | 某款概率 ×N |
| 释放质量 | `freed_mass` | 排除某款后从其基础权重中释放出的质量 |
| 回收率 | `recover_rate` | 释放质量中可重新分配的比例，**0.60** |
| 空洞 | `void` | 不可回收的那 40%，落为零价值结果（§5.4） |
| 重分配模式 | `redistribute_mode` | `AUTO`（按基础权重）／ `TARGETED`（指定目标款） |
| 替换 | `replace` | 镶嵌位满时的唯一操作——**没有"再装一个"** |
| 物资品质 | `quality` | 1–5 序数，物资的等级维度（见 `02-material.md`） |
| 套系品质 | `series_quality` | 该套系的规模等级（1–4），决定其**常规款数与镶嵌位数**（核心设计书 §4.1.1） |

> **术语纪律（v0.6 新增）**：本作的"品质"有**两个**含义——**物资品质 `quality`**（1–5，见 `02-material.md`）与**套系品质 `series_quality`**（核心设计书 §4.1.1）。
> 凡文中出现"品质"二字**必须可分辨是哪一个**：谈镶嵌位与款数时指**套系品质**，谈物资价值与任务需求时指**物资品质**。
> （`ModuleDef.quality` 是**模块品质梯度**，属第三条独立轴，见 D13，不得与前两者混用。）

## 4. 数据结构

```gdscript
# res://data/defs/module_def.gd
class_name ModuleDef
extends Resource

enum OpType { BAN, BOOST, RECOVER }

@export var id: StringName
@export var display_name: String
@export var quality: int                       # 模块品质梯度（核心文档 D13）
@export var op_type: OpType
@export var targets: Array[StringName]         # 多目标；隐藏款出现在此处即为非法配置
@export var magnitude: float = 1.0             # BOOST 的倍数；BAN/RECOVER 忽略
@export var redistribute_mode: int = 0         # 0 = AUTO, 1 = TARGETED
@export var redistribute_target: StringName    # TARGETED 时的目标款
@export var material_cost: Dictionary          # 制造消耗：MaterialDef.id -> 数量
@export var exclusive_tags: Array[StringName]  # 互斥标记
```

```gdscript
# res://autoload/pool_service.gd
class_name PoolService

class PoolState:
    var series_id: StringName
    var revision: int = 0
    var socketed: Array[StringName] = []       # 长度恒 == socket_count（C4）
    var socket_count: int = 3                  # ★ 该套系的常量，从 SeriesDef.socket_count 拷贝，运行时永不改变
    var regular_count: int = 8                 # ★ 该套系的常规款数，从 SeriesDef 拷贝；ban_limit 由其派生（C6）
    var void_mass: float = 0.0                 # 当前不可回收质量
```

> `[补充]` `regular_count` 与由它派生的 `ban_limit` 是 C6 的落地字段：核心设计书只规定"至少保留 3 款可产出"，
> 把上限落成 `PoolState` 字段可让 V5 校验与 §10.1 T4b 断言有唯一数据源，**避免各处按 8 款硬编码 5/8**（品质 3/4 的池子是 12 款）。

### 4.1 唯一写入接口

```gdscript
## 镶嵌。槽位满时返回错误——不做隐式替换，强制玩家显式选择换下谁。
static func socket(state: GameState, module_id: StringName, slot: int) -> Result

## 拆卸。返还 50% 素材。
static func unsocket(state: GameState, slot: int) -> Result

## 试算通道：算出"若这样镶嵌"的候选 PoolState，但**不写入任何状态**、不推进 revision。
## 供 08 的实时预览与沙盒使用（P6）。返回的是副本，调用方不得回写。
static func preview_socket(state: GameState, slot: int, module_id: StringName) -> PoolState

## 内部：重建 PoolState（不对外暴露）
static func _rebuild(state: GameState) -> void
```

> **`preview_socket()` 是只读的**：它走与 `_rebuild()` 完全相同的计算路径（避免两套实现），但结果不落盘、不推进 `revision`、不触发缓存失效。09 的演出层不得调用它。

> **`PoolState` 没有任何公开的 setter。** 所有字段只能由 `PoolService._rebuild()` 写入。
> 这是本作头号 bug 源（R4）的唯一防线。

## 5. 规则与公式

### 5.1 重建流程（与 07 的 `evaluate_pool()` 步骤严格对应）

```
_rebuild(state):
  1. revision += 1
  2. 校验全部已镶嵌模块的合法性（§5.5）
  3. freed_mass = Σ 被排除款的基础权重
  4. void_mass   = freed_mass × (1 - recover_rate)      # 40%
  5. 可回收部分按 redistribute_mode 分配：
       AUTO     → 按基础权重分配给其余未被排除的常规款
       TARGETED → 全部分配给 redistribute_target
  6. 提升：w[target] *= magnitude
  7. 隐藏款权重全程不动（C3）
  8. 断言：socketed.size() == socket_count（C4）
  9. 断言：可产出常规款数 ≥ 3（C6）
```

> `[补充]` 步骤顺序被固定，与 `07-economy-rho.md` §5.1 一致。顺序影响结果，固定顺序是求值可复现与归因可对账的前提。

### 5.2 硬约束（C1 / C4 / C6）

| # | 约束 | 理由 |
|---|---|---|
| **C1** | **零和**：常规款概率之和 ≤ 98%（差额为 `void_prob`） | 提升必须从别处抢，取舍才真实 |
| **C4** ★ | **镶嵌位数由套系品质决定；在同一套系内恒定、运行时不可变** | 功率门控（P7）：**同一套系内没有任何扩容路径** |
| **C6** ★ | **排除款数上限 = 常规款数 − 3**（任何池子至少保留 3 款可产出） | **防收敛下限** |

常规款概率质量总量恒定。**提升某款必须从其他常规款按比例扣除**——不存在"凭空增加概率"的模块。

代价因此是真实的：**你给某款加的概率，是从所有别款身上按比例抠出来的**，包括你正需要的那几款。

**C4 管"位子有多少"，C6 管"能排除多少"**：位子再多（最高品质套系也只有 5 个），池子也必须留下至少 3 款可产出——因此**永远收敛不到单一款**。

### 5.3 `void` 即自限机制（v0.6 升格）

```
freed_mass = Σ base_weight[banned]
void_mass  = freed_mass × 0.4
```

v0.5 靠"C4 固定常数"抑制 R2（池子编辑过强）。**v0.6 位子随套系品质变多，因此抑制改由 C2 的 40% 损耗承担**：

| 玩家若…… | 会发生什么 |
|---|---|
| 排除 1 款 | 该款释放质量的 **40% 永久变成 `void`** |
| 排除到只剩 3 款 | `void_mass` 已累积到可观比例，**`m_bar` 显著塌陷**，ρ 下降 |
| 想把池子收敛到必出某款 | 做不到（C6 保底 3 款），且代价是循环效率大幅下滑 |

**排除越多 → `void_mass` 累积越多 → `m_bar` 塌得越狠 → ρ 越低。过度排除是自我惩罚的。**

这条机制的三条关键性质：

- **自限，不是封顶**：`void` 不阻止玩家排除，只让"排得越狠、循环越差"成为机制事实；收官阶段的玩法因此是"权衡逼近到什么程度为止"（核心设计书 §5.5）。
- **随品质自动扩展**：高品质套系给更多位子，但每一次排除的代价同样真实——**位子多 ≠ 收敛容易**，不需要为每档品质另设上限。
- **不新增参数**：抑制 R2 靠的是 C2 这条既有机制，而不是一个需要单独调平的常数。

损耗的可见性（`void` 的基本定义见 §5.4，本条只升级其地位）：
- **可见**：直方图多一根 `void` 柱；
- **可计价**：`void` 的 `v = 0`，直接压低 `m_bar`（P2 可归因）；
- **不可被归一化抹掉**：归一化会让损耗完全失效，D6 这个主旋钮就白设了。

### 5.4 `void` 的实现方式 ⚠️

**核心设计书存在一处内部矛盾**（C1 说"Σp 恒为 98%"，C2 说"40% 蒸发"），本系统采用如下解法：

> **蒸发的概率不消失，而是落为一个显式的零价值结果 `void`。**

```
Σ probs(常规款) + void_prob + 0.02(隐藏) == 1.0
```

| 好处 | 说明 |
|---|---|
| 损耗**可见** | 直方图上多出一根柱子，玩家亲眼看到"我把池子凿出了一个洞" |
| 损耗**可计价** | `void` 的 `v = 0`，直接压低 `m_bar`，符合 P2 可归因 |
| 不需要归一化抹掉损耗 | 归一化会让损耗**完全失效**，D6 这个主旋钮就白设了 |

**代价**：C1 措辞需从"恒为 98%"改为"**≤ 98%，差额为 `void_prob`**"。
⚠️ **已同步记入 `07-economy-rho.md` §11 与 `README.md` 待定项汇总，需回改核心设计书。**

### 5.5 合法性与冲突规则

| # | 规则 | 违反时 |
|---|---|---|
| V1 | `targets` 不得包含隐藏款 | 配置期报错，拒绝加载 |
| V2 | 同一款不得同时被排除与提升 | 拒绝镶嵌，UI 明确提示冲突源 |
| V3 | `socketed.size() <= socket_count` | 拒绝，要求先拆卸 |
| V4 | `boost` 倍数不得超过 `boost_cap`（×3） | 配置期钳制并警告 |
| V5 | 常规款被排除总数 ≤ `ban_limit`（**派生自 C6**：`ban_limit = regular_count − 3`；品质2 即 8 − 3 = 5） | 拒绝，保证至少 3 款可产出 |
| V6 | 互斥标记（`exclusive_tags`）冲突的模块不得共存 | 拒绝镶嵌 |

> **所有非法操作必须"响亮地拒绝"，不做静默钳制。** 静默处理会让玩家以为自己成功了，从而对所有数字失去信任（P1）。

### 5.6 替换：本作最锋利的一层决策

镶嵌位在**同一套系内恒定、不可扩容**，所以**不存在"再装一个模块"这个选项**——想要更多位子，只能去**更高品质的套系**（那是内容，不是扩容）。

玩家每一次镶嵌都在回答：**我要把谁换下来？**

配套要求：
- 镶嵌界面**必须显示将被换下的模块**及其效果损失（核心文档 R10）；
- 拆卸返还 50%，使"换错"有代价但可承受；
- **禁止提供任何增加镶嵌位的接口**（P7 的代码层体现，见 §10.1 T4）。

## 6. 参数表

| 参数 | 推荐值 | 说明 |
|---|---|---|
| `socket_count` | **随套系品质取值（品质1–4 → 2 / 3 / 4 / 5）** | ★ 核心文档 D3：**同一套系内恒定、运行时不可变**（C4）🔧🔧 |
| `recover_rate` | **0.60** | 即损耗 40%，核心文档 D6 🔧🔧 |
| `boost_cap` | ×3 | 单款提升倍数上限（D7）🔧 |
| `ban_limit` | **`regular_count − 3`** | **派生自 C6，不是独立旋钮**；品质2 = 8 款 → 上限 5 |
| 位子/池子比例 | **25%–40%** | 核心设计书 §4.1.1 硬要求：位子必须与池子同步长，否则高品位套系会被收敛（R2 从后门回来）🔧 |
| 拆卸返还率 | 50% | D8 🔧 |
| 重新分配默认模式 | `AUTO` | 按基础权重分配 |
| 切片模块数 | 6–8 个 | 覆盖 BAN 与 BOOST，含 1 组多目标排除 |

🔧 = 调参旋钮 ／ 🔧🔧 = 主旋钮

**`socket_count` 与 `recover_rate` 是本作最重要的两个数字。** 它们共同决定：
- ρ 的上限（§2.4 内容释放的起点）
- R2（池子编辑过强）的强度
- §5.6 替换决策的锋利度

**两者都必须在切片阶段用真实手感测出来，不得拍脑袋写进配置。**
（v0.6：切片取**品质 2 = 3 位**，可直接沿用 v0.5 的手感数据；**品质→位子曲线推迟到第 2 套系前**，见 §11 M1。）

## 7. 流程

```
玩家选择模块 + 槽位
      │
      ▼
┌──────────────────┐
│ 合法性校验 §5.5   │──非法──▶ 响亮拒绝 + 指明冲突源
└────────┬─────────┘
         │合法
         ▼
  槽位是否已占用？
    │           │
   是          否
    │           │
    ▼           ▼
 显示"将被换下"  ──确认──▶ PoolService.socket()
 并要求显式确认                 │
                                ▼
                        PoolService._rebuild()
                          revision += 1
                                │
                                ▼
                    EvalService 缓存失效
                                │
                                ▼
        08 六面板刷新（**默认层两数字立即变化**）
```

### 7.1 状态机（池子生命周期）

```
[基础池] ──首次镶嵌──▶ [已编辑池] ──继续镶嵌──▶ [已编辑池]
                            │                        │
                            └────全部拆卸────────────┘
                                     ▼
                              [基础池]（void_mass 归零）
```

**拆卸必须完全恢复到基础池**（`void_mass = 0`），否则池子会被不可逆地污染，违背 §5.6 的可逆承诺。

> **位子数是该套系的属性**：`socket_count` 与 `regular_count` 随套系走，**切换套系会改变位子数与池子规模**；在同一套系内始终不变（C4）。替换路径本身不变——满位时仍然只能换下谁。

## 9. UI 需求

本系统**提供数据与操作，不实现面板**（面板归 `08-ui-panels.md`），但下列为硬要求：

| 要求 | 理由 |
|---|---|
| **镶嵌前实时预览**：显示编辑后分布、`void_prob` 变化、默认层两数字变化 | P6 + 核心文档 §8.2。**没有预览的池子编辑是不可用的** |
| **直方图必须同时画编辑前后两条分布** | 核心文档 §7：玩家要"亲眼看到自己把分布捏成了另一个形状" |
| **`void` 必须有独立可视元素**（一根柱子） | §5.4：损耗必须可见，否则玩家不理解 40% 意味着什么 |
| **镶嵌位占用必须常驻可见**（`socket_count` 个格子，随套系品质为 2–5） | §5.6：位次稀缺是本系统全部重量所在 |
| **替换时必须显示被换下的模块及其损失** | R10：否则玩家会因害怕误操作而不敢决策 |
| **非法操作必须指出冲突源**（"与槽位 2 的模块冲突"） | P1：静默拒绝等于欺骗 |

## 10. 测试点与验收标准

### 10.1 红线测试（必须自动化，进 CI，与 07 §10.1 共用）

| # | 测试 | 判据 |
|---|---|---|
| **T1** | **C3 隐藏款免疫** | 穷举所有模块组合，`probs[hidden] == 0.02`（容差 1e-6） |
| **T2** | **C1 概率守恒** | `Σ probs(常规) + void_prob ≤ 0.98`，且总和 + 0.02 == 1.0 |
| **T3** | **C2 损耗率** | `void_mass` 增量 == `0.4 × freed_mass`（容差 1e-9） |
| **T4** | **C4 镶嵌位不变量** | `pool_state.socket_count` **恒等于该套系 `SeriesDef.socket_count`**——**对同一套系恒定，跨套系随品质取值**（2/3/4/5）；**并对 `PoolState` 做 getter/setter 审计，确认不存在任何设置它的接口** |
| **T4b** ★ | **C6 收敛下限** | 任意合法 `PoolState` 下**可产出常规款数 ≥ 3**（穷举全部合法排除组合） |
| **T5** | **单写入方** | 除 `PoolService` 外，全仓库无任何位置写入 `PoolState`（静态检查 + 运行时断言） |
| **T6** | **拆卸完全可逆** | 镶嵌 N 个模块后全部拆卸，`PoolState` 回到基础态且 `void_mass == 0` |

### 10.3 切片验收信号

- ✅ 测试者主动讨论"这个要不要留"
- ✅ 测试者在被排除款与缺口款之间做出**有意识的取舍**
- ✅ 测试者表现出"等我把池子编好再开这批盒子"的囤积行为
- ❌ **测试者在 10 分钟内就把池子编到接近必出** → C4 / C6 / C2 未生效，检查代码而非调参
- ❌ **测试者抱怨"想再装一个但位子不够"** → ⚠️ **这是设计意图，不是 bug**。但若玩家感到的是**挫败**而非**取舍**，应调低拆卸成本（50% → 更高返还），**而不是增加镶嵌位**
- ❌ **测试者完全忽略池子面板** → R3 成立，"燃料/引擎"被淹没，需要简化而非放弃本系统
- ❌ **测试者不理解 `void`** → §5.4 的可视化失败，直方图必须重做
- ❌ **测试者抱怨"高品质盒子位子多了但没什么用"** → **位子/池子比例失衡**（位子涨得比池子快），核对核心设计书 §4.1.1 的 25%–40% 区间，修正比例而**不是**加排除强度

## 11. 待定项

| # | 待定项 | 推荐 | 影响 |
|---|---|---|---|
| **M1** | **`socket_count`（D3）** | **切片取品质 2 = 3 位；品质曲线推迟** | **已不再是开工阻塞项**：切片单套系只需一个值（核心 §13.1 / D3）；曲线待第 2 套系前用对比数据定 |

| **M7** | 是否为"排除"提供撤销窗口（如 30 秒内免费撤销） | 不做，靠 50% 拆卸返还 | 关系 R10 |
