# 《Open Box》核心设计书

- 版本：**v0.3（以核心循环为宪法重写）**
- 历史版本：`docs/archive/core-design-v0.1.md`、`core-design-v0.2.md`
- 引擎：Godot 4.5（Forward+）
- 已定前提：**纯单人** / **纯游戏内货币，无数值付费** / 社交**留接口不实现**

> **v0.3 说明**
> v0.2 把盲盒的期望做成玩家的工作台，但**漏掉了"使用物资"这一步**——物资被设计成永久装配的算子，而真实循环里物资是**被消耗掉**去完成任务的。
> v0.3 以核心循环为宪法重写："做大数学期望"不再指开盒池子的期望，而是**整条闭环的期望**。

## 1. 核心循环（宪法）

```
   ┌──────────────────────────────────────────────────────┐
   │                                                      │
   ▼                                                      │
开盲盒 ──▶ 获取物资 ──▶ 使用物资 ──▶ 完成任务 ──▶ 获取盲盒 ─┘
   ▲                                                      │
   └──────────────────────────────────────────────────────┘
                          │
                          ▼
                    最终完成全收集
```

**这条循环是设计宪法。** 任何新系统必须先回答"它服务循环的哪一步"，否则不做。

### 1.1 循环各步的情绪与职责

| 步骤 | 情绪 | 玩家在做什么 | 系统职责 |
|---|---|---|---|
| **开盲盒** | 悬念、揭示 | 兑现未知 | 演出、概率 |
| **获取物资** | 收获、入库 | 清点战利品 | 物资分级、图鉴 |
| **使用物资** | **决策** ★ | **唯一的能动性所在** | **任务分配、转化、装配** |
| **完成任务** | 目标达成、验证 | 推进度 | 任务需求与奖励 |
| **获取盲盒** | 期待积攒 | 囤积下一次悬念 | 闭环闭合 |
| **全收集** | 终局成就感 | — | 长线终端目标 |

### 1.2 最重要的一条洞察

**整条循环上，玩家能动性只集中在"使用物资"这一步。**

- 开盲盒是随机的（无决策）
- 获取物资是被动的（无决策）
- 完成任务是执行（无决策）
- 只有**使用物资**有选择。

**推论：本作的全部玩法深度必须堆在"使用物资"上。** 其余各步的职责是**制造压力**（让这一步的选择有重量），而不是抢戏。

这条推论直接否决了一大类设计：任何让"开盲盒"本身变成策略博弈的方案（例如 v0.2 的算子装配工作台），都是在给无决策的步骤加深度，而唯一有决策的步骤反而空着。

## 2. 核心数值：闭环收益率 ρ

### 2.1 定义

把循环写成转换链：

```
开 1 个盲盒      → 平均产出 M̄ 单位物资
完成 1 个任务    → 消耗 D̄ 单位物资，奖励 B 个盲盒

闭环收益率  ρ = ( M̄ / D̄ ) × B
```

| ρ | 含义 | 玩家体感 |
|---|---|---|
| ρ < 1 | 循环衰减 | 我在亏，需要外部补给 |
| ρ = 1 | 自持 | 勉强转得动 |
| ρ > 1 | 循环增殖 | **滚起来了** |

### 2.2 ρ 就是"盲盒的数学期望"

用户给定的方向是"整个游戏的内容是做大盲盒的数学期望"。在这条循环里，它的确切含义是：

> **每投入 1 个盲盒，最终平均能回收多少个盲盒。**

这是整条链的期望，不是开盒单点的期望。**做大 ρ 就是这个游戏的全部玩法。**

### 2.3 ρ 的两因子分解（归因面板的内容）

```
ρ  =  M̄ / D̄   ×   B
     └──┬──┘     └┬┘
     开盒端      转化端
   能开出多少物资  物资换盲盒的效率
```

玩家有两个清晰的施工方向，且**两者张力不同**：

| 端 | 手段 | 特征 |
|---|---|---|
| **开盒端**（M̄） | 提高单盒产出量、稀有度、品种覆盖 | 高方差、靠运气、见效快 |
| **转化端**（D̄ / B） | 降低任务消耗、提高任务奖励、减少转化损耗 | 低方差、靠工程、见效慢但稳 |

**这两端的存在，就是本作防止"最优解收敛"的第一道防线**（见 §6）。而且归因面板要做的事变得非常简单明确：**把 ρ 拆成这两项，并逐项列出贡献者。**

## 3. 核心决策：燃料还是引擎

"使用物资"要成为有重量的决策点，物资必须面对一个**永久性的取舍**：

> **同一份物资，用掉它完成任务（燃料），还是留下它作为长期装置（引擎）？**

- **燃料**：物资被消耗，推进任务，换来盲盒，进入下一轮循环。
- **引擎**：物资被装配为装置，**永久**提升 M̄ 或降低 D̄，但它再也不能用来完成任务。

### 3.1 为什么这是本作的中心机制

1. **它是循环上唯一有真实代价的选择。** 用掉就没了，这个代价是永久的、不可撤销的。
2. **它复刻了实体盲盒最真实的心理——舍不得拆。** 摆在架上的盒子比拆开的盒子更让人惦记。
3. **它天然制造了收集与推进的根本矛盾。** 想全收集就得留着；留在架上的物资不能拿去完成任务；不完成任务就没有新盲盒。**这个矛盾不需要额外系统，它是循环自带的。**
4. **它让"全收集"和"做大 ρ"两条追求互相拉扯**，而不是各走各的。

### 3.2 设计约束

- 装配**必须可逆但昂贵**（允许拆卸，代价是损失已投入的一部分），否则玩家会因为害怕误操作而不敢决策。
- 装配信息（装了什么、放弃了什么）必须在**每次面临选择时可见**，否则取舍感会消失。
- 装置数量要有**硬上限**（槽位），否则后期所有物资都会被留下，"燃料/引擎"的取舍自然消失。

## 4. 系统骨架

### 4.1 盲盒（Box）

- 每个套系**独立概率池**：8 常规 + 1 隐藏。
- 隐藏款基础概率 2%；常规款均等；未拥有款权重 ×1.5；连续 8 次未出新款则硬保底。
- **概率与保底公示界面属于核心玩法范围，不是可选项**（P1）。
- 盲盒**可以囤积**：何时兑现是决策（见 §4.6）。

### 4.2 物资（Material）

从盲盒中开出的东西，是本作唯一的实体资源。

物资的三个属性决定了它的全部用途：

| 属性 | 作用 |
|---|---|
| **类别** | 决定能满足哪类任务需求 |
| **品质** | 决定任务贡献度、作为装置时的强度 |
| **数量** | 可堆叠；重复款即数量增加 |

物资的两个出口（互斥）：

```
物资 ──┬──▶ 交付给任务（被消耗，推进循环）
       └──▶ 装配为装置（永久，提升 ρ）
```

### 4.3 任务（Task）

- 任务有**需求**（某类别/某品质的物资若干）与**奖励**（盲盒、券、装置槽位）。
- 任务分两类，职责不同：
  - **常规任务**：循环的引擎，可重复完成，是盲盒回流的主要来源。
  - **里程碑任务**：一次性，解锁新套系、新物资类别、新装置槽位。
- **任务需求会随进度变宽**（后期任务要求更分散、更稀有的物资类别）。
  这是自然摩擦：ρ 会因需求分散而下滑，玩家必须持续提升 ρ 才能维持进度。**用需求结构提供长期压力，而不是靠调低概率**（见 R5）。

### 4.4 装置（Device）

- 装置是物资的第二形态，永久生效，占用槽位。
- 装置的作用点**只在两端**，与 §2.3 对应：

| 作用端 | 装置示例 |
|---|---|
| **开盒端（M̄）** | 「每盒产出 +1 件」「品质下限 +1」「该套系稀有物资权重 ×2」 |
| **转化端（D̄/B）** | 「任务物资消耗 −10%」「转化损耗 −15%」「完成任务额外 +1 盒」 |

- **设计目标：任何两个跨端装置的组合，都应产生一个玩家能自己发现、但不容易预先算到的跃升。** 这是构筑深度的来源（同类线性叠加，跨类相乘）。

### 4.5 转化（Conversion）

- 把过剩类别的物资转成稀缺类别的物资，**有损耗**。
- 损耗率是 ρ 的关键参数，也是"转化端"装置的主要作用对象。
- 转化的存在是为了解决盲盒的根本矛盾：**随机产出 vs 确定性需求**。没有转化，玩家会被"开出不需要的物资"卡死。

### 4.6 兑现时机（Timing）

盲盒可囤积，于是产生一个纯涌现的决策：

> 「现在开」还是「等我 ρ 再高一点再开」？

由此自然形成一种资源配置玩法：**用低价值套系刷装置素材，把高价值套系的盒子攒到结构成型后再开。**

不需要任何新系统，只需保留"盒子可囤积"这一条规则。

## 5. 设计支柱

支柱必须有**否决权**。

### P1 · 一切概率与期望可见可算
概率、权重、保底计数、M̄、D̄、B、ρ——全部对玩家公开。
**否决：** 任何暗改概率、动态调权、"根据玩家进度悄悄调爆率"的设计。概率是玩家的施工材料，材料必须是真的。

### P2 · 每一次 ρ 的上升都必须可归因
必须能逐项读到「装置 A：+0.42（开盒端）／ 装置 B：+0.11（转化端）／ 任务结构变化：−0.05」。
**否决：** 任何只显示总数的数值呈现方式。

### P3 · 深度只堆在"使用物资"上
**否决：** 任何在开盒、获取、完成这几步上增加策略博弈、而"使用物资"仍无选择的方案（§1.2）。

### P4 · 单次悬念不可消除
可优化的是分布，不是结果。
**否决：** 透视、预知、下次必出某款（保底是分布层规则，不是结果层预测，二者不可混同）。

### P5 · 重复与过剩永远不是空手
重复物资是装置与转化的原料。
**否决：** 任何会产生"我什么都没得到"的开箱结果。

### P6 · 玩家的时间用于决策，不是用于算数
提供试算 / 沙盒，试错成本趋近于零。
**否决：** 任何要求玩家手算或外部查表才能决策的机制。

## 6. 方差：第二条轴

**这是防止"最优解收敛"的第二道防线。**

ρ 不是唯一目标。方差 σ 是**独立的第二条轴**，且必须**显式显示**（数字 + 分布直方图）。

| 构筑方向 | 玩家类型 | 手段 |
|---|---|---|
| **ρ 最大** | 长期主义者 | 堆开盒端，容忍高方差 |
| **σ 最小** | 稳健派 | 堆转化端、抬下限、堆保底 |
| **定向获取** | 收集派 | 让产出偏向缺口物资，牺牲 ρ |

三者**互相冲突**（堆保底牺牲上限，定向注入摊薄 ρ），因此**不存在唯一最优解**。

规格要求：
1. 方差是**一等公民数值**，不是隐藏属性。
2. 分布直方图是**核心 UI**，要能实时反映装置装配后的形状变化。

**第三道防线是场景约束随机化**：每次兑现或每批任务附带 1 条环境约束（禁用某端装置 / 加成某类物资），使当前最优配置随场景漂移。

## 7. 可视化是玩法本体

**美术与 UI 预算的重心在"ρ 与归因可视化"，不在开箱特效。** 理由同 §1.2：深度集中在"使用物资"，可视化必须服务这一步。

### 四个必备面板

| 面板 | 内容 | 为什么是玩法 |
|---|---|---|
| **循环面板** | ρ、M̄、D̄、B 四项，以及循环箭头上的实时流量 | 没有它就没有"做大 ρ"这个动作 |
| **归因面板** | ρ 的两因子分解、逐装置贡献、装配前后对比 | 决策的唯一依据（P2） |
| **架上面板** | 已囤积未开盒、已装配装置、槽位占用 | "燃料还是引擎"的决策现场 |
| **任务面板** | 需求向量 vs 手上物资向量、缺口高亮 | "使用物资"的工作台 |

### 试算 / 沙盒（P6）

装配前可**预览 ρ 变化**，试错成本为零。**没有试算功能的 ρ 游戏会变成电子表格苦力。**

## 8. 开箱演出

演出规格沿用 v0.1 的四段式（摇盒 → 破封 → 分级预告 → 揭晓入库，总时长 4.5–7s，上限 15s，可跳过），但定位是**循环的第一步**，不是核心：

| | v0.1 | v0.3 |
|---|---|---|
| 演出是什么 | 唯一情绪峰值 | **循环入口：悬念的产生地** |
| 玩家看的是 | "我会抽到什么" | "我这一轮的原料够不够" |

新增两条要求：
1. **兑现后立刻显示本次产出对 ρ 的影响**（这批原料能完成几个任务），把开箱和"使用物资"缝合起来，避免开箱变成孤立的爽点。
2. **批量兑现是必要功能**：ρ 成型后玩家会连续验证。

**工程铁律（不变，且更重要）：**

> **先结算结果，再播放演出。**
> 1. `GachaService.roll(series_id, structure, seed) -> Result` 是**纯函数**、带 seed、与 UI 完全解耦；演出层只播放已知结果。
> 2. `EvalService.compute(state) -> {rho, m_bar, d_bar, b, sigma, attribution}` 也是**纯函数**，与装配 UI 解耦。
> 3. **归因面板、试算、兑现对照三处必须共用同一个 `EvalService`**，绝不允许三份实现算出三个数字。
> 4. `EvalService` 与 `GachaService` **必须共享同一套权重计算路径**——即"显示的期望"和"实际抽取"用的是同一份代码。这是 P1 的工程保证，也是最容易出 bug 的地方。

## 9. 全收集：终局

### 9.1 终局情感

全收集的收尾不是"我终于抽到了"，而是 **"我算赢了它"**。

因为这个游戏里集齐不靠运气，靠把 ρ 做到足够高。**全收集是玩家工程能力的证明。** 这是"从赌徒到庄家"这条线的最终兑现。

### 9.2 终局结构

| 阶段 | ρ | 玩家体感 | 收集状态 |
|---|---|---|---|
| 开局 | < 1 | 花一个少一个，紧张 | 零星几款 |
| 破局 | ≈ 1 | 勉强转得动 | 首个套系过半 |
| 起飞 | 1–3 | **滚起来了** | 快速补全前期套系 |
| 工程期 | 3–10 | 我在设计系统 | 长尾款开始显形 |
| 收官 | 10+ | 碾压 | 集齐全套系 |

### 9.3 后期摩擦的来源

后期摩擦**必须来自需求结构**（任务越来越需要分散、稀有的物资类别），而不是来自调低概率。这条是硬的：**用低概率撑时长会直接摧毁 P1 和"可信的未知"。**

## 10. 教学曲线

ρ 是多参数概念，门槛高于"开盲盒收集"。**这是本设计最大的用户层代价，必须用教学设计补偿。**

| 阶段 | 引入内容 | 玩家此刻理解的事 |
|---|---|---|
| 0–10 min | 只有开盒 + 交付 + 显示 ρ | "原来这游戏有个循环" |
| 10–30 min | 引入**转化** | "我能把没用的换成有用的" |
| 30 min–1 h | 引入**装置**（只有转化端） | "物资可以留着变强，而不是用掉" |
| 1–2 h | 引入**开盒端装置** | "ρ 有两个方向" |
| 2 h+ | 方差轴、场景约束、多套系 | "我要在两条轴之间取舍" |

**第一小时只暴露一个维度。** 一次给全两端 + 方差 + 转化，玩家会立刻放弃。
**"燃料还是引擎"这个中心机制必须在 30 分钟内出现**——它是本作的灵魂，不能埋太深。

## 11. 风险与对策

| # | 风险 | 后果 | 对策 |
|---|---|---|---|
| **R1** | **使用物资的决策退化为唯一解**（最大风险） | 深度消失，循环变成点击流水线 | §3 燃料/引擎的永久取舍；§6 三轴冲突 + 场景约束；装置槽位硬上限 |
| **R2** | 物资种类爆炸，超出玩家心算能力 | 玩家放弃规划，改成乱点 | P6 试算 / 沙盒；任务面板用需求向量 vs 持有向量的对照呈现，而不是列表 |
| **R3** | ρ 起飞后循环失去张力 | 后期变成无脑挂机 | §9.3 需求结构提供摩擦；每个数量级解锁新套系与新物资类别 |
| **R4** | 数字膨胀但体验空洞 | ρ 从 1e3 到 1e6，玩家毫无感觉 | ρ 必须绑定**可感知产出**（真的开出更多更好的东西）；每个数量级要有新的可感知内容 |
| **R5** | 无付费导致肝度失控 | 靠调低概率撑时长，毁掉 P1 | 用**内容量**（套系数 × 物资类别 × 任务结构）而非低概率提供长期目标；隐藏款 2% 不随进度衰减 |
| **R6** | 用户层收窄 | 目标用户从"休闲收集玩家"变为"系统思考型玩家" | **接受这个取舍并据此外宣**；用 §10 尽量扩大入口 |
| **R7** | 开箱被工具化 | 玩家只想批量兑现，跳过所有演出 | 保留 §5 P4 单次悬念；稀有结果强制完整演出；§4.6 兑现时机决策 |
| **R8** | 装配误操作的恐惧让玩家不敢决策 | 中心机制被玩家主动回避 | §3.2 可逆但昂贵；选择点必须显示"放弃了什么" |

**R1 与 R6 是必须先回答的两个问题。** R1 决定玩法成不成立，R6 决定这门生意做不做。

## 12. 垂直切片范围

**切片目标：验证"使用物资"这一步好不好玩。**（不是验证开箱，不是验证 ρ 的数值）

要回答的问题：
1. 玩家拿到物资时，**会不会真的犹豫**"用掉还是留着"？（§3）
2. 玩家能否在 2 分钟内说出自己 ρ 的主要来源？（P2 归因是否被理解）
3. ρ 从 0.8 涨到 2.4 时，**有没有爽感**？
4. 玩家会不会主动去试算、反复调整装配？（P6）
5. 第一小时有没有被两端 + 转化 + 方差淹没？（§10）

### 12.1 做

- [ ] **`EvalService`：纯函数计算 ρ / M̄ / D̄ / B / σ / 逐项归因**（一切的地基）
- [ ] **循环面板 + 归因面板 + 架上面板 + 任务面板**（四个面板就是玩法本体）
- [ ] 1 个套系：8 常规 + 1 隐藏
- [ ] **2 类物资**（类别 × 品质两维），足够支撑转化与任务需求
- [ ] **任务系统**：3 个可重复常规任务 + 1 个里程碑任务，需求向量化
- [ ] **燃料/引擎取舍**（中心机制，必须最早实现）
- [ ] 装置：4 个槽位，**两端各至少 2 个**，含 1 组跨端非线性组合
- [ ] **转化系统**：带损耗，损耗率可被装置影响
- [ ] 试算 / 沙盒：装配前预览 ρ 变化
- [ ] 分布直方图，随装配实时变形
- [ ] 兑现链条：开盒 → 四段式演出 → **产出对 ρ 的影响提示**
- [ ] 盲盒囤积 + 兑现时机选择
- [ ] 重复物资 → 数量叠加以外的去处（转化 / 装置素材）
- [ ] 概率与保底公示界面
- [ ] **手动设定 ρ 曲线做手感测试**（不接真实经济，先验证爽感）
- [ ] 存档 + 全数据驱动配置
- [ ] 开箱日志（seed + 结果，可复现）

### 12.2 不做

- 成品美术与音效（占位资源）
- 社交、排行榜、交换（仅预留接口）
- 第 2 个及以后的套系
- 里程碑任务链、成就系统
- 剧情、角色养成
- 本地化、设置菜单、手柄适配
- 付费、广告、任何变现

### 12.3 切片成功判据

任一成立即继续：
- 测试者在**无人引导**的情况下，主动讨论"这个要不要留"；
- 测试者能说出自己 ρ 的主要贡献来源；
- 测试者表现出"等我把 ρ 做上去再开这批盒子"的囤积行为；
- 测试者连续调整装配 ≥3 次而不觉得烦。

### 12.4 切片失败信号（要正视）

- 测试者把物资**全部**用掉，从不考虑装配 → §3 的中心机制不成立；
- 测试者把物资**全部**留下，从不完成任务 → 循环张力不成立；
- 测试者问"这些数字是干嘛的" → §10 教学曲线失败。

## 13. 技术骨架（Godot 4.5）

### 13.1 目录结构

```
res://
  autoload/
    game_state.gd         # 运行时状态（物资、装置、任务、囤积盲盒、保底计数）
    eval_service.gd       # ★ 纯函数：state -> {rho, m_bar, d_bar, b, sigma, attribution}
    gacha_service.gd      # ★ 纯函数：roll(series_id, state, seed) -> Result
    task_service.gd       # 任务需求匹配与结算
    save_service.gd       # user:// 存档（JSON）
  data/
    defs/
      material_def.gd     # extends Resource：类别、品质、堆叠规则
      device_def.gd       # extends Resource：作用端、作用目标、系数、条件
      task_def.gd         # extends Resource：需求向量、奖励、可重复性
      series_def.gd       # extends Resource：权重表、保底参数、池构成
    series/
      series_01.tres
  scenes/
    panels/               # 循环 / 归因 / 架上 / 任务 四个面板
    loadout/              # 装置装配工作台 + 试算
    workbench/            # 转化
    gacha/                # 兑现演出（四段式，独立可测）
    collection/           # 图鉴 / 套系进度
  ui/
  tests/
```

### 13.2 工程铁律

1. **`EvalService` 与 `GachaService` 都是纯函数、不依赖节点**，可在无头模式跑单测。给定 `(state, series, seed)`，输出必须完全确定。
2. **四个面板、试算、兑现对照全部共用 `EvalService`**，绝不允许各自实现。
3. `EvalService` 与 `GachaService` **共享同一套权重计算路径**——"显示的期望"和"实际抽取"必须是同一份代码。
4. 存档记录每次兑现的 `{ seed, series_id, state_snapshot, item_id, star }`，同时具备四个用途：开箱日志、可复现凭据、玩家信任基础（P1）、**归因回归测试的数据源**。

### 13.3 数据驱动

- 内容用自定义 `Resource`（`.tres`）：`MaterialDef` / `DeviceDef` / `TaskDef` / `SeriesDef`，编辑器内可检视与引用。
- **装置与任务参数必须完全数据化**（作用端、目标、系数、条件、互斥标记）。新装置、新任务应可纯配置产出，不改代码。
- 这是内容产能的生命线：本作的长期内容量 = 装置数 × 任务结构数 × 物资类别数，如果每个都要写代码，内容永远做不够。

## 14. 待定决策

| # | 决策 | 推荐 | 备选 | 影响 |
|---|---|---|---|---|
| **D1** | ρ 成长形态 | **无上限增长（增量式）** | 有限目标分阶段 | 决定数值架构与存档结构；阻塞切片开工 |
| **D2** | 物资维度 | **类别 × 品质 两维** | 仅类别 / 三维（+ 产地） | 决定任务需求向量与心算负担（R2） |
| **D3** | 装置槽位与解锁曲线 | 4 → 10，按里程碑解锁 | 固定 4 / 固定 6 | 决定"燃料/引擎"取舍的强度 |
| **D4** | 装配可逆性 | **可拆，返还 50%** | 完全不可逆 / 全额返还 | 直接关系 R8 |
| **D5** | 转化损耗基准 | 30%（可被装置降到 10%） | 更高 / 更低 | ρ 的主要调参旋钮 |
| **D6** | 任务需求是否随进度变宽 | **是**（§9.3 后期摩擦来源） | 恒定 | 决定是否必须靠概率提供长期压力（R5） |
| **D7** | 场景约束随机化的形式 | 每批任务附带 1 条环境约束 | 无约束 | 抑制 R1 的主要手段 |
| **D8** | 是否允许一键最优装配 | **不提供** | 提供自动最优化 | 直接关系 R1 |

**D1 是唯一的硬阻塞项**，定了才能开工写数值。

## 16. 一句话总结

**循环上只有"使用物资"这一步有选择，所以全部深度都在那里。**
物资永远面对同一个问题——**用掉它推进循环，还是留下它让循环转得更好**——
而玩家对这一问题的每一次回答，都在把"盲盒的期望"往上推，直到集齐不再需要运气。
