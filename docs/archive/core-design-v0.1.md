# 《Open Box》核心设计书

- 版本：v0.1
- 状态：方向已定，待垂直切片验证
- 引擎：Godot 4.5（Forward+）
- 已定前提：**纯单人** / **纯游戏内货币，无数值付费** / 藏品**有用**（改变玩法与构筑）/ 社交**留接口不实现**

---

## 1. 核心体验

### 1.1 一句话定义

> 用一段短暂而可信的悬念，换一次必然揭晓的确定感；而真正的黏性不在揭晓那一刻，而在揭晓之后你手上多出来的那个缺口。

### 1.2 四个情绪节拍

| 节拍 | 玩家内心 | 设计载体 |
|---|---|---|
| **期待** | "我不知道里面是什么，但我知道清单上有什么" | 盒子的分量感、摇盒/掂量/透光等手感仪式 |
| **揭示** | 悬念释放的 2–3 秒 | 破封演出、分级预告、音效、稀有度提示 |
| **占有** | 从"一个概率"变成"一个私有物" | 入库确认、上架陈列、可在构筑中被使用 |
| **缺口** | "我差 3 个" | 图鉴空格、套系进度条、构筑面板上的空槽 |

### 1.3 最重要的判断

**"揭示"的半衰期是秒，"缺口"的半衰期是周。**

- 开箱演出决定玩家**爽不爽**；
- 套系清单与缺口设计决定玩家**玩多久**。

绝大多数盲盒游戏死在只做了前一半：演出花团锦簇，但清单只有 12 款，抽完即终局。
**推论：本作的内容产能预算，必须至少一半投在"套系清单与缺口可见性"上，而不是全砸在开箱特效。**

### 1.4 未知必须同时满足的三个条件

| 条件 | 含义 | 违反的后果 |
|---|---|---|
| **可信的未知** | 玩家相信稀有款真实存在且自己可能抽到 | 隐藏款变成传说，抽卡变成交税 |
| **有界的未知** | 清单有限、有名字、全貌可见 | 无限随机 = 赌博，没有终局感 |
| **廉价的未知** | 重复一次决策的成本极低 | 期待退化成排队，第二十次开箱就是折磨 |

## 2. 设计支柱

支柱必须有**否决权**，不能否决任何东西的支柱是口号。

### P1 · 未知可信
概率公开、可查、可复现。每次开箱记录随机种子。
**否决：** 任何暗改概率、动态调低爆率、"根据玩家余额悄悄调权重"的设计。

### P2 · 重复永远不是空手
任何一次开箱都必须产出有用途的东西（升阶 / 碎片 / 定向兑换）。
**否决：** 任何会产生"我什么都没得到"的开箱结果。

### P3 · 盒子改变玩法，不改变数值天花板
新藏品带来新的**玩法杠杆**（新机制、新乘区、新触发条件），而不是更高的攻击力。
**否决：** "隐藏款 = 数值更高的同款"这类设计。

### P4 · 揭示优先
开箱是全游戏情绪峰值，任何系统都不许把它压缩成"点一下确认"。
**否决：** 把开箱做成批量"一键十连并直接跳结果"作为默认路径（可作为解锁后的便利功能，但默认必须是完整演出）。
反面同样成立：单次开箱演出**不得超过 15 秒**。

---

## 3. 核心循环

三层时间尺度，必须首尾相接成闭环。

```
[秒级]  货币/券 ──▶ 开盒 ──▶ 揭示 ──▶ 入库（藏品 + 升阶 + 碎片）
                                          │
[分级]  构筑 ──▶ 挑战关卡 ──▶ 奖励（币 / 券 / 未开封的盒子）
            ▲                             │
            └─────── 新藏品解锁新打法 ◀────┘

[周级]  套系缺口 ──▶ 定向追求 ──▶ 集齐 ──▶ 套系共鸣 ──▶ 新套系开放
```

### 3.1 关键机制：奖励以"未开封的盒子"交付

挑战奖励不要全部给货币，**要直接给未开封的盒子**。

- 玩家攒的不是数字，而是**一堆待开的悬念**。
- 悬念可囤积 = 天然的期待池。囤了 5 个盒子再一次性开，是玩家自己制造的仪式感。
- 拿到盒子的那一刻（奖励结算）就已经开始产生期待，早于实际开箱。

这是本作最便宜、最强的一个情绪杠杆，必须早期实现。

### 3.2 关键机制：分池 + 定向券

**收集悖论**：套系越多，单一套系的完成度被稀释得越厉害，玩家会陷入"永远差很多"的绝望。

对策（两者都要）：
1. **每个套系独立概率池**，各自 8 常规 + 1 隐藏。
2. **套系券（Series Ticket）**：只能开指定套系的盒子，由挑战奖励与成就发放，让玩家能定向推进某个套系。
3. 通用盒（Coin 开）从**已解锁的套系池**中按玩家自选或轮换产出。

## 4. 系统骨架

### 4.1 资源（3 种，全部可肝）

| 资源 | 代码名 | 获取 | 用途 |
|---|---|---|---|
| 零钱 | `coin` | 挑战关卡、日常 | 开通用盒 |
| 套系券 | `ticket[series_id]` | 挑战奖励、套系成就 | 开指定套系盒（定向） |
| 碎片 | `shard[series_id]` / `shard_universal` | 重复款转化 | 定向兑换指定常规款、升阶加速 |

### 4.2 藏品（Collection Item）

- 每个藏品 = 一个**玩法词条（Trait）**，装入构筑槽后生效。
- 稀有度 `N / R / H`（隐藏）。**稀有度表示杠杆的"意外程度"，不表示强度等级。**
- 每款可升阶：★1 → ★5。升阶微幅增强词条或降低触发条件，**封顶**，避免无限堆叠导致平衡崩坏。
- 满星后的重复款自动转碎片。

### 4.3 套系（Series）

- 一个套系 = 一个主题 + 一个共享玩法机制方向。
- 结构：**8 常规 + 1 隐藏**。
- **套系共鸣（Set Resonance）**：集齐 8 款常规 → 解锁该套系专属共鸣词条（仅在构筑中生效）。
- 隐藏款提供**规则改写级**效果（例：改变某个乘区的计算方式），而不是数值加成。

### 4.4 缝合机制（本作的中心设计任务）

"有用"会侵蚀"收藏"——若藏品只代表强度，玩家会退化成"我只要最强的那件"，盲盒随即塌回抽装备。三条缝合线：

1. **重复款 = 构筑资源**（对应 P2）
   重复不是浪费，是同一件的升阶材料。重复率随套系进度自然下降，玩家体感是"我在把这个盒子变强"。
2. **套系共鸣 = 集齐的玩法回报**（对应 P3）
   集齐不再只是图鉴好看，而是**构筑强度的一部分**。缺口因此有了玩法层的理由，而不只是收藏强迫症。
3. **缺口在构筑面板可见**
   构筑槽位里未拥有的藏品以"空槽 + 套系进度"形式显示。让缺口出现在玩家每天都会看的界面上，而不是藏在图鉴深处。

### 4.5 概率与保底（必须明示）

| 项 | 数值 | 说明 |
|---|---|---|
| 隐藏款基础概率 | 2% | 单套系内 |
| 常规款基础权重 | 均等 | 8 款各 12.25% |
| 新款加权 | 未拥有款权重 ×1.5 | 轻度倾斜，降低连续重复挫败 |
| 硬保底 | 连续 8 次未出新款 → 下次必出新款 | 计数器 UI 可见 |
| 隐藏款重复 | 首次获得后移出池，替换为大量碎片 | 单人无交换，重复隐藏款极度挫败 |

**概率公示界面是"可信的未知"的载体，属于垂直切片范围，不是可选项。**

### 4.6 定向兑换（数字版的"端盒"）

实体盲盒真正的钱来自两拨相反的人：享受赌的人（买概率）与不享受赌的人（买确定），所以才有端盒——多花钱把随机性整个买掉。

单机无付费版本里，**"确定性出口"必须由碎片系统提供**：
用碎片直接兑换指定常规款，价格 ≈ 该款期望开盒次数的 1.6 倍。

- 服务不享受赌的玩家，防止其流失；
- 同时给碎片一个消耗出口，避免通胀。

## 5. 开箱演出规格

情绪峰值所在，必须写死规格。

### 5.1 四段式时间轴

| 段 | 时长 | 内容 | 玩家可操作性 |
|---|---|---|---|
| 1 摇盒 | 1.0 – 1.8s | 盒子随鼠标/摇杆晃动，内含物碰撞声 | **可操作**——制造掌控错觉 |
| 2 破封 | 0.4 – 0.6s | 封条断裂，光从缝隙溢出 | 不可操作 |
| 3 分级预告 | 0.3s + 1.5s 停顿 | **先只说稀有度**（颜色 + 音高），不说是哪一款 | 不可操作，**故意留白** |
| 4 揭晓入库 | 1.0 – 1.5s | 藏品出现、词条展示、缺口更新提示 | 可跳过后续 |

总时长 4.5 – 7s，上限 15s。

### 5.2 核心技巧：分级预告

第 3 段是全部情绪的放大器。**先让玩家知道"这次不一样"，再让玩家多等 1.5 秒。**

- 音高与色温分级：常规 = 中性色 / 低频；稀有 = 暖色 / 中频；隐藏 = 高饱和 + 音高上扬 + 屏幕边缘微光。
- 停顿期间**任何东西都不出现**，只有暗示。这段留白是设计出来的，不要为了"节奏紧凑"删掉它。

### 5.3 重复款的体面

常规款重复时，**不要羞辱玩家**（禁止"很遗憾""又是它"这类文案）。
必须显示：升阶进度条前进、碎片 +N、距离保底还差几次、该套系完成度变化。让重复在视觉上仍然是一次**进展**。

### 5.4 工程约定（重要）

> **先结算结果，再播放演出。**

`GachaService.roll()` 必须是纯函数式的、可复现的（带 seed）、与 UI 完全解耦；演出层只是"播放一个已知结果"。

理由：
- 可跳过、可回看、可批量；
- 抽卡逻辑不耦合进动画代码（这是同类项目最常见的返工来源）；
- 出问题时可复现（存 seed + 结果，便于查证，服务 P1）。

## 6. 风险与对策

| # | 风险 | 后果 | 对策 |
|---|---|---|---|
| R1 | "有用"侵蚀"收藏" | 玩家退化为只追最强件，盲盒变抽装备 | §4.4 三条缝合线；P3 否决纯数值升级 |
| R2 | 重复款挫败 | 玩家感到"花钱买垃圾" | P2 + 升阶 + 新款加权 + 硬保底 + 碎片定向 |
| R3 | 收集悖论（池子稀释） | 套系越多越绝望 | §3.2 分池 + 套系券 |
| R4 | 开箱疲劳 | 第 20 次开箱开始找跳过键 | 演出可跳过但默认完整；批量开箱作为解锁功能；总时长硬上限 15s |
| R5 | 无付费 → 肝度失控 | 为了撑时长把概率调低，直接毁掉"可信的未知" | 用**内容量**（套系数）而不是**低概率**来提供长期目标；隐藏款 2% 不随进度衰减 |
| R6 | 单人无交换 → 稀有缺乏见证 | 稀有款没有社会意义，"可信的未知"变弱 | 垂直切片期用**本地开箱日志/出货记录**作为准见证；社交接口预留 |

## 7. 垂直切片范围

**切片目标：验证核心体验，不是验证构筑深度。**

要回答的问题：
1. 连开 30 次盒子，第 30 次还愿意看演出吗？（R4）
2. 抽到重复款时，玩家感到"进展"还是"浪费"？（R2）
3. 看到图鉴缺口时，有没有"就再来一次"的冲动？（§1.3）

### 7.1 做

- [ ] 1 个套系：8 常规 + 1 隐藏，全部有实际词条
- [ ] 开箱链条：币/券 → 开盒 → 四段式演出 → 入库
- [ ] **以未开封盒子形态交付奖励**（§3.1）
- [ ] 图鉴 + 套系进度 + 构筑面板缺口显示
- [ ] 重复款升阶（★1–★5）+ 碎片 + 定向兑换
- [ ] 概率公示界面 + 保底计数器
- [ ] 最小构筑：3 槽位，8–10 个词条，能组合出至少 2 种可辨识的不同打法
- [ ] 1 个极简挑战关卡（验证"有用"是可信的）
- [ ] 存档 + 全数据驱动配置（改数值不改代码）
- [ ] 开箱日志（seed + 结果，可回看）

### 7.2 不做

- 成品美术与音效（用占位资源）
- 社交、排行榜、交换（仅预留接口）
- 第 2 个及以后的套系
- 剧情、对话、角色养成
- 本地化、设置菜单完善、手柄适配
- 付费、广告、任何变现

## 8. 技术骨架（Godot 4.5）

### 8.1 目录结构

```
res://
  autoload/
    game_state.gd        # 运行时状态（持有藏品、货币、保底计数）
    gacha_service.gd     # 纯逻辑开箱：roll(series_id, seed) -> Result
    save_service.gd      # user:// 存档读写（JSON）
    audio_service.gd     # 音效与分级音高
  data/
    defs/
      item_def.gd        # extends Resource
      series_def.gd      # extends Resource，含权重表
    series/
      series_01.tres
  scenes/
    gacha/               # 开箱演出场景（四段式，独立可测）
    collection/          # 图鉴 / 套系进度
    loadout/             # 构筑面板
    challenge/           # 挑战关卡
  ui/
  tests/
```

### 8.2 数据驱动

- **内容用自定义 `Resource`（`.tres`）**：`ItemDef` / `SeriesDef`，可在编辑器里引用贴图、检视权重。
- `SeriesDef` 内嵌权重表与保底参数，改数值不改代码。
- 逐个藏品/套系的批量数值如后期膨胀，再考虑外置 CSV 导入。

### 8.3 分层与测试

- `GachaService` 不依赖任何节点，可在无头模式下跑单测：给定 seed 与权重，输出必须确定。
- 演出层订阅 `GachaService` 的 Result，不参与结算。
- 存档记录：`{ seed, series_id, item_id, star, is_new }` 列表——同时是开箱日志、可复现凭据、玩家信任基础（P1）。

## 9. 待定决策

| # | 决策 | 推荐 | 备选 | 影响 |
|---|---|---|---|---|
| D1 | 承载玩法外壳 | **关卡式挑战 + 轻 Roguelite**（带 3 槽构筑进场，途中可加装） | 放置挂机 / 卡牌对战 / 塔防 | 决定构筑词条的设计空间与切片工作量 |
| D2 | 藏品命名与包装 | **"藏品"（可陈列的物）** | 伙伴 / 装置 / 卡牌 | 决定美术方向与玩家情感称呼 |
| D3 | 构筑槽数量曲线 | 3 → 6（随进度开放 3 个） | 固定 3 / 固定 6 | 影响词条组合爆炸度与平衡难度 |
| D4 | 挑战是否消耗资源 | **消耗体力/券**，用于控制节奏 | 无限次挑战 | 决定经济体是否闭环 |
| D5 | 是否做"碎片合成隐藏款" | 暂不做，隐藏款只靠概率 | 极高价碎片兑换 | 影响隐藏款的心理价值 |

---

## 10. 一句话总结

把开箱做成 6 秒的情绪过山车，把套系缺口做成 6 周的执念；
让每一次重复都算作进展，让每一次集齐都改变打法。
