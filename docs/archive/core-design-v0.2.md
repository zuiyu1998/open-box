# 《Open Box》核心设计书

- 版本：**v0.2（核心玩法转向：做大盲盒的数学期望）**
- 上一版：`docs/archive/core-design-v0.1.md`
- 引擎：Godot 4.5（Forward+）
- 已定前提：**纯单人** / **纯游戏内货币，无数值付费** / 社交**留接口不实现**

> **v0.2 转向说明**
> v0.1 把盲盒当作**奖励交付机制**，玩家是被随机性支配的一方。
> v0.2 把盲盒的**数学期望本身**当作被施工的对象，玩家是拿着参数在随机性之上动工的一方。
> 核心幻想从「赌徒」变为「庄家」。因果关系反转了：**v0.1 是"玩玩法，顺带开盒"；v0.2 是"改概率，用开盒兑现"。**

---

## 1. 核心体验

### 1.1 一句话定义

> **在不消灭单次悬念的前提下，把随机性从"命运"改造成"参数"——玩家成为自己盲盒的庄家。**

### 1.2 核心幻想：从赌徒到庄家

| | v0.1 / 传统盲盒 | v0.2 / 本作 |
|---|---|---|
| 玩家身份 | 赌徒 | **庄家（精算师）** |
| 随机性的地位 | 支配玩家的力量 | **玩家手里的可调参数** |
| 玩家的台词 | "我运气不好" | **"我的返还率是 3.7，我要做到 12"** |
| 情绪峰值 | 揭示那 2 秒 | **期望数字上升的那一刻** |

玩家的满足感不再来自"这次抽到了好的"，而来自**"我让这个池子的产出结构变好了"**。

### 1.3 保住了盲盒的灵魂

一个诚实的质疑：**如果一切都能算清楚，悬念不就死了吗？**

答案不是回避，而是**把未知下移一层**：

| 层级 | 状态 | 玩家能做什么 |
|---|---|---|
| **分布层** | 完全已知、可计算、可改造 | **施工对象** —— 这是玩法本体 |
| **单次结果层** | 永远未知 | **悬念来源** —— 这是盲盒本体 |

这正如赌场：庄家清楚自己的优势为正，但**每一局的结果仍然随机**。
玩家因此**同时拥有庄家的确定性与赌徒的悬念**——这是本作体验的独特之处，也是"这还叫盲盒吗"这个身份问题的答案。

### 1.4 四个情绪节拍（重构）

| 拍 | 玩家内心 | 载体 |
|---|---|---|
| **测量** | "我现在到底赚不赚？" | EV / RTP 面板、归因分解 |
| **施工** | "我把这条规则换掉会怎样？" | 算子装配、结构面板、试算 |
| **验证** | "涨了！"—— **峰值在此** | 期望数字跃升、归因高亮 |
| **兑现** | "现在开给你看" | 开箱演出、实际产出、方差收窄 |

**v0.1 的"揭晓"从唯一峰值降级为兑现环节。** 开箱演出因此获得了一个更扎实的存在理由：它是玩家**验证自己施工正确性**的仪式，而不只是刺激本身。

## 2. 主数值：RTP

### 2.1 定义

主数值不是裸 EV，而是**返还率 RTP**：

```
EV   = Σ ( p_i × v_i )      每种结果的概率 × 其价值
RTP  = EV / C                C = 开盒成本
```

选 RTP 而不是 EV 的理由：**它自带参照系。** `RTP = 1.0` 是一个天然的、可感知的里程碑——它意味着"打平庄家"。这条线给了玩家一条清晰的成长叙事：

> **亏 → 打平（RTP=1）→ 开始赢 → 碾压（RTP=10、100、1000）**

从韭菜到庄家。这是本作的灵魂曲线。

### 2.2 主数值必须满足的三个条件

| 条件 | 含义 | 违反的后果 |
|---|---|---|
| **可测量** | 游戏必须显式显示 EV / RTP | 玩家看不见数字，就无法"做大"它 |
| **可提升** | 有足够多且彼此组合的杠杆 | 两三步就摸到天花板，内容量撑不住 |
| **可归因** | 能看到**每一项规则贡献了多少** | 上升变成黑箱，玩家丧失施工感 |

第三条最容易被忽略，也最致命。玩家必须能读到：
「装备算子 A：+1.10（权重改造）／ 算子 B：+0.14（与 A 的联动）／ 套系共鸣：+0.35」

**归因面板是核心玩法，不是数据可视化装饰。**

### 2.3 必要的经济约束：估值 ≠ 可变现

若 EV 可直接变现，RTP > 1 会导致通胀崩坏。因此：

- `v_i` 是**账面估值**（价值点），不是可直接兑换的货币。
- 藏品有两种出口：**作为算子使用**（保留账面价值）或**转化为碎片**（实际货币）。
- **碎片转化率远低于估值**，这条差值就是经济缓冲垫。

结论：玩家放大的是**账面期望**，实际收益体现在"我的池子产出质量更高"。**成长感来自产出质量，而不是印钱。**

## 3. 设计支柱

支柱必须有**否决权**。

### P1 · 一切概率与期望可见可算
概率、权重、保底计数、EV、RTP、方差——全部对玩家公开。
**否决：** 任何暗改概率、动态调权、"根据玩家余额悄悄调爆率"的设计。这一条在 v0.2 里比 v0.1 更不可让步，因为**概率现在是玩家的施工材料，材料必须是真的**。

### P2 · 每一次上升都必须可归因
EV 变化必须能逐项解释贡献者。
**否决：** 任何"多个效果叠加后只显示一个总数"的数值呈现方式。

### P3 · 不存在唯一最优解
构筑必须在 **EV / 方差 / 定向** 三条互相冲突的轴上取舍（§6）。
**否决：** 任何能被算出一个压倒性最优配置的规则组合。

### P4 · 单次悬念不可消除
可优化的是分布，不是结果。任何"预测本次结果"的机制一律否决。
**否决：** 透视、预知、下次必出某款（保底是分布层的规则，不是结果层的预测，二者不可混同）。

### P5 · 重复永远不是空手
重复款是算子升阶与碎片的主要来源，是"做大"的燃料。
**否决：** 任何会产生"我什么都没得到"的开箱结果。

### P6 · 玩家的时间用于决策，不是用于算数
试错成本必须趋近于零：提供试算 / 沙盒。
**否决：** 任何要求玩家手算或外部查表才能决策的机制。

## 4. 核心循环

### 4.1 自指闭环

```
① 测量 ── 看清当前 RTP 与它的构成
              │
② 施工 ── 装配算子，改造概率结构
              │
③ 验证 ── RTP 上升  ★峰值在此★
              │
④ 兑现 ── 用新结构开盒：产出质量提升、方差收窄
              │
⑤ 产出 ── 开出新的算子素材 / 更强的算子
              │
              └──────────▶ 回到 ①
```

**这是一个自指闭环：开盒产出的东西，让开盒本身变强。**
每一步都有悬念（开出什么），每一步都有确定增长（RTP 上升）。**悬念与增长的双重驱动**，是增量类玩法最强的形态。

### 4.2 藏品的重新定义（最大的改动）

| | v0.1 | v0.2 |
|---|---|---|
| 藏品是什么 | 玩法词条（装备，改变战斗表现） | **概率算子（Probability Operator）** |
| 藏品的作用对象 | 角色 | **开盒过程本身** |
| 收集的意义 | 集齐套系 | **收集算子是做大期望的唯一原料** |

这一步让 **"收集"与"变强"彻底焊死**：v0.1 的 R1 风险（"有用"侵蚀"收藏"）在 v0.2 中自动消失——因为**有用就等于提高期望，而提高期望需要更多藏品**。

### 4.3 兑现时机（Timing）——意外收获的决策层

奖励可以**以未开封的盒子形态交付**（继承 v0.1 §3.1），在新设计下它获得了一层全新意义：

- 盒子可**囤积**。
- 何时兑现是**决策**：「现在开」vs「等我 RTP 再高一点再开」。

由此自然产生一种资源配置玩法：**用低价值池刷算子素材，把高价值池的盒子攒到结构成型后再开。**

这是纯粹的涌现乐趣，不需要额外系统，只需保留"盒子可囤积"这一条规则。

## 5. 系统骨架

### 5.1 算子分类

算子是本作的全部内容。要让组合产生**非线性**，算子必须分类，且**跨类之间才有强交互**。

| 类别 | 作用位置 | 示例 |
|---|---|---|
| **权重算子** | 概率分布 `p_i` | 池中估值最低的 2 款，权重 ×0.5 |
| **阈值算子** | 稀有度判定边界 | 稀有判定阈值 −1 |
| **保底算子** | 必出条件的触发计数 | 保底计数 8 → 6 |
| **转化算子** | 重复款价值 | 重复款转化的碎片 ×2 |
| **池算子** | 池子构成 | 允许向池中注入 1 款自选藏品 |
| **估值算子** | 产出物计价 `v_i` | 该套系藏品估值 +30% |
| **规则算子** | 改写判定流程本身 | 隐藏款不再移出池（仅隐藏款提供） |

### 5.2 非线性从哪来（构筑深度的来源）

**同类算子只做叠加，跨类算子相乘。** 这是全部深度的来源。

例：
- 「保底算子（8→6）」+「阈值算子（稀有门槛 −1）」
  单独看，前者只是更快出货；两者组合后，**保底产出的不再是常规款而是稀有款**——EV 跃升远超线性叠加。
- 「池算子（注入自选高价值款）」+「权重算子（压制低价值款）」
  池子被"提纯"，价值密度大幅上升，且**注入哪一款**取决于玩家当前缺口，形成策略分支。

**设计目标：任何两个跨类算子的组合，都应该产生一个玩家能自己发现、但不容易预先算到的跃升。**

### 5.3 套系与算子

- 一个套系 = 一个主题 + **一类算子的主产地**。
  例：套系 1 出产权重算子，套系 2 出产保底算子，套系 3 出产池算子。
- 结构：**8 常规 + 1 隐藏**（隐藏款提供规则算子）。
- 这样"推进新套系"= "解锁新算子类别" = "打开新的组合空间"，内容量与玩法深度同步增长。
- 套系共鸣：集齐 8 款常规 → 解锁该套系的共鸣算子。

### 5.4 概率池

- 每个套系**独立概率池**（分池，避免 v0.1 的收集悖论）。
- 隐藏款基础概率 2%；常规款均等；未拥有款权重 ×1.5；连续 8 次未出新款则硬保底。
- **概率公示界面属于核心玩法范围，不是可选项**（P1）。

### 5.5 资源

| 资源 | 代码名 | 获取 | 用途 |
|---|---|---|---|
| 零钱 | `coin` | 兑现产出、成就 | 开通用盒 |
| 套系券 | `ticket[series_id]` | 进度奖励 | 开指定套系盒（定向推进） |
| 碎片 | `shard[series]` / `shard_universal` | 重复款转化 | 定向兑换、算子升阶 |

**无数值付费**，所以长期目标必须由**内容量（套系数 × 算子数）**提供，而不是靠调低概率（见 R5）。

## 6. 方差：第二条轴

**这是防止"最优解收敛"的关键设计（P3）。**

RTP 不是唯一目标。方差 σ 是**独立的第二条轴**，且必须**显式显示**（数字 + 分布直方图）。

| 构筑方向 | 玩家类型 | 手段 |
|---|---|---|
| **RTP 最大** | 长期主义者 | 堆期望，容忍高方差 |
| **σ 最小** | 稳健派 | 堆保底、收窄分布、抬高下限 |
| **定向获取** | 收集派 | 用池算子精确注入缺口款 |

三者**互相冲突**（堆保底会牺牲上限，定向注入会摊薄 RTP），因此**不存在唯一最优解**。

必须写进规格的两条：
1. 方差是**一等公民数值**，不是隐藏属性。
2. 分布直方图是**核心 UI**，要能实时反映算子装配后的形状变化——"看着这条曲线被自己捏成另一个形状"是本作最独特的快感。

## 7. 可视化是玩法本体

**v0.2 把美术与 UI 预算的重心从"开箱特效"移到了"概率可视化"。** 这是相对 v0.1 的资源再分配，必须明确。

### 三个必备面板

| 面板 | 内容 | 为什么是玩法 |
|---|---|---|
| **期望面板** | 当前 EV / RTP / σ、里程碑进度 | 没有它就没有"做大"这个动作 |
| **归因面板** | 逐算子贡献分解、装配前后对比、高亮差值 | 施工感的来源（P2） |
| **结构面板** | 生效算子、槽位、互斥关系、池子构成 | 玩家的工作台 |

### 试算 / 沙盒（P6）

装配前可**预览 RTP 变化**，试错成本为零。
玩家负责决策，机器负责计算。**没有试算功能的 EV 游戏会变成电子表格苦力。**

## 8. 开箱演出的新地位

演出规格继承 v0.1 §5（摇盒 → 破封 → 分级预告 → 揭晓入库，总时长 4.5–7s，上限 15s，可跳过），但**定位变化**：

| | v0.1 | v0.2 |
|---|---|---|
| 演出是什么 | 唯一情绪峰值 | **兑现环节：施工成果的验收仪式** |
| 玩家看的是 | "我会抽到什么" | **"我调的结构到底管不管用"** |

因此新增两条演出要求：
1. **兑现前显示"预期 vs 实际"**：开盒结算后，展示本次结果与当前分布的对照（是否落在预期内）。
2. **批量兑现**：结构成型后，玩家会想连续验证。批量开盒是**必要功能**而非便利功能（与 v0.1 的结论相反）。

工程约定不变，且在 v0.2 中更为关键：

> **先结算结果，再播放演出。**
> `GachaService.roll()` 是纯函数式、带 seed、与 UI 完全解耦的；演出层只播放已知结果。
>
> v0.2 追加：**`EvalService.compute(structure, series) -> {ev, rtp, sigma, attribution}` 也必须是纯函数**，与算子装配 UI 解耦。归因面板、试算、验收对照三处共用同一个计算源，杜绝三份实现算出三个数字。

## 9. 教学曲线

**EV 概念对休闲玩家门槛显著高于"开盲盒收集"。这是本转向最大的用户层代价，必须用教学设计补偿。**

| 阶段 | 引入内容 | 玩家此刻理解的事 |
|---|---|---|
| 0–10 min | 只有开盒 + 显示 RTP | "原来开盒有个平均回报" |
| 10–30 min | 只给**权重算子** | "我能改动这个数字" |
| 30 min–2 h | 引入阈值 / 保底算子 | "不同类别的规则会互相影响" |
| 2 h+ | 引入池 / 估值 / 规则算子 | "我在设计一个池子" |
| 中后期 | 方差轴、多套系跨类联动 | "我要在三条轴之间取舍" |

**第一小时只暴露一个维度。** 一次给全六个类别，玩家会立刻放弃。

## 10. 风险与对策

| # | 风险 | 后果 | 对策 |
|---|---|---|---|
| **R1** | **最优解收敛**（本作最大风险） | 最优配置被算出并传播，游戏即刻结束 | P3 三轴冲突；槽位有限；算子跨类互斥；**场景约束随机化**（每次兑现的环境约束不同，改变当前最优解） |
| **R2** | 数字膨胀但体验空洞 | RTP 从 1e6 到 1e9，玩家毫无感觉 | RTP 必须绑定**可感知产出**；每个数量级解锁新的可感知内容（新套系 / 新算子类 / 新可视化） |
| **R3** | 计算变成苦工 | 玩家在算数学而不是玩游戏 | P6 试算 / 沙盒；提供配置方案保存与对比 |
| **R4** | 悬念死亡 | 一切可计算 → 盲盒失去灵魂 | P4 未知层下移；未解锁算子的隐藏联动；套系叙事包装 |
| **R5** | 无付费导致肝度失控 | 靠调低概率撑时长，毁掉 P1 | 用**内容量**而非低概率提供长期目标；隐藏款 2% 不随进度衰减 |
| **R6** | 用户层收窄 | 目标用户从"休闲收集玩家"变为"系统思考型 / 增量游戏玩家" | **接受这个取舍并据此外宣**；用教学曲线（§9）尽量扩大入口 |
| **R7** | 单次开盒失去意义 | 玩家只想批量兑现，跳过所有演出 | 保留"兑现时机"决策（§4.3）；稀有结果仍需完整演出并强制不跳过 |

**R6 必须说清楚：这个转向把目标用户换了一批人。** 这是一个真实的产品取舍，不是可以两头讨好的事。喜不喜欢这个取舍，是继续做下去前要先回答的问题。

## 11. 垂直切片范围

**切片目标：验证"做大期望"这件事本身好不好玩。**

要回答的问题：
1. 玩家看到 RTP 从 0.8 涨到 3.2 时，**有没有爽感**？（§1.4 验证拍）
2. 玩家会不会主动去调整算子、反复试算？（§5.2 施工行为是否自发发生）
3. 装了算子之后，兑现时的产出是否**可感知地变好**？（R2）
4. 玩家能否说出"我为什么涨了"？（P2 归因是否被理解）
5. 第一小时有没有被六个算子类别淹没？（§9）

### 11.1 做

- [ ] **`EvalService`：纯函数计算 EV / RTP / σ / 逐项归因**（一切的地基）
- [ ] **期望面板 + 归因面板 + 结构面板**（三个面板就是玩法本体）
- [ ] 1 个套系：8 常规 + 1 隐藏，覆盖**至少 3 个算子类别**（权重 / 保底 / 阈值）
- [ ] 算子装配：4 个槽位，含 1 组跨类非线性组合（§5.2 的两个例子）
- [ ] 试算 / 沙盒：装配前预览 RTP 变化
- [ ] 分布直方图，随装配实时变形
- [ ] 兑现链条：币/券 → 开盒 → 四段式演出 → **预期 vs 实际对照**
- [ ] 奖励以未开封盒子交付 + 囤积 + 兑现时机选择
- [ ] 重复款 → 算子升阶 + 碎片
- [ ] 概率与保底公示界面
- [ ] **手动设定 RTP 曲线做手感测试**（不接真实经济，先验证爽感）
- [ ] 存档 + 全数据驱动配置
- [ ] 开箱日志（seed + 结果，可复现）

### 11.2 不做

- 成品美术与音效（占位资源）
- 社交、排行榜、交换（仅预留接口）
- 第 2 个及以后的套系
- 池 / 估值 / 规则算子（留到第二切片）
- 剧情、角色养成、关卡玩法外壳
- 本地化、设置菜单、手柄适配
- 付费、广告、任何变现

### 11.3 切片成功判据

任一成立即继续：
- 测试者**主动**尝试"如果我换掉这条规则会怎样"，且不需要引导；
- 测试者能在 2 分钟内说出自己 RTP 的主要贡献来源；
- 测试者在装完结构后表现出"现在开给你看"的兑现冲动。

## 12. 技术骨架（Godot 4.5）

### 12.1 目录结构

```
res://
  autoload/
    game_state.gd         # 运行时状态（算子、资源、保底计数、结构配置）
    eval_service.gd       # ★ 纯函数：structure -> {ev, rtp, sigma, attribution}
    gacha_service.gd      # ★ 纯函数：roll(series_id, structure, seed) -> Result
    save_service.gd       # user:// 存档（JSON）
  data/
    defs/
      operator_def.gd     # extends Resource：算子类别、参数、适用位置
      item_def.gd         # extends Resource：藏品（= 算子载体）
      series_def.gd       # extends Resource：权重表、保底参数、池构成
    series/
      series_01.tres
  scenes/
    panels/               # 期望 / 归因 / 结构 三个面板
    loadout/              # 算子装配工作台 + 试算
    simulate/             # 沙盒
    gacha/                # 兑现演出（四段式，独立可测）
    collection/           # 图鉴 / 套系进度
  ui/
  tests/
```

### 12.2 工程铁律

1. **`EvalService` 与 `GachaService` 都是纯函数、不依赖节点**，可在无头模式跑单测。
   给定 `(structure, series, seed)`，输出必须完全确定。
2. **归因面板、试算、兑现对照三处必须共用 `EvalService`**，绝不允许三份实现。
3. `EvalService` 与 `GachaService` **必须共享同一套权重计算路径**——即"显示的期望"和"实际抽取"用的是同一份代码。这是 P1（一切可见可算）的工程保证，也是最容易出 bug 的地方。
4. 存档记录每次兑现的 `{ seed, series_id, structure_snapshot, item_id, star }`，
   同时具备四个用途：开箱日志、可复现凭据、玩家信任基础（P1）、**归因回归测试的数据源**。

### 12.3 数据驱动

- 内容用自定义 `Resource`（`.tres`）：`OperatorDef` / `ItemDef` / `SeriesDef`，可在编辑器内检视与引用。
- **算子参数必须数据化**（作用目标、系数、条件、互斥标记），新算子应可纯配置产出，不改代码。
- 这是内容产能的生命线：本作的长期内容量 = 算子数量 × 组合空间，如果每个算子都要写代码，内容永远做不够。

## 13. 待定决策

| # | 决策 | 推荐 | 备选 | 影响 |
|---|---|---|---|---|
| **D1** | RTP 成长形态 | **无上限指数增长（增量式）** | 有限目标分阶段（关卡式） | 决定数值架构与存档结构；阻塞切片开工 |
| **D2** | 算子槽位与解锁曲线 | 4 → 10 槽，按套系解锁 | 固定 4 / 固定 6 | 决定组合爆炸度与平衡难度 |
| **D3** | 是否允许一键最优装配 | **不提供**（可选提供"仅做最优化"作为后期便利） | 提供自动最优化 | 直接关系 R1；提供则有最优解收敛风险 |
| **D4** | 场景约束随机化的形式 | 每次兑现附带 1 条环境约束（禁用某类算子 / 加成某类） | 无约束 | 是抑制 R1 的主要手段 |
| **D5** | 兑现演出的强制程度 | 常规结果可跳过，稀有结果强制完整播放 | 全部可跳过 | 关系 R7 与盲盒仪式感 |
| **D6** | 是否引入"变现"出口 | 碎片转化率 ≈ 估值 15% | 更低的 5% | 决定经济缓冲垫厚度（§2.3） |
| **D7** | 承载玩法外壳 | **无外壳，纯做期望工程** | 加一层关卡/放置/Roguelite | 决定工作量规模；纯做期望工程最聚焦 |

**D1 与 D7 是阻塞项**，定了才能开工。

## 15. 一句话总结

**把盲盒的悬念留在单次抽取里，把盲盒的数学摊开成玩家的工作台。**
玩家不再问"这次我抽到什么"，而是问"我的池子值多少，怎么让它更值"——
而每一次兑现，都是对自己工程的一次验收。
