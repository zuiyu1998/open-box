# UI / UX 设计稿

本目录存放**游戏的 UI / UX 设计稿**——尤其是 **AI 生成的设计稿**（线框图、高保真稿、配色与排版尝试、
HTML 原型、界面截图等）。**所有 AI 产出的设计稿一律放这里**，不要散落到 `docs/` 其它目录或仓库根。

## 1. 这个目录是什么、不是什么

| 是 | 不是 |
|---|---|
| **参考稿 / 讨论稿**：长什么样、怎么排版、信息密度、交互顺序 | **行为契约**：按钮点了会扣什么钱、失败码是什么——那在 `docs/systems/*.md` |
| AI 的探索与备选方案（**保留被否掉的方案**，便于回看为什么否） | **唯一权威的视觉规格**：`docs/systems/08-ui-panels.md` 仍是视觉规格的**权威**；设计稿与它冲突时**以 08 为准**，或先改 08 再改稿 |
| 截图 / 导出图 / 可点击原型 | 游戏运行代码（`src/**`）——设计稿**不得**成为第二份实现 |

> **铁律：设计稿可以"提议"，但不能"生效"。** 任何"改了稿就等于改了规则"的路径都不存在；
> 稿子若要落地，落点是：**行为改动 → 改对应系统文档**，**视觉改动 → 改 `08-ui-panels.md`**，
> 然后才是代码。这条与 `docs/systems/README.md` §2 的引用纪律（权威方给数值、引用方只给指针）一致。

## 2. 目录组织

按**系统编号**分子目录，与 `docs/systems/NN-*.md` 的编号对齐（这样"这稿属于哪个系统"一眼可见）：

```
docs/ui-ux/
├─ README.md                 # 本文件（约定与索引）
├─ 08-ui-panels/             # 跨面板的通用视觉规格尝试（配色 / 排版 / 信息层级）
├─ 11-flow/                  # 菜单 / 游戏场景 tab 骨架 / 设置
├─ 12-warehouse/             # 仓库页（网格视图等）
├─ 13-market/                # 市场页
├─ 14-company/               # 公司页
└─ 15-operator/              # 干员页
```

> **许愿机页（设备面板）的稿放 `11-flow/`**——它是 `wish_machine.tscn` 这个页场景，
> 页面接入归 `11-flow.md`；设备本身的行为归 `04-device.md`，不要为此新开 `04-device/`。

## 3. 文件命名约定

`<系统编号或主题>-<主题>-v<序号>.<扩展名>`，全小写、连字符分词、**带版本序号**：

```
12-warehouse/warehouse-grid-cells-v1.png
12-warehouse/warehouse-grid-cells-v2.png      # 改版就升 v，不要覆盖旧稿
11-flow/wish-machine-three-column-v1.png
11-flow/wish-machine-three-column-v1.html     # 可点击原型
08-ui-panels/palette-six-quality-v1.png
```

- **不覆盖旧稿**：改动 = 新序号（`v2`、`v3`），这样"当初为什么否掉 v1"永远可查。
- 一张稿一个文件；**不要把多张图拼进一张**（切图便于单独引用）。
- 需要文字说明时，与图**同名**加 `.md`：`wish-machine-three-column-v1.md`（写意图 / 被否原因 / 待定项）。
- 图片格式：`png`（截图 / 线框）、`jpg`（体积大的渲染图）、`svg`（矢量图标）。**不要存 `.psd` / `.ai`** 等私有格式。

## 5. 与门禁的关系

`tools/check_docs.ps1` 会扫描 `docs/` 下**所有 `.md`**（`archive/` 除外），因此本目录里的 `.md`：

- 必须是 **UTF-8 无 BOM、纯 LF**；
- 不得引用**不存在的** P/R/D 决策号或核心章节号（门禁会报 FAIL）；
- 引用的 `NN-xxx.md` 必须真实存在于 `docs/systems/`。

**`.png` / `.jpg` / `.svg` / `.html` 不在门禁范围内**（门禁只看 `.md`），可以自由存放。
