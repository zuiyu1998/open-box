## 2. 排期原则（三条，都来自文档里的判断）

### 原则一：纯逻辑先做，UI 后做
`EvalService` / `PoolService` / `GachaService` 是**全部玩法的地基**，且**不依赖任何界面**。
它们可以完全在无头模式下测完。把 UI 提前插入只会让地基的 bug 更难定位。

### 原则二：R1 的验证尽可能早
**R1（"使用物资"退化为唯一解）是本作最大风险**，也是唯一能一票否决整个设计的风险。
它不需要完整切片就能验证——**用文本界面 + 两个模块 + 一个假任务按钮，30 分钟就能看出玩家会不会犹豫**。

### 原则三：地基不可并行
`EvalService` 与 `GachaService` **必须共享同一套池子求值路径**（核心 §5.6 工程约束）。
把这段拆给两个人写，是**破坏 P1 最可靠的方式**——它会直接产出"显示的分布 ≠ 抽取用的分布"，而这是本作头号 bug 源、且症状是"玩家所有施工失去可信度"。

**P0 必须由一个人串行完成。** P2 之后才可以铺开并行。

## 4. P1 · Slice-0 冒烟验证（6.5 人日）

**目标：用最低成本回答 R1 —— 玩家拿到物资时会不会犹豫"用掉还是留着"。**

**这不是一个游戏，是一个实验装置。** 界面可以是纯文本/调试面板，不需要任何美术。

| # | 任务 | 人日 | 依赖 |
|---|---|---|---|
| 1.1 | 极简调试界面：显示 ρ / M̄ / D̄ / B、池子分布、镶嵌位占用 | 2 | P0 |
| 1.2 | 2 个模块（1 排除 + 1 提升）+ 镶嵌/替换交互 | 1.5 | 1.1 |
| 1.3 | 假任务循环：物资 → 消耗 → 换回盲盒（只要能闭合即可） | 1 | P0 |
| 1.4 | 手动 ρ 曲线开关 + 观测埋点（关键行为计时） | 1 | 1.1 |
| 1.5 | 测试脚本、访谈提纲、记录表 | 1 | — |

### 4.1 必须埋点的四个行为
1. 首次镶嵌前的**犹豫时长**（从拿到物资到做出选择）
2. **装配次数**（连续调整 ≥3 次 = 施工行为自发发生）
3. 是否出现**囤积行为**（"等我把池子编好再开"）
4. 测试者**能否说出**自己 ρ 的主要来源（P2 可归因）

### 4.2 明确的失败信号（任一出现即**停止并重设计**，不要继续投 P2）
- ❌ 物资**全部**用掉，从不考虑装配 → **燃料/引擎取舍不成立**，中心机制死了
- ❌ 物资**全部**留下，从不完成任务 → 循环张力不成立
- ❌ 测试者问"这些数字是干嘛的" → 默认层信息设计失败
- ❌ 测试者 10 分钟内就把池子编到接近必出 → C6 或 C2 未生效

### 4.3 P1 门禁
**至少满足 2 条**才进入 P2：
- [ ] 测试者在无人引导下主动讨论"这个要不要留"
- [ ] 测试者能在 2 分钟内说出 ρ 的主要贡献来源
- [ ] 出现囤积行为
- [ ] 连续调整装配 ≥3 次而不觉得烦

> **P1 是整个排期里性价比最高的一段。** 6.5 人日，可能省下 40 人日。

### 5.1 并行化建议（P2 是三段里唯一能铺开的）
```
轨道 A（逻辑）：2.1 → 2.2 → 2.3       （物资 / 任务 / 转化）
轨道 B（交互）：2.5 → 2.9 → 2.11      （模块 / 池子面板 / 沙盒）
```

### 5.2 切片的硬要求（不可省略，省了等于没验证）

- **默认层两数字实时联动**（2.7）：编辑不反映在默认层，玩家会怀疑系统动手脚（P1）

## 9. 关键路径

```
数据层(0.2) → evaluate_pool(0.3) → PoolService(0.4) → EvalService(0.6)
                                        │
                                        ├→ 红线回归(0.7) → P1 门禁
                                        │
                                        └→ 模块与池子(2.5) → 池子面板(2.9) → 沙盒(2.11)
                                                                              │
                                              任务系统(2.2) ─ 循环闭合 ────────┤
                                                                              ▼
                                                                    P3 手感调参 → D3/D4/D6/D9
```

**关键路径上的单点是 `evaluate_pool()`。** 它串起 `PoolService`、`GachaService`、`EvalService` 三处，且不可并行（§2 原则三）。

**唯一的解耦机会**：`09 演出系统`（2.12，4 人日）与关键路径**完全无关**，可以立刻交给第二个人——它只需要消费一个已结算的 `Result`。

## 12. 排期的已知不确定性
